# PLAYBOOK —— 人的組塊庫

> 記「這個人手上該長出來的判斷」：下次什麼訊號出現、那一刻要做什麼。
> 與 [LESSONS.md](LESSONS.md) 的分工：那本記 **AI 漏接了什麼**（失敗紀錄），這本記 **人該調用什麼**（提取卡）。
> 兩本共用同一套三態與同一種檢索方式，但記的方向相反——一本記失敗，一本記判斷。
>
> **範本附帶的 P-001～P-010 來自前一個專案**，例子換成了泛稱。「叫出來」的次數是那個人的，新專案的使用者從 0 開始數也可以，照實記就好。

## 這本為什麼存在

`LESSONS.md` 已經在收 AI 的坑，而每一個坑的背面都有一個人本來該有的判斷：
AI 說「檢查都過了」，人本來該問「漏的是哪一半」。那個問句沒有被記在任何地方，
於是同一個坑第五次出現的時候，擋住它的還是帳本，不是人。

這本收的就是那些問句。

**為什麼是卡不是文章。** 認知科學裡最硬的一條是「回想勝過重讀」：
讀四遍的人自認為記得更牢，一週後的留存率卻只有讀一遍再回想三次那組的一半
（Karpicke & Roediger 2008，*Science* 319:966–968）。
所以這本的價值不在寫得多好，在**下次撞到訊號的時候，是你先講還是 AI 先講**。
寫成文章就會被讀，被讀就會產生「我懂了」的錯覺，然後什麼都不會留下。

## 怎麼用這本

**不要整本讀。** 跟 `LESSONS.md` 同一個道理：卡是被**訊號**叫出來的，不是被主題叫出來的。
你 debug 的時候不會想「我來翻一下架構那一欄」——你會撞到一句「測試都綠的」。

### 卡的三欄

| 欄位 | 是什麼 |
| --- | --- |
| **名字** | 可以整個叫出來的把手。你的「口訣」就是這一欄 |
| **訊號** | 下次**什麼情況**會遇到它。這欄比其他兩欄加起來重要 |
| **動作** | 遇到了要做什麼，一句話 |

再加兩個記帳欄：**出處**（對應 `LESSONS.md` 哪一條）、**狀態**。

### 回想規則（這本能不能生效，全看這一條）

AI 偵測到手上這件事命中某張卡的訊號時，**先問，不要先給答案**：

```
🎴 回想：「綠燈不等於驗過」——動作是什麼？
```

- 你答得出來 → 那張卡「叫出來 +1」，**連三次答對就降頻**，以後少問
- 你答不出來，或說「忘了」 → AI 直接給，不追問，那張卡升頻
- **一次對話最多問一次**
- **問在做完之後，不是動手之前**——回想不能擋住手上的工作

### 三態（跟 `LESSONS.md` 同一套）

- `現役`——還要靠你自己記住，AI 會問。
- `降頻`——連三次答對，或已經變成你的反射動作；AI 只在高風險場合問。
- `退役`——已經有 hook、測試或流程接管，人不必再記。**退役要寫出是誰接管的**，
  沒有出處的退役是把判斷忘掉，不是把它自動化。

### 不准做的兩件事

1. **不准憑空造卡。** 卡只能從真的發生過的事來，出處要指得到 `LESSONS.md` 的條目或一顆 PR。
   憑「這個聽起來很重要」寫出來的卡，就是 `L-003`（捏造 Why）的形狀——讀起來毫無破綻，而且沒有人能驗。
2. **不准把卡寫成段落。** 聊天裡三行是上限。檔案裡可以長（有出處、有累計），
   但**名字＋訊號＋動作**永遠要在前三行講完。

## 卡

### P-001 綠燈不等於驗過

- **訊號**：有人（包含 AI）跟你說「檢查都過了」「hook 擋住了」「測試是綠的」「零命中所以沒問題」。
- **動作**：問一句「**它擋的是哪一半，漏的是哪一半**」。講不出漏的那一半，就是沒驗過。
- **狀態**：現役｜叫出來 0 次
- **出處**：`L-007`（守衛只擋一半，累犯 6）、`L-008`（測試釘在自己身上，累犯 4）、`L-010`（測試把守衛的執行環境換掉了）

為什麼這張排第一：帳本裡這一型加起來十一次，是最貴的一型。
它的症狀是**看起來一切正常**——前一個專案有一次，20 條需求標著未達成、票全關了，五百多條測試全綠。

追問的兩個方向，挑一個問就好：

- 擋了「不存在」，有沒有擋「存在但形狀不對」？（`"/"` 有斜線，過關，之後每一筆比對都落空）
- 測試驗的是程式裡那個值，還是測試自己重打的一份副本？（重打的那份**永遠會過**）

### P-002 「查不到」不是答案，是一句待證的話

- **訊號**：出現「沒有這個東西」「零命中」「不存在」「應該沒有」，而**沒有講查了哪裡**。
- **動作**：問「**如果它存在，會被記在哪裡？那幾個地方都翻過了嗎**」。查過的位置清單本身就是證據。
- **狀態**：現役｜叫出來 0 次
- **出處**：`L-009`（沒查證的否定判斷）、`L-003`（捏造 Why，累犯 9）

為什麼這張難防：**肯定句會被要求出處，否定句不會。**
「我找不到」聽起來像是已經找過了，而「謹慎」這個外觀讓它免於被追問。
代價比編一個理由更高——編造是加了不存在的東西，錯誤的否定會**刪掉真的東西**（退票、撤標籤、關票）。

機制上有一個具體的坑：`grep` 是三態，`0` 找到、`1` 沒找到、**`2` 出錯**（路徑不存在、權限不足）。
大多數人只記得前兩個，於是 `grep || true` 把「路徑打錯」靜靜吞成「沒找到」。

### P-003 沒有回頭量的數字，錯的方向是隨機的

- **訊號**：一個好記的整數（`5 hits`、`651 pass`）；或數字跟貼在同一段的指令輸出**不是同一次**跑出來的。
- **動作**：叫他**重跑**那個指令，從輸出複製。不是「檢查一遍」——記憶檢查記憶抓不出東西。
- **狀態**：現役｜叫出來 0 次
- **出處**：`L-012`（累犯 3）

**不要拿「講大了」當訊號。** 帳本裡第一次是講大（`15` 對真值 `11`），第二次是講小（`651` 對真值 `653`）。
曾經歸納成「讀錯的方向永遠是把數字講大」，那條是錯的而且危險——它會讓你只在數字漂亮的時候起疑。
唯一的規律是：**沒有回頭量**。

順帶一個會重複咬人的細節：報行數用 `git diff --numstat`（兩欄分明），
不要用 `--stat`——`--stat` 前面那個數字是**變更總行數**，不是插入數。

### P-004 剛寫下的規則，最不會被套用在手上這一句

- **訊號**：同一顆 commit 既新增一條紀律、又新增受那條紀律管的內容；或聽到「下次會注意」「下一張票會做」。
- **動作**：規則寫完，**下一個動作是拿它掃這次的 diff，不是提交**。成本是一次掃讀。
- **狀態**：現役｜叫出來 0 次
- **出處**：`L-011`（累犯 2）

為什麼這比「不知道規則」更難防：**寫下來這個動作本身給了完成感**，
於是那條規則被歸檔，而不是被拿起來用——而當事人這一刻正是最清楚它的人。

帳本裡最乾淨的一次：同一顆 commit 的第 39 行掛了一個撐不住的出處，
第 57 行寫著「這種一致性斷言也是主張，要真的去比對」。**相隔 18 行。**

### P-005 同一型錯到第三次，就不要再加句子

- **訊號**：同一個形狀的錯又出現了，而你正想在文件或模板裡**再補一句話**防它。
- **動作**：改成一個**刪除動作**或一個**閘門**（hook、測試、CI）。文字防不了文字型的錯。
- **狀態**：現役｜叫出來 0 次
- **出處**：`L-002`（人語層漏接，累犯 13；其中「先講機制才講結論」這一型 9 次）、`L-007`

證據在 `L-002` 自己身上：前六次漏接的對策都是「模板加一句」，
第六次的時候規則已經寫下、進了版控、當天早上還被引用過——然後照樣沒套用。
第七次改成一個**刪除動作**（交出去前逐段問「這段在講機制還是講結果」，講機制的預設刪掉），
第八次證明刪除動作也會被跳過，第九次才收斂成「寫的時候就不要寫」。

**規則的數量跟它被遵守的機率是反比。** 加句子的成本感覺很低，那正是它一直被選中的原因。

### P-006 紅燈也不等於驗過

- **訊號**：CI 紅了，而且**不只你這條分支紅**——`main` 也紅、別人的 PR 也紅；或它紅得太快（個位數秒）。
- **動作**：問「**跑了幾步**」。`gh api repos/<owner>/<repo>/actions/jobs/<job_id> --jq '.steps|length'`，零步驟＝沒驗過，不是驗失敗。
- **狀態**：現役｜叫出來 1 次（2026-09-09，本卡的首次觸發就是它自己的來源事件）
- **出處**：`L-015`

**這張是 `P-001` 的鏡像，不是新的一型。** 兩張講的是同一件事：**燈號不是證據**。
綠燈可能是「沒驗到」，紅燈可能是「沒驗」——差別只在你會不會因為它是紅的就相信它。
人對紅燈的防備天生比綠燈高，所以這一型更貴：紅燈會讓你去改一份根本沒壞的程式。

實例：Actions 帳沒付，三顆寫完的 PR 停了兩天，而畫面上的訊息是「checks failed」。

### P-007 二手摘要不是出處

- **訊號**：你要引用的說法來自搜尋結果的摘要、別人的轉述、或 AI 的整理，而不是那一頁原文。**摘要講得越具體越要警覺**——變數名、版本號、「這是某某專屬的」。
- **動作**：點進去讀原文再引用。讀不到就標「未證實」，不要讓它以事實的樣子落地。
- **狀態**：現役｜叫出來 1 次（2026-09-09，追一個上游框架的 issue 時）
- **出處**：`L-003`（捏造 Why，累犯 9——其中兩筆正是拿二手摘要當論文的主張講）

為什麼摘要比「查不到」更危險：**它已經幫你做完「這在講什麼」那一步**，所以讀起來像結論而不像素材。
而它最會自己補上的，剛好是原文最常沒有的那三樣——**根因、適用範圍、workaround**。
那三樣也剛好是你最想要、最少人回頭驗的東西。

實例：追那個上游 issue 那次，摘要斷言「根因是 `childrenEndTime` 初始化成 `-Infinity`」「Turbopack 專屬」
「改用 `--webpack` 可以避開」。點進 issue 原文——根因欄是空的、全文沒提 Turbopack、沒有任何 workaround。
**三條都是摘要自己長出來的**，而三條都合理到可以直接貼進 PR 描述。

### P-008 閘門沒擋，不等於可以做

- **訊號**：AI 的理由是「閘門放行了」「hook 沒擋」；或你正要做一件你其實知道規則不允許的事，而沒有任何東西出聲。
- **動作**：**規則優先於閘門的沉默。** 按之前自己念一次那份清單，對照這次要動的東西——閘門是最後一道，不是唯一一道。
- **狀態**：現役｜叫出來 1 次（2026-09-09）
- **出處**：`L-007` 的連帶（第 6 次）

**半開的守衛比沒有守衛更危險，因為每一次成功的攔截都在替它背書。**
一顆 PR 早上被正確擋下來，幾小時後另一顆從同一道門溜過去——而按下去的那個人（我）
幾小時前才自己說過那個檔案是 T3、是你的按鈕。規則沒有變，變的是我不再自己執行它。

這張跟 `P-001`／`P-006` 是同一族：那兩張講「燈號不是證據」，這張講**沉默也不是證據**。

### P-009 兩份文件打架，先量高度再判對錯

- **訊號**：兩份文件講同一個系統而結論不同，而你正要判「哪一份對」，或正要用新的那份換掉舊的。
- **動作**：先問「**它們在回答同一個高度的問題嗎**」。把兩邊的條目對成一張表——對得上的是同一件事換了名字，對不上的才值得當衝突處理。
- **狀態**：現役｜叫出來 0 次
- **出處**：2026-09-28，新舊兩份產品文件——新的那份通用、講「這是什麼生意」；舊的那份具體、講「什麼必須成立」。
  **沒有對應的 `LESSONS.md` 條目**——這是產品取捨那一格的第一張卡，材料來自一次規劃對話，不是一次失敗。

第一輪我列了一整頁衝突：產品形態、賣不賣、AI 的權限上限、流程併不併、六個名詞撞車、文件分層。
把新文件的九個模組逐一對回舊文件的流程之後，**只有三個留下來**，其餘是同一件事在兩個高度上各有一個名字。

兩個方向的代價不對稱：

- 把「同一件事換名字」判成真衝突 → 你會砍掉一份還活著的文件，或為了不砍它而維護兩套詞。
- 把真衝突判成層級問題 → 它會以「兩邊都留著」的形式活下來，然後在寫程式的那天才炸。

**「新的那份比較對」是這一型裡最貴的直覺。** 新文件通常更抽象——抽象的代價是它會把
舊文件裡「只在某一步成立」的判準磨成模組名稱。那次被磨掉的是橫跨四個步驟的一條規則鏈，
而那條鏈恰好是整個產品最不像通用工具的地方。

### P-010 派人之前先數椅子

- **訊號**：正要再開一個子代理、worktree 或 session；或有人說「再加兩個，快一點」。
- **動作**：先量這台機器**現在**剩多少（核心、可用記憶體、硬碟、壓力指標 PSI、卡在磁碟的程序數、已經在跑的代理與測試），算一個子代理連它會跑的測試要吃多少，留四分之一餘裕，得出「還能開幾個」；然後問第二句——**瓶頸真的是算力嗎**。多數時候卡的是檔案重疊、審查頻寬、API 配額，加人只會讓合併更慢。
- **狀態**：現役｜叫出來 0 次
- **出處**：2026-10-03，使用者在一次設計站提出：「每台電腦的硬體資源都不一樣，派發之前先預估現在有多少資源可以用」。跟 `P-009` 一樣，材料來自一次規劃對話，不是一次失敗。量法與門檻寫在 `.claude/skills/PIPELINE.md`〈派工前的資源盤點〉與〈慢檔案系統的 I/O 上限〉；後者的材料是 `L-019`（同一個掛載上跑太多線，整個卡死三次）。這裡不留數字。

為什麼是「數椅子」不是「看 CPU」：一個子代理本身很便宜（一個 claude 程序幾百 MB、幾乎不吃 CPU，它在等模型回話），
貴的是它接下來會跑的東西——`pnpm test` 會把每個核心都用上，e2e 要開瀏覽器。
所以要算的不是「有幾個子代理」，是「同一時刻會有幾套測試在跑」。

兩個方向的代價不對稱：

- 開太多 → 測試互搶核心，每套都慢，不穩測試開始出現，而且你會把它當成程式的問題去追（`L-003` 第 8 次：負載夠高時，回歸也長得像隨機紅）；repo 在慢的掛載上時，整個掛載還可能卡死（`L-019`）。
- 開太少 → 只是慢一點，而且慢得看得見。

## 現在的覆蓋缺口（誠實記著）

`P-001` 到 `P-008` 全部落在同一格：**怎麼審 AI 給你的東西**（`P-006` 審的是閘門送回來的燈號，`P-007` 審的是 AI 轉述給你的來源，`P-008` 審的是閘門什麼都沒說的時候）。

`P-009` 是第一張不在那一格的卡，它落在**產品取捨**；`P-010` 落在**派工與資源**，出處同樣是一次規劃對話。它也是第一張出處不指向 `LESSONS.md` 的卡——
