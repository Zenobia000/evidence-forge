# ADR-0008：外觀三選一，預設跟隨系統

> **狀態：** 已接受 | **日期：** 2026-10-10 | **決策者：** 專案擁有者（直接向視覺 session 提出，產品流程 session 轉達，架構 session 撰寫）
> 依 `docs/templates/vibecoding/04_architecture_decision_record_template.md` 撰寫。
> **修正 ADR-0007 §3.4 最後一段**（「執行紀錄頁固定深色，其他頁固定淺色」，以及「不跟系統自動切深色不算偏離」）。ADR-0007 其餘內容不變。

## 1. 背景與問題

- **上下文：** ADR-0007 定的是「每頁寫死深淺色」：執行紀錄頁固定深色，其他頁固定淺色。創作者之後提出：外觀要讓人自己選，所有頁面一起切，預設跟著作業系統。
- **問題：** 這跟 Loomy 的規則不一致。Loomy（Artifact 版）規定最外層一定要寫 `data-theme="light"` 或 `"dark"`，並明說「不會自動跟著系統的深淺設定」。所以 ADR-0007 當時判斷「不跟系統」不算偏離；現在要跟系統，就變成偏離，必須記下來。
- **為什麼要寫成 ADR：** 這推翻了一份已接受的 ADR；而且「預設跟系統」會影響 token 檔怎麼產生、偏好存在哪，之後改回來要動到每一頁。

## 2. 考量的選項

| 選項 | 做法 | 結果 |
| :--- | :--- | :--- |
| 維持 ADR-0007：每頁寫死 | 執行紀錄深色、其他淺色 | 不符合創作者的新要求 |
| 只給淺／深兩個選項 | 創作者手動切 | 不符合「預設跟隨系統」 |
| **三選一：跟隨系統／淺色／深色，預設跟隨系統** | 最外層一律明確寫 `data-theme`，值為 `system`、`light`、`dark` 其中之一 | **採用** |

## 3. 決策

1. **外觀有三個選項：跟隨系統、淺色、深色。預設是跟隨系統。** 選擇套用到所有頁面，沒有哪一頁固定深淺。
2. **最外層一律明確寫 `data-theme`**（`system`／`light`／`dark`），保留 Loomy「一定要明確指定」的那一半。
3. **`system` 由本專案自己實作**：在作業系統偏好深色時套 Loomy 的深色值，否則套淺色值。兩組值都來自同一份 Loomy token，**不手抄色碼**；跟隨系統的規則必須由產生 token 的程序一起產出。
4. **這是第五條不採用的 Loomy 規則**：Loomy 的「不自動跟著系統」不採用。ADR-0007 列的四條加上這一條，共五條。
5. 設定入口在 IA 文件的〈設定〉→〈外觀偏好〉（`30-snapshot/plans/design/2026-10-10-frontend-ia-draft.md`；這一節在產品流程 session 的 commit `c8f64a3`，**撰寫本 ADR 時還沒合進 `dev`**）。這是介面規則，家在 `10-truth/design/`，不進 PRD。

## 4. 後果

- **正面：** 創作者在什麼環境都看得舒服；所有頁面行為一致，少一條「哪頁例外」的規則。
- **負面：**
  - 每個畫面、每個狀態 token 都要在淺、深兩種主題下驗對比，工作量加倍。ADR-0007 §3.3 的限制（黃與靛藍不當字、淡灰只配文字標籤）在深色主題也要成立。
  - 頁面是伺服器端產生的（架構草案 v0.2 §1.4）。若偏好只存在瀏覽器端腳本，頁面會先用錯的主題畫一下再切換（閃一下）。實作時偏好要讓伺服器在產生頁面時就讀得到，例如存在 cookie。
  - 同步 Loomy 時，跟隨系統的規則要跟著重新產生。
- **影響範圍：** `10-truth/design/`、之後的 `static/css/tokens.css`、AppShell 模板、設定頁。
- **重新評估觸發：** Loomy 自己支援跟隨系統時，改用 Loomy 的做法。
