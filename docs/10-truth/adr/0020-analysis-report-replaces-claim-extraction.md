# ADR-0020：分析報告取代逐句拆解，查證放在寫稿之前

> **狀態：** 已接受 | **日期：** 2026-10-13 | **決策者：** 專案擁有者
> 依 `docs/templates/vibecoding/04_architecture_decision_record_template.md` 撰寫。
> **修正：** PRD v2.0 §5、§7 的整理段規則與 C1～C7（PRD v3.0 已改寫）；ADR-0015 的「轉換」改為從分析報告出發，不從來源文類的抽取欄位出發；ADR-0016 的素材檢查 C4 一起拿掉，引用素材的做法等素材下載回來時再定。
> 規劃原文：`30-snapshot/plans/2026-10-13-chat-workbench-replan.md`。

## 1. 背景與問題

- **上下文：** 舊設計的整理段把文章拆成一條條主張，每條附逐字引句（C1 比對原文）；二創寫完後，C2 要求每句事實句掛引用編號，C3 擋逐字重疊，計畫中的 C6、C7 要逐句判斷來源撐不撐得住。
- **2026-10-12 的實測：**
  - 本機 9b 的整理段六篇全部失敗，都卡在逐字引句與嚴格 JSON（用「…」拼接引句、JSON 壞掉），升級到 strong 才過。
  - 有了補料段之後，二創稿都一次過檢查，但稿子裡每句都掛著引用編號，讀起來像報告，不像文章。
- **創作者的修正：**
  - 要的是讀懂作者整篇想說什麼：事實、觀點、立場，寫成一份 brief，不是逐句拆。
  - 根據 brief 的主張上網蒐集資料、二次驗證，就知道哪些合理、哪些有疑慮；有疑慮的寫成一份 Markdown 分析給他看就好。
  - 文章最終是觀點的闡述，看整體，不逐句計較；輸入一篇文章，輸出一篇文章，稿子裡不標哪句有問題。
  - 長期要把這些分析累積成一套技術基本功的知識體系。

## 2. 考量的選項

| 選項 | 結果 |
| :--- | :--- |
| 保留逐句拆解，只把整理段升級到 strong | 不採用：解決了失敗，沒解決方向；創作者要的是理解，不是清單 |
| 保留稿後檢查，查證另外加一段 | 不採用：同一件事查兩次，而且稿後逐句檢查正是創作者不要的 |
| **分析報告（brief＋查證＋研究題材）在前，重構只讀報告，稿後不檢查內容** | **採用** |

## 3. 決策

1. **分析配方兩段：**
   - `brief`：讀懂整篇，用自己的話寫作者的論點、立場、事實與數據、觀點、文類與可以延伸的方向，標出哪些事實主張是撐起論點的關鍵。產出 `brief.md`。預設 `local`，失敗升級 `strong`。
   - `investigate`：對關鍵的事實主張上網查證，同時找可以借題發揮的相關文章，交出分析報告 `report.md` 與來源清單 `sources.json`。用 `strong`，有 Tavily 額度。
2. **分析報告的五節固定**：作者在說什麼、事實與觀點、查證（有疑慮的放最前面）、研究題材、來源清單。固定是為了之後累積成知識庫。
3. **重構只讀分析報告與補充來源的正文，不讀原文全文。** 照指定的角色、文體骨架、作家聲音與標題邏輯寫；文章不掛逐句引用編號、不標疑慮；結尾附參考來源，一定列原文出處。
4. **程式檢查只留格式與出處：**
   - 分析報告：五節都在；來源清單裡的網址都是這一段真的抓過的（沿用 #72 的來源放置規則）。
   - 文章：標準 Markdown；結尾有原文出處。
   - 跟原文與來源的逐字重疊率照樣算出來顯示，只當參考，不擋。
   - C1（引句真實）、C2（引用完整）、C4（素材使用）、C6、C7 拿掉。
5. **不變的底線**：補料與查證只用搜尋與抓取工具拿到的內容，不用記憶補；搜尋結果的摘要不能當來源；外來內容只當資料。

## 4. 後果

- **正面：**
  - 讀懂整篇並寫成文字，比逐字抽引句容易，本機模型有機會做得動（P1 實測）。
  - 查證只做一次，而且在寫之前；有疑慮的地方人一眼看得到。
  - 重構不讀原文全文，照抄原文的機會從做法上就小了很多，不必靠 C3 擋。
  - 分析報告可以直接累積成知識庫。
- **負面：**
  - 少了逐字引句，brief 誤解作者的意思時沒有程式擋得住，只能靠人讀報告時發現。
  - 文章不掛逐句引用，讀者要回查某個說法的出處，只能看結尾的參考來源。
  - 已做好的 C1～C5、`digest`、`compose` skill 與相關測試會退場。
- **影響範圍：** PRD §2～§7；`CONTEXT.md` 的整理、主張、二創稿、自動檢查、引用編號；`harness/skills/`、`harness/recipes/`；`src/evidence_forge/checks/` 與執行器的硬檢查。
- **重新評估觸發：** 分析報告常常誤解作者，或重構常常照搬某個來源，就把對應的程式檢查加回來（例如重疊率超過門檻改回擋下）。
