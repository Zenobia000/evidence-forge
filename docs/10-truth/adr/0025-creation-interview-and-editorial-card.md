# ADR-0025：寫稿前先訪談，一關一關用問題卡問；決定記成只增不改的事件，編輯卡由事件算出來

> **狀態：** 已接受（創作者 2026-10-15 拍板；PR 合併即生效） | **日期：** 2026-10-15 | **決策者：** 專案擁有者
> 依 `docs/templates/vibecoding/04_architecture_decision_record_template.md` 撰寫。
> **修正：** ADR-0019 §3.2（分析完不是直接重構，而是進訪談；寫稿只讀訪談收斂出來的編輯卡）與 §4（無人看管的自動投入只跑到分析報告）；ADR-0020 §3.3、§3.4（重構的輸入改成編輯卡快照；稿後多幾條機械能查的程式檢查，仍不用模型檢查內容）；ADR-0021 §3.4（對話多幾個有名字的閘道工具，其中幾個會寫這個對話自己的決策紀錄與作者素材）；ADR-0024 §3.2 第 2、4 點（不提原文、參考來源第一條是原文，只在從報告開始時適用；文體是 `essay` 時內文可以引用並回應原文）。
> 規劃原文：`30-snapshot/plans/2026-10-15-content-workflow-integration.md`。票：#105。

## 1. 背景與問題

- **上下文：** 照 ADR-0019，創作者看完分析報告說「寫第 N 個」，系統就用指定的角色與文體一次寫完一篇。觀點、例子、主幹、標題全由模型挑，創作者只能事後帶一句意見再改。
- **創作者自己的寫作流程**（Sunny 內容流程，32 篇實戰）走的是另一種分工：作者在每一站拍板，順序是文體 → 核心觀點 → 只有作者能給的例子 → 邊界 → 工作標題 → 主幹 → 第一人稱與配圖；AI 負責列候選、整理、寫初稿與產圖。整篇的狀態寫在一份一直改的編輯卡（`brief.md`）。它自己的交接文件寫明缺一個「有狀態的工作流程引擎」：關卡現在全靠對話維持，選過什麼沒有紀錄，「作者沒給實測資料就不動筆」這類規則也沒有程式擋。
- **創作者要的體驗（2026-10-15）：** AI 有條理地訪談，每一步給選項讓他挑或補充；問法像 Claude Code、Codex CLI 在規劃模式裡問釐清問題那樣，一次一張問題卡；看得到自己選了什麼、沒選什麼、最後的結構與選題；每篇的素材與圖片都留著可以再調。
- **為什麼要寫成 ADR：** 這改了人在流程裡的位置（從「看完報告就交給模型寫」變成「每一關拍板」）、多了一種狀態（編輯卡、決策紀錄與作者素材），也改了重構的輸入與稿後檢查的範圍；後面八張票都照這份做。

## 2. 考量的選項

| 選項 | 結果 |
| :--- | :--- |
| 維持一次寫完，只把目標（`goal`）寫得更細 | 不採用：創作者的選擇沒有留下來，也沒辦法回頭只改一關 |
| 做一張固定欄位的表單（照編輯卡範本填） | 不採用：ADR-0019 否決過固定表單；而且創作者要的是 AI 先給幾個有說明的選項，不是空白欄位 |
| 編輯卡是一個一直覆寫的檔（照搬現在的 `brief.md`） | 不採用：看不到過程；跟 ADR-0010「只增不改」衝突，寫稿工單也說不清楚當時讀的是哪一版 |
| **在聊天室裡一關一關用問題卡訪談；每個決定記成只增不改的事件，編輯卡由事件算出來；寫稿工單帶一份當時的快照** | **採用** |

## 3. 決策

### 3.1 三種起點

訪談可以從三個地方開始，都在同一個對話裡：

1. **報告的第 N 個題材。** 創作者在分析完之後說「寫第 N 個」。那個題材的暫定標題、角度與建議文體帶進第 1 關當預設選項。
2. **創作者自己的一個想法。** 一句話就可以開始，沒有分析報告。
3. **貼素材。** 創作者自己的筆記、數據、草稿或口述的逐字稿，記成這張編輯卡的作者素材（§3.3 的作者素材事件），不當成別人的文章去分析。要拿別人的文章當起點，照舊走分析（ADR-0019），再從報告的題材開始。

### 3.2 六個訪談關卡與問題卡

順序固定，一次只問一關，這一關送出才往下：

| 關 | 問什麼 | 記下來的是 |
| :--- | :--- | :--- |
| 1 文體＋主題 | 這篇的主證據是什麼、讀者讀完要做哪個決定 | 一個文體、一個主題（ADR-0026） |
| 2 核心觀點 | 把感覺命名成一個說得出口的觀點 | 觀點的名字與一句話 |
| 3 只有作者能給的例子 | 作者自己遇過、做過、量過的東西 | 作者給的例子與實測資料，或作者自己回答「沒有例子」 |
| 4 邊界 | 這個觀點在什麼條件下成立、什麼情況下不成立 | 成立條件與失效條件 |
| 5 工作標題 | 幾個候選標題 | 一個當錨的工作標題（正式標題寫完再訂） |
| 6 框架、主幹與圖文分鏡 | 用哪種結構、各節的順序與主張、每節配不配圖、配哪一種 | 框架、大綱、圖文分鏡，以及文章會提出的主張清單 |

- **問題卡：** 每一關用 1～4 張問題卡問，畫面一次只出一張，照順序；答完一張就出下一張。一張卡有：
  - 一個短標籤（標出這張在問什麼，例如「文體」「主題」）；
  - 一個問題；
  - 2～4 個選項，每個有名稱與一句說明；
  - 一定有「其他」，讓創作者自己打字回答；
  - 選了某個選項時，可以附一段補充。
- **一關一次送出。** 這一關的卡都答完之後，創作者可以回頭改任何一張，再按「確認並送出這一關」。送出一次就是這一關的決定；事件仍是一張卡一筆，但在送出時一批寫進去。
- **創作者點的東西由系統記，不由 agent 轉述。** 問題卡送出的回答、「沿用」、「重問這一關」都是畫面 → 閘道，閘道直接寫進決策紀錄，再像 `[ef-job]` 那樣通知對話的 agent 接著往下（例如出下一關的問題卡）。agent 沒有替創作者記點選的工具。
- 創作者口述的長內容，agent 先整理成條列，用一張問題卡請他確認再記。
- **創作者沒點卡、改在主輸入框打字回答時**，agent 自己解讀那段話，可以用 `record_interpreted_answers` 記成這一關的回答；這種回答在事件上標 `source: agent`，畫面上看得出是 agent 解讀的，跟創作者自己點的（`source: ui`）分開。
- **第 3 關不准替作者編經歷。** 這一關的選項只能是提示（「你有沒有遇過……」）或「沒有例子」，「沒有例子」只有作者自己能選；例子的內容一定來自創作者（他的回答或他的作者素材）。這是原本流程裡「第一人稱確認」的那一步。
- **文體與第 3 關要對得上。** `product-case`、`benchmark`、`postmortem` 的主證據是作者自己的使用、測試或專案（ADR-0026 §3.1）：第 3 關沒有作者的實測或經驗，就停在第 3 關，請他補，或回第 1 關換文體。`essay` 的主證據是作者的經驗或觸發它的原文：作者回答「沒有例子」時，只有從報告開始（有原文）才能往下。
- **第 6 關列出文章會提出的主張，每條附「怎麼會被證明是錯的」，給創作者看過。** 原本流程在寫完之後逐句做可否證測試；這裡改成寫之前在主張層級看，因為稿後不用模型檢查內容（ADR-0020，§3.7）。
- **圖文分鏡只排這個里程碑做得出來的種類**：概念圖、數據圖、不配圖（ADR-0027 §3.1）。某一節要用表格，就在分鏡記「表格」，由寫稿工單直接寫成 Markdown 表格，不是圖、不留圖位。截圖之後再加。封面每篇一張，不排在分鏡的節裡。
- **創作者說「你幫我選」：** agent 用 `record_interpreted_answers` 替這一關的每一張問題卡記一筆回答（`source: agent`），選它排第一的選項，補充寫「交給 AI 選」，創作者事後看得到。但有兩條限制：
  - 第 3 關 agent 只能記「尚待作者提供」，不能替作者決定「沒有例子」，也不能記成有內容的決定。「尚待作者提供」不算這一關有決定；agent 接著只問作者這一題，作者回答「沒有例子」才算決定。
  - 所以第 1 關替他選文體時，只能選不需要作者自己經驗的 `research-review`、`explainer`、`trend`；它排第一的是別種文體，就停下來問創作者。
- 原本流程的第 7 站「配圖」併進第 6 關的圖文分鏡；產圖本身是寫稿之後的配圖工單（ADR-0027）。

### 3.3 決策紀錄、作者素材與編輯卡

- **位置：** `$EF_DATA/conversations/<對話 id>/cards/<卡 id>/`。一個對話可以有好幾張卡（同一份報告挑了兩個題材，就是兩張）。
- **決策紀錄 `decisions.jsonl`：** 一行一個事件，只增不改，只有閘道寫。每一筆都記 `source`：`ui`（創作者在畫面上點的，閘道直接記）或 `agent`（對話的 agent 寫的）。事件有五種：
  - **提出問題：** 哪一關、問題卡編號、標籤、問題、選項（每個有名稱與說明）、時間。「其他」一定有，不用記。`source: agent`。
  - **回答：** 哪一張問題卡、選了哪個選項或「其他」的文字、補充、時間。一關送出時一批寫進去，同一批帶同一個送出編號；這一關的問題卡都有回答、而且沒有一張是「尚待作者提供」，才算有決定（編輯卡照這條算）。創作者點卡送出的是 `source: ui`；agent 解讀主輸入框的話、或「交給 AI 選」的是 `source: agent`。
  - **沿用：** 一關被標「要重確認」之後，創作者按「沿用」保留原本的決定：哪一關、保留的是哪一次送出、時間。`source: ui`。
  - **重問：** 創作者按「重問這一關」：哪一關、時間。這一關回到還沒送出的狀態（原本的回答留著當預設），閘道通知 agent 重新提出問題卡。`source: ui`。
  - **作者素材：** 創作者貼的或上傳的自己的東西：編號（`M1`、`M2`…）、種類（文字、檔案）、內容的 sha256、檔名、大小、時間。內容本身存在同一個資料夾的 `materials/<sha256>`，寫一次就不再改；事件只記參照。也經閘道寫，對話的 agent 碰不到檔案本身。叫「作者素材」是為了跟 `CONTEXT.md` 的素材（查證段找到的圖）與素材項目（inbox 裡別人的文章）分開。
- **編輯卡 `card.json`：** 由事件從頭算一次得到的當前狀態：每一關現在的決定、還沒決定的關、要重確認的關、作者素材清單。它只是快取，可以隨時重算；兩邊對不上時以事件為準。壞掉的一行跳過，不拖垮整張卡（跟帳本的讀法一樣）。
- **回頭改一關：** 創作者按「重問這一關」（或在聊天裡要求，由 agent 提出新的問題卡），重新送出那一關。新的送出一寫進去，後面已經決定過的關卡在編輯卡上標「要重確認」，原本的決定留著當預設；創作者按「沿用」、或重新送出之後才取消標記。
- **閘道的入口分兩種**（範圍照 ADR-0021：只碰得到這個對話自己的卡；沒有任何通用的讀寫檔工具）：
  - **對話的 agent 能叫的工具：**
    - `propose_questions(card, station, questions[{header, question, options[{label, description}]}])`：記下提出的問題卡，交給畫面一張一張出。不打模型、不花錢。
    - `record_interpreted_answers(card, station, answers[{question, choice | other_text, note}])`：只用在創作者在主輸入框打字回答、或說「你幫我選」的時候；一批記一關，事件標 `source: agent`。
    - `add_material(card, text | upload)`：記下一份作者素材。
    - `read_card(card)`：讀編輯卡。
  - **只有畫面能叫的入口**（對話主機的 API 轉給閘道，對話的 Pi 看不到也叫不到）：
    - `submit_station(card, station, answers[…])`：「確認並送出這一關」，一批寫回答事件（`source: ui`）。
    - `keep_decision(card, station)`：「沿用」。
    - `reask_station(card, station)`：「重問這一關」。
  - 畫面的入口寫完之後，對話主機像 `/ef-job-done` 那樣對這個對話的 Pi 送一則通知（`[ef-card]`，帶卡與關），agent 讀編輯卡接著往下。
- **寫稿的入口：** 「照這張編輯卡寫稿」的按鈕只在六關都有決定、而且沒有要重確認的關時才出現。寫稿工具自己再查一次，條件不滿足就拒絕，訊息說是哪幾關（按鈕之外的最後一道關）。

### 3.4 寫稿工單帶一份編輯卡快照

- 開寫稿工單時，閘道把當下的 `card.json` 與它列到的作者素材檔一起複製進工單的 `input/card/`（照 sha256 放在 `input/card/materials/`）。工單只讀這份快照，不讀活的編輯卡；之後再改編輯卡不影響已經開出去的單。
- 改稿、或改了編輯卡再寫，都是新工單、新快照（ADR-0019 §3.6 的「每一版都是一張新工單」照舊）。
- 寫稿工單的輸入：編輯卡快照（含作者素材）＋分析報告與來源（從報告的題材開始時才有）＋角色資料（ADR-0026）。從報告開始時，「不讀原文全文」「內文不提原文與原作者」「參考來源第一條是原文」照舊（ADR-0020、ADR-0024），只有一個例外：文體是 `essay`（有感而發）時，內文可以引用並回應觸發它的原文，原文照樣列在參考來源第一條。從自己的想法或素材開始時沒有原文，這幾條不適用。
- 數據圖的證據帳本可以用編號引用快照裡的作者素材當出處（ADR-0027 §3.3）。

### 3.5 對 ADR-0019 的修正

- 分析報告之後，「寫第 N 個」開始的是訪談，不是直接重構；訪談收斂成編輯卡，寫稿才開工。
- 在聊天室裡說「分析完直接寫」，意思變成「每一關你幫我選」，照 §3.2 的兩條限制：第 3 關不替作者填內容，第 1 關只選不需要作者經驗的文體，做不到就停下來問。
- **無人看管的自動投入（訂閱源）只跑到分析報告**，不能設定成直接寫。ADR-0019 §4 的「或在配方裡明寫分析完直接寫」拿掉：沒有人在對話裡，就沒有人回答問題卡。
- 分析與重構仍是兩件照配方跑的工作；訪談在對話裡，不是工單，也不照配方跑。

### 3.6 新的對話工具一覽

ADR-0021 的「對話沒有任何寫檔工具」改成：**對話沒有通用的讀寫檔工具；只有幾個有名字的閘道工具，各自只寫這個對話自己資料夾裡的一種東西。** 這份加的是 §3.3 的工具（agent 能叫的四個，加上只有畫面能叫的三個入口）；配圖與 lessons 的工具見 ADR-0027 §3.5、ADR-0026 §3.3。報告與文章仍只能由工單產生。

### 3.7 對 ADR-0020 的修正：稿後只多查機械能查的

ADR-0020 的「稿後不用模型檢查內容」不變。程式檢查多這幾條，全部只用程式判斷（參考資料、圖文節奏、數據圖證據鏈是 #105 定的；front matter 與句型來自規劃〈要做的〉第 6 項，圖位對得上分鏡來自 #110）：

- 文章的 front matter 齊全（`title`、`description`、`genre`、`theme`）。
- 有參考資料一節，每一筆有網址。
- 圖文分鏡裡的每一張圖在文章裡都留了圖位。
- 圖文節奏（配圖工單，ADR-0027）：第一張圖之前、兩張圖之間的字數照規則。
- 數據圖的證據鏈（配圖工單，ADR-0027）：每個數字對得回證據帳本。
- 句型這類寫作規則屬於角色的聲音（ADR-0026），規則內容不寫進 repo。程式檢查可以照角色資料裡列出的句型去擋，清單在角色資料、檢查的程式在 repo。

## 4. 後果

- **正面：**
  - 創作者在寫之前就拍板觀點、例子與主幹，寫出來的東西是他的，不是模型挑的方向。
  - 每一個選過、沒選的方向都留在決策紀錄裡；回頭只改一關，後面的關卡自動標出要重看，不想改的按「沿用」就好。
  - 寫稿工單只讀一份凍結的快照（連同作者素材），重跑、比對版本都說得清楚當時依據的是什麼。
  - 交接文件說缺的「有狀態的流程引擎」，用現有的對話、閘道、只增不改的檔就做得出來，不另外架資料庫。
- **負面：**
  - 從報告到文章多了六關、每關 1～4 張問題卡，對話的模型呼叫變多（`fast`）。
  - 對話從只讀變成會經閘道寫幾種東西（決策紀錄、作者素材）；每一個工具與畫面入口都要有自己的範圍檢查。
  - 創作者在主輸入框打字回答時，記下來的是 agent 的解讀（`source: agent`），可能跟他的意思有落差；畫面要把這種回答標出來，讓他看得到、可以重問。
  - 「你幫我選」不再是一路到底：第 3 關與第 1 關會停下來問；無人看管的自動投入也不再能直接寫。
  - 第 6 關的主張清單是寫之前的承諾，寫稿時模型仍可能多寫出清單外的說法；稿後不用模型檢查，只能靠創作者讀稿。
- **影響範圍：** `src/evidence_forge/gateway/chat_tools.py`、`conversations.py`、`chat/`（對話主機推問題卡給畫面、送出、沿用、重問與寫稿按鈕的 API，`[ef-card]` 通知）、`harness/pi/extensions/ef-tools/`、`harness/pi/chat-system-prompt.md`（訪談規則）、`harness/recipes/rewrite.md` 與 `harness/skills/rewrite/`、`runner/stage_inputs.py`、`checks/article.py`、`ui/`（問題卡、決策分頁）；PRD §2、§3、§4、§5、§7；`CONTEXT.md`。
- **重新評估觸發：** 創作者常常每關都說「你幫我選」（訪談變成負擔）；或常常寫到一半才發現某一關的決定行不通（關卡的順序或內容要改）。
