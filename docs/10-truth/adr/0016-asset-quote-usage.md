# ADR-0016：素材新增「引用」使用狀態：附出處、只取必要部分、人逐件核准

> **狀態：** 已接受 | **日期：** 2026-10-11 | **決策者：** 專案擁有者
> **後續修正：** 由 ADR-0020 修正——C4 素材檢查拿掉；引用素材的做法等素材下載做進來時再定。
> 依 `docs/templates/vibecoding/04_architecture_decision_record_template.md` 撰寫。
> **修正 ADR-0013 §3.5** 的「授權不明的圖不進成品」：授權不明的素材可以用「引用」的方式進成品，條件見下。其餘底線不變。

## 1. 背景與問題

- **上下文：** 來源文章的作者本身就大量引用別人的 blog、影片與簡報截圖。創作者要把這些上游素材保留下來，並在二創時也能使用。這是非營利用途。
- **原本的規則：** 只有授權狀態是 `ok` 的圖能放進稿子，其他一律只當參考。照這條規則，大部分上游素材都用不了。
- **限制：** 非營利有利於主張合理使用，但不代表一定合法。台灣著作權法的做法是：
  - 第 52 條：為評論、教學、研究等正當目的，在合理範圍內可以引用。
  - 第 64 條：引用要明示出處。
  - 第 65 條：合理使用要綜合判斷目的、著作性質、使用的量、對市場的影響。
  - 這份 ADR 是工程上的防線，不是法律意見。
- **為什麼要寫成 ADR：** 修改了 ADR-0013 的底線，而且牽涉著作權。

## 2. 考量的選項

| 選項 | 結果 |
| :--- | :--- |
| 維持只用授權 `ok` 的素材 | 不採用：上游素材幾乎都用不了 |
| 非營利就全部可用 | 不採用：非營利不等於合法；整張轉貼、取代原作的用法風險高 |
| **新增「引用」狀態，有條件放進成品，人逐件核准** | **採用** |

## 3. 決策

1. **素材有兩個欄位：**
   - `license`：授權狀態，`ok`／`unknown`／`denied`。
   - `use`：使用方式。
     - `embed`（直接使用）：只限 `license: ok`。
     - `quote`（引用）：條件見下。
     - `reference`（只保存，不放進稿子）：預設值。
2. **保存一律可以**：上游素材（blog、影片頁、簡報截圖、圖片）都抓回來，連同出處保存；能不能放進稿子，另由 `use` 決定。
3. **`quote` 的條件：**
   - 圖或截圖旁邊一定要有出處說明：作者或來源名稱、標題、連結。
   - 只取討論需要的部分：截圖要裁到正在討論的那一塊，不整頁轉貼。
   - 稿子的文字要真的在討論它；引用是為了評論或說明，不能拿來當裝飾配圖。
   - 影片只用官方嵌入或「連結＋時間點」，不轉存影片檔。
   - `license: denied`（權利人明確拒絕）一律不能引用。
4. **自動檢查 C4 改為：**
   - `embed` 必須是授權 `ok`。
   - `quote` 必須附出處說明，而且稿子在附近的段落有提到它。
   - 其他狀態不能出現在稿子裡。
5. **人逐件核准：** 稿子裡用到的每一件 `quote` 素材，都會列在待審畫面，由創作者逐件核准或拒絕。被拒絕的那件，退件重跑時要換掉或拿掉。工單要「通過」，前提是稿子裡的每一件 `quote` 都已核准。
6. **前提是非營利。** 一旦有營利（廣告、付費內容、業配），這份決定要重新評估。

## 4. 後果

- **正面：** 上游素材可以保存並在評論、說明時使用；出處一定會出現；每一件都經過人看過。
- **負面：**
  - 審稿多一個逐件核准的步驟。
  - 「只取必要部分」「稿子真的在討論它」這兩條，程式只能部分檢查（有沒有出處、附近段落有沒有提到），剩下的靠人核准。
- **影響範圍：** 素材清單格式（`assets.json`）、C4 檢查、待審畫面與審稿決定的格式、二創 skill、PRD 的素材與審稿需求。
- **重新評估觸發：** 開始營利；或收到權利人的反對。
