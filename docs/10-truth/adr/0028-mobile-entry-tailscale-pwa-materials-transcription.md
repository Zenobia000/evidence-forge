# ADR-0028：隨身入口：Tailscale、PWA、多模態素材、轉文字

> **狀態：** 已接受（創作者 2026-10-16 拍板；PR 合併即生效） | **日期：** 2026-10-16 | **決策者：** 專案擁有者
> 依 `docs/templates/vibecoding/04_architecture_decision_record_template.md` 撰寫。
> **修正：** ADR-0019 §1、§3.2——對話的起點不再只有「丟一篇別人的文章，它就開始分析」：丟進對話的東西先收進素材清單，創作者說要分析才開 `analyze`（§3.5）。ADR-0021 §3.4——對話多兩個只讀的工具 `list_attachments`、`read_attachment`，`analyze` 可以拿素材清單上的一個附件當輸入；畫面多一個對話的 Pi 叫不到的入口 `save_attachment`，由閘道寫（§3.5）；看圖記在對話的帳本（§3.6）。**補充 ADR-0011 §3.4：** 閘道多一個會花錢的供應商（OpenAI 轉文字），跟 ADR-0027 的生圖同一套預估、預留、結算與記帳（§3.7）。
> 規劃原文：`30-snapshot/plans/2026-10-16-voice-first-replan.md`。票：#129。

## 1. 背景與問題

- **上下文：** 創作者最常有想法的時候不在電腦前。現在的 EF 只能在家裡那台電腦的瀏覽器開（`ef serve` 的聊天室 8790 與閘道 8787 都只綁 `127.0.0.1`），也只能從「別人的一篇文章」開始。想法要等回家才丟得進來，多半就忘了。
- **創作者 2026-10-16 拍板：**
  1. 使用者只有創作者自己：單人、純檔案、本機；不做多人，也不做登入系統。
  2. 手機要能直接用，未來看起來像一個 App：截圖、照片、檔案、連結、錄音、打字，在外面就能直接丟進來，不要回家再丟。
  3. 轉文字先用 OpenAI 的 `whisper-1`。
  4. 每種東西的大小上限參考 ChatGPT 與 Claude 的 App（§3.8）。
- **要回答的事：** 手機怎麼安全地連到家裡那台電腦；「像 App」做到什麼程度；丟進來的東西存在哪、誰寫、會不會自動花錢；錄音怎麼變成文字、錢記在哪；家裡電腦連不到時手機上看到什麼。
- **為什麼要寫成 ADR：** 這是 EF 第一次讓 `127.0.0.1` 以外的裝置連進來（T3）；閘道多一個付費供應商；對話多工具、起點也改了。改回來要動網路設定、身分檢查、閘道、帳本與畫面。

## 2. 考量的選項

| 選項 | 結果 |
| :--- | :--- |
| 開一個公開網址（雲端主機或反向代理），自己做帳號登入 | 不採用：一個人用的工具要先扛多人產品的成本（帳號、密碼、被掃描、憑證），而且資料要離開家裡那台電腦 |
| 寫原生 App（Android、iOS 各一支） | 不採用：兩套程式、上架、更新；目前要驗證的是「在外面丟得進來」，不是 App 本身 |
| 本機跑 whisper 轉文字 | 不採用：WSL 的記憶體本來就緊，本機模型會跟 Qwen 搶；雲端一分鐘約 US$0.006，一小時不到半美元 |
| `tailscale serve` 直接轉到聊天室現有的 8790 | 不採用：8790 上分不出「本機桌面直連」與「經 serve 進來但沒有身分標頭」（Tailscale 對帶 tag 的裝置不給身分標頭），身分檢查就只能有條件地做 |
| **Tailscale 私人網路＋`tailscale serve` 轉到另一個只給它用的本機埠；畫面做成 PWA；丟進來的先收進素材清單；轉文字經閘道用 `whisper-1`** | **採用** |

## 3. 決策

### 3.1 只有創作者一人

- EF 是一個人的工具。沒有帳號系統、沒有登入頁、沒有「使用者」這個資料。
- **信任邊界是「家裡那台電腦的 WSL」。** 在 WSL 裡跑的程式本來就讀得到 `EF_DATA` 與金鑰，所以它們一律算創作者本人：本機的程式在 loopback 上偽造身分標頭，不在要防的範圍內。要防的是 WSL 以外的一切：tailnet 裡別的裝置、網際網路、手機瀏覽器裡別的網站。
- 「是不是創作者」從外面進來時只用 Tailscale 帶來的身分判斷（§3.2）。之後要給第二個人用，是另一份 ADR 的事（§4 重新評估觸發）。

### 3.2 手機怎麼連進來：Tailscale，另開一個只給 serve 的埠

- 家裡那台電腦與創作者的手機加進同一個 Tailscale 私人網路（tailnet）。**不開公開網址**，不開 Tailscale Funnel，tailnet 以外的人連不到。
- **tailscaled 裝在 WSL 裡，不裝在 Windows 那一側。** 理由：
  - `tailscale serve` 轉送的目標是 WSL 自己的 `127.0.0.1`，是真的 loopback；裝在 Windows 那一側就要靠 WSL 的 localhost 轉送把 Windows 的 `localhost` 接到 WSL，多一層會變的設定，信任邊界也跨到 Windows。
  - WSL 睡著或被收掉時 EF 本來就不在了；這時 tailnet 上的節點跟著離線，手機看到的就是「連不到」（§3.9 第一列）。裝在 Windows 那一側反而會變成「節點在線、後面沒人回」，更難講清楚。
  - 代價：WSL 要用 systemd 開 tailscaled，WSL 每次起來它才在；這跟 EF 本身要 WSL 醒著是同一件事。
- **`ef serve` 多開一個埠給 serve 用（預設 8791，只綁 `127.0.0.1`）。** 它跟 8790 是同一個聊天室與 API，只差在進門的規則：
  - **8791：每一個請求都要帶 `Tailscale-User-Login`，而且要等於設定的創作者帳號；沒帶或對不上一律 403**，畫面只說「這個帳號不能用」，不說創作者的帳號是誰。這一條一併擋掉帶 tag 的裝置（沒有身分標頭）、Funnel 進來的請求（沒有身分標頭）、以及任何沒帶標頭的請求。外面送來的同名標頭會被 serve 拿掉，所以從 tailnet 偽造不了。
  - **8790：只給這台電腦上的瀏覽器直接用**，進門規則照舊（見下），不看身分標頭。
- `tailscale serve` 只把 8791 用 HTTPS 開給 tailnet；HTTPS 憑證由 Tailscale 發。瀏覽器要在 HTTPS 底下才准用麥克風（`MediaRecorder`），也才裝得了 PWA。
- **閘道 8787 照舊只綁 `127.0.0.1`，永遠不經 serve 開出去。** 手機只碰得到聊天室與它給畫面的 API；模型、搜尋、金鑰仍然只在閘道（ADR-0011 §3.4、NFR-SEC-04）。
- 創作者的 Tailscale 帳號與 tailnet 給這台電腦的網址（`<機器名>.<tailnet>.ts.net`）寫在 `$EF_DATA/settings/` 底下的設定檔（實作票定檔名），不進 repo；沒設定時 8791 不開。
- tailnet 的設定、手機加入 tailnet、開 serve，都是創作者在 Tailscale 那邊自己做的事；EF 不碰也不存 Tailscale 的金鑰。

### 3.3 跨站保護：兩個埠都保留現有的三道

聊天室的 API 會花錢（每句話都打模型），現在擋跨站請求的三道（`chat/api.py` 的進門檢查）在兩個埠上**全部保留**：

| 檢查 | 8790（本機桌面） | 8791（serve） |
| :--- | :--- | :--- |
| `Host` 白名單（擋 DNS rebinding） | 照舊只准 `127.0.0.1`、`localhost`、`[::1]` | **只准設定裡那一個 ts.net 網址** |
| 同源檢查：帶了 `Origin` 就要是自己；`Sec-Fetch-Site` 不是同源就擋 | 照舊 | 同一套，自己是 `https://<那個 ts.net 網址>` |
| `POST` 不收表單送得出的三種 `Content-Type`（`application/x-www-form-urlencoded`、`multipart/form-data`、`text/plain`） | 一般 API 照舊只收 `application/json`；上傳附件只收 `application/octet-stream`（§3.5） | 同左 |

- **8791 上真正擋跨站偽造請求（CSRF）的是同源檢查，不是身分標頭。** 身分標頭像 cookie 一樣是自動帶上的：手機瀏覽器開著別的網站時，那個網站叫瀏覽器打 EF 的 ts.net 網址，serve 一樣會補上創作者的身分。所以 `Origin` 與 `Sec-Fetch-Site` 的檢查在 8791 上不能省。
- 第三道照舊的理由：表單送得出的那三種 `Content-Type` 不需要瀏覽器先問（預檢），別的網站可以偷送；`application/json` 與 `application/octet-stream` 都要預檢，同源檢查就擋得下。
- **Android 的分享目標規定用 `multipart/form-data` 送過來（§3.4），伺服器不收。** 這個請求由 PWA 的 service worker 在手機上先接住，把分享的檔案交給分享頁；分享頁再照一般上傳的規矩一個附件一個請求送出去。伺服器從頭到尾不接受表單 POST。

### 3.4 像 App：PWA

- 聊天室做成 PWA：有 manifest 與圖示，可以加到手機主畫面、全螢幕開。不寫原生 App。
- **Service worker 只快取靜態檔**（HTML 外殼、CSS、JS、圖示），不快取 API 的回應、對話內容或附件。唯一的例外是分享進來的檔案：只在分享頁送出前暫時拿在 service worker 手上，送出或取消就丟掉，不寫進快取。
- **Android：** manifest 宣告分享目標（Web Share Target），其他 App 的「分享」選單裡就有 EF，截圖、連結、檔案可以直接分享進來。分享進來先停在一頁：列出要收的東西、選要放進哪個對話（預設開一個新對話），按一下才送出。
- **iOS：** Safari 不支援分享目標，改用聊天室輸入框的上傳按鈕（相簿、相機、檔案）。這是平台限制，不是遺漏。

### 3.5 丟進來的先收進素材清單，不自動分析

- **聊天輸入框可以收：** 圖片與截圖、檔案（Markdown、純文字、PDF）、連結、口述（在輸入框錄音，或上傳音檔）、打字。一則訊息最多 20 個附件（§3.8）。
- **每一個附件先收進這個對話的素材清單**（`CONTEXT.md`「素材清單」「附件」）：原始檔存成 `$EF_DATA/conversations/<對話 id>/materials/<sha256>`，以內容雜湊為名，寫一次不再改；清單本身是同一個資料夾裡只增不改的一份紀錄，每個附件記種類、時間、檔名、大小與 sha256。只有閘道寫（ADR-0021 的一個檔一個寫入者）。
- **上傳不經 base64 JSON。** 一個附件一個請求，`Content-Type: application/octet-stream`，原始位元組邊收邊寫進磁碟，寫完才算雜湊、改成正式檔名；不整份讀進記憶體。現在 `/api/extract` 把 base64 JSON 整份讀進記憶體的做法只留給它自己，不用在附件上。不另設「一則訊息的總大小」上限：每個附件都有自己的上限、又是邊收邊寫，記憶體不會因為一則訊息附件多而爆；20 × 30 MB 的最壞情況只佔磁碟。
  - 圖片：原檔照存，看圖照 §3.6。
  - 檔案：收進來之後，在伺服器上從存好的原檔抽出文字（沿用 `/api/extract` 的抽取程式），抽出來的文字跟原檔一起存。
  - 連結：沿用閘道的 `Fetcher` 抓；抓不到照舊標「讀不到」並寫原因（FR-IN-01、NFR-RUN-08）。
  - 口述：音檔存起來，接著轉文字（§3.7），逐字稿連同時間戳一起存，之後可以點一句回聽。
- **不自動開分析工單。** 收進清單不花模型的錢（轉文字除外，見 §3.7）；創作者說「分析這篇」「看一下這張截圖」，對話的 agent 才開 `analyze` 或讀那個附件。理由：不強迫互動（在外面丟了就走），錢只花在創作者選的事上。
  - 這一條改了 ADR-0019 §1 的「丟文章 → 系統自動分析」與 §3.2 的開工方式：以前在對話裡貼一個網址就開分析；之後網址也只是收進清單，對話的 agent 回一句收到了什麼、問要不要分析，創作者說要才開。創作者一句話裡就說「分析這篇」，照舊直接開。
  - 訂閱源這類沒人看著的自動投入不受影響，照 ADR-0019、ADR-0025 §3.5 只跑到分析報告。
- **跟作者素材的關係：** 素材清單屬於一個對話；作者素材屬於一張編輯卡（ADR-0025 §3.3）。清單上創作者自己的附件（口述、筆記、數據、截圖）帶進訪談時，經編輯卡的 `add_material` 變成那張編輯卡的作者素材；別人的文章經 `analyze` 變成種子，照舊分析。兩邊的檔都用內容的 sha256 命名，同一份內容對得起來。

**對話與畫面多的工具（修正 ADR-0021 §3.4）：**

| 工具 | 誰能叫 | 做什麼 |
| :--- | :--- | :--- |
| `list_attachments` | 對話的 agent | 列出這個對話素材清單上的每個附件（種類、時間、檔名、有沒有逐字稿） |
| `read_attachment` | 對話的 agent | 讀一個附件的內容：文字、抽出來的文字、逐字稿；圖片照 §3.6 縮過再給模型看 |
| `analyze` 多一種輸入 | 對話的 agent | 拿清單上的一個附件（連結或檔案）開分析，不用再丟一次 |
| `save_attachment` | 只有畫面，經閘道 | 把收到的附件寫進素材清單；口述就接著轉文字。對話的 Pi 叫不到 |

- 名字刻意跟編輯卡的 `add_material` 分開：`*_attachment` 碰的是對話的素材清單，`add_material` 寫的是一張編輯卡的作者素材（ADR-0025 §3.3）。一個附件要變成作者素材，是對話的 agent 在訪談裡用 `add_material` 把它的內容記進那張卡，兩邊不共用工具。
- 範圍照 ADR-0021：只碰得到這個對話自己的清單；別的對話的一律拒絕，而且不說它存不存在。
- 對話的 agent 仍然沒有通用的讀寫檔工具，也寫不進素材清單：清單只由創作者在畫面上丟東西產生。

### 3.6 看圖

- **圖片由對話的 agent 在創作者要它看時才看**，跟一般的對話一樣經閘道、記在對話的帳本、從對話的預算預留（ADR-0021 §3.3）。對話的模型預設是 `fast`（`ef serve --chat-tier`，預設 `fast`，是雲端模型，看得懂圖）。
- 送模型前先縮到長邊 2576 px 以內，原檔不動（理由見 §3.8 的圖片那一列）。
- **對話用 `local` 跑的時候，對話的 agent 直接說它看不懂圖，不自己換成雲端模型。** 理由：對話的等級是開 `ef serve` 時定的，同一個對話裡偷偷換一級，就是不經創作者同意多花錢（跟 NFR-RUN-05「不偷偷改用付費模型」同一個道理）；要看圖就照預設用 `fast` 開。

### 3.7 轉文字：OpenAI `whisper-1`，經閘道、記帳

- **為什麼是 `whisper-1`：** OpenAI 的轉文字模型裡只有它給得出時間戳（`verbose_json` 加 `timestamp_granularities`），正好接「點一句回聽」；價錢約 US$0.006／分鐘；單檔上限 25 MB；收 mp3、mp4、mpeg、mpga、m4a、wav、webm。
- **轉文字是閘道的一個供應商，照 ADR-0027 §3.4 生圖的模式：**
  - 金鑰用同一把 `$EF_SECRETS/openai`，只有閘道讀，不進日誌、帳本、錯誤訊息（NFR-SEC-04）。
  - 價目表加轉文字的價錢（依分鐘）；用真的金鑰前對一次 OpenAI 的現行定價。
  - **預留照伺服器自己量的長度：** 送出前，伺服器用 `ffprobe` 讀音檔的長度（瀏覽器錄的 webm 檔頭常常沒寫長度，就把檔案整個解一次來量），照價目表估價、從預算預留。讀不出長度的音檔，那個附件標「讀不出長度，沒轉」，不送出。
  - **結算照 whisper 回的長度**（`verbose_json` 的 `duration`）。
  - **預算不夠時：** 那個附件標「預算不夠，沒轉」，音檔照樣留著；創作者加了預算之後可以按重試。不會因為一個附件轉不了，整則訊息都收不進來。
  - 帳本一個音檔一筆，記模型、秒數、金額、延遲、狀態；帳單把轉文字單獨列一項。
  - 自動化測試一律用假的轉文字後端，不花錢（NFR-COST-06）。
  - OpenAI 沒回應、網路斷是基礎設施故障：那個附件標「轉文字失敗」並寫原因，音檔照樣留著，創作者可以按重試；不換別的供應商。
- **錢記在哪：** 收進清單時還沒有工單，所以轉文字記在這個對話自己的帳本，從對話的預算預留（ADR-0021 §3.3）；每月上限有設的話照樣算進去（ADR-0027 §3.6）。
- **口述收進來就轉，不另外問。** 創作者錄音就是要 EF 聽懂他說了什麼，逐字稿是讀它的前提；一小時不到半美元。分析、整理成想法卡這些要花模型錢的事，照 §3.5 等創作者說。

### 3.8 大小上限

參考 ChatGPT 與 Claude 的 App（2026-10-16 查，原文在規劃第七節）：

| 類型 | ChatGPT app | Claude app | EF 採用 | 理由 |
| :--- | :--- | :--- | :--- | :--- |
| 圖片 | 20 MB／張 | 10 MB／張、8000×8000 px | **20 MB／張**，原檔照存；送模型前縮到長邊 2576 px 以內 | 手機原圖常超過 10 MB；Claude API 單張上限 10 MB，新模型長邊超過 2576 px 會自己縮，先縮省錢 |
| 音檔 | （無單獨規定） | （無單獨規定） | **25 MB／檔** | Whisper API 硬上限；瀏覽器錄的 webm／opus 約一小時十幾 MB，夠用；超過先拒絕並說明，切段之後再做 |

- 數字放在設定裡，不寫死在畫面上；改上限不必改程式。

### 3.9 家裡電腦連不到時，手機上看到什麼

EF 跑在家裡那台電腦的 WSL 裡。電腦關機、WSL 睡著、或 Windows 記憶體不足把 WSL 收掉時，手機那頭就連不到。這是用私人網路換來的代價，畫面要講清楚，不能讓創作者以為東西送出去了。

| 情況 | 手機上看到 |
| :--- | :--- |
| 連不到聊天室（電腦關機、WSL 沒開、手機沒連上 Tailscale） | PWA 的外殼從快取打開，頂端一行：「連不到家裡的 EF。電腦可能關機或睡著了，也可能手機沒連上 Tailscale。」輸入框照樣能打字、能選附件，但送出按鈕換成「重試」 |
| 聊天室連得到，閘道沒回應 | 「EF 開著，但後面的閘道沒回應；東西還沒收進來。」照舊不偷偷換路（NFR-RUN-05） |
| 附件傳到一半斷掉 | 那個附件標「沒傳上去」與「重試」；已經收進清單的不會重複收（同一個 sha256 只存一份） |
| 身分對不上 | 「這個帳號不能用 EF。」不說誰才可以 |

- **P5a 不在手機上排隊暫存（待創作者確認）。** 送出前的東西只活在打開的頁面裡：頁面還開著就不會丟，重試就好；頁面關了、手機把瀏覽器收掉，沒送出的就沒了。不做排隊是因為複雜度：要在手機上留一份附件的副本、連回來時自動重送、重送時去重，這三件都要做對才不會丟或重複。創作者說的「不要回家再丟」其實是支持排隊的，所以這是第一版為了簡單做的取捨，P5a 的 Exit Gate（一週 10 次、沒有一次因為連不上放棄）量出來不夠，就回頭做排隊。
- 畫面只說看得出來的事；分不出是哪一種原因時，照第一列講，不猜。

## 4. 後果

- **正面：**
  - 創作者在外面就能把想法與看到的東西丟進來，入口不再只有「別人的一篇文章」。
  - 沒有公開網址、沒有帳號系統；對外的面只有 tailnet 裡的一個 HTTPS 埠，而且那個埠上每個請求都要是創作者本人；閘道與金鑰照舊只在本機。
  - 丟東西不花模型的錢（轉文字很便宜），要分析、要整理由創作者決定；花費照舊每一筆進帳本。
  - 逐字稿帶時間戳，P5b 的想法卡可以指回錄音的那一段。
- **負面：**
  - 家裡那台電腦要開著、WSL 要醒著；記憶體不足時手機那頭連不到。§3.9 只能把話講清楚，不能讓它連得到。
  - 多一個外部依賴（Tailscale，裝在 WSL 裡、要 systemd）與一個付費供應商（OpenAI 轉文字）；閘道要多維護一種價目與轉送格式；量音檔長度要 `ffprobe`（ffmpeg）。
  - `ef serve` 多一個埠，兩個埠的進門規則不同，測試要兩邊都蓋到。
  - 手機不排隊暫存：頁面關了，沒送出的就沒了（待創作者確認，§3.9）。
  - 在對話裡貼網址不再直接開分析，習慣以前那樣的會多說一句「分析這篇」。
  - 音檔超過 25 MB 先拒絕，長的口述要等切段做出來。
- **影響範圍：** `cli.py`（`ef serve` 多一個給 serve 的埠）、`chat/api.py`（兩套進門規則、附件的上傳、素材清單、斷線狀態）、`ui/pages.py`（上傳上限、PWA 外殼與 manifest、service worker、分享頁）、`src/evidence_forge/gateway/`（轉文字供應商、`save_attachment`、`list_attachments`、`read_attachment`、`analyze` 的輸入、價目表、帳本的種類）、`ui/bills.py`（轉文字一項）、ef-tools 的對話工具；PRD FR-MO、FR-MT、FR-TR、FR-IN-01、FR-IN-04、US-21、NFR-SEC-05、§9；`CONTEXT.md` 的素材清單、附件、口述、隨身入口；BDD `chat.feature` 的「從丟網址到拿到報告」與 `intake.feature` 的「在對話裡丟素材就開始分析」（只丟東西不再直接開分析）。
- **重新評估觸發：** 要給第二個人用；常常因為家裡電腦連不到而放棄丟東西（P5a 的 Exit Gate 量得到）；轉文字的花費在帳單上變成大項；或常常有超過 25 MB 的口述。
