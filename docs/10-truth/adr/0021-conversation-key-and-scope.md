# ADR-0021：對話鑰匙 `conv:<對話 id>:<第幾次開>`，對話只碰得到自己開的工單

> **狀態：** 已接受（創作者 2026-10-13 決定「兩個對話不共用分析」；PR 合併即接受） | **日期：** 2026-10-13 | **決策者：** 專案擁有者
> 依 `docs/templates/vibecoding/04_architecture_decision_record_template.md` 撰寫。
> **補充 ADR-0011 §3.6**（工單身分）與 **ADR-0019 §4**（對話要另外定義鑰匙與範圍）。
> 草稿由 #80 的 spike 起草（分支 `spike/p2-pi-rpc-chat`，結論在 #80 的留言），#84 實作閘道這一半。
> **後續修正：ADR-0025、ADR-0026、ADR-0027**——§3.4 的「對話沒有任何寫檔工具」改成：**對話沒有通用的讀寫檔工具；只有幾個有名字的閘道工具，各自只寫這個對話自己資料夾裡的一種東西**，報告與文章仍只能由工單產生。多的工具：編輯卡的 `propose_questions`、`record_interpreted_answers`（agent 解讀創作者打字的回答，事件標 `source: agent`）、`add_material`、`read_card`；另有只由畫面叫、對話的 Pi 叫不到的入口 `submit_station`、`keep_decision`、`reask_station`，閘道直接記（`source: ui`）後用 `[ef-card]` 通知對話（ADR-0025 §3.3）；開配圖工單的 `figures`（ADR-0027 §3.5）；lessons 的 `propose_lesson`，以及只由畫面叫的 `approve_lesson`（由閘道寫角色的 `lessons.md`，對話自己從不寫角色資料夾，ADR-0026 §3.3）。
> **後續修正：ADR-0028**——§3.4 對話再多兩個只讀的工具 `list_attachments`、`read_attachment`（只讀這個對話自己的素材清單），`analyze` 可以拿清單上的一個附件當輸入；把附件寫進素材清單的 `save_attachment` 只由畫面經閘道叫，對話的 Pi 叫不到。口述轉文字的花費記在對話的帳本、從對話的預算預留（§3.3 的對話帳本照舊）。

## 1. 背景與問題

- **上下文：** 改成聊天室之後（ADR-0019），每個對話是一個長時間開著的 Pi（RPC 模式）。它也要打模型、要開工、要讀報告，所以閘道要認得它、替它記帳、限制它能碰什麼。
- **工單鑰匙不能直接拿來用：** 工單鑰匙 `job:<工單>:<段>:<次>` 只在一段一次的 Pi 活著時有效，閘道照它找工單資料夾、記帳、算能寫哪裡。對話沒有段、沒有次，而且會被殺掉再接回、會跨好幾張工單。
- **要回答五件事：** 對話拿什麼鑰匙；它的帳記在哪、預算怎麼算；它能碰哪些檔；它能一次開幾張單；同一篇文章丟進兩個對話算不算同一份分析。
- **為什麼要寫成 ADR：** 這是閘道的身分與範圍規則（T3），之後所有對話工具都照它判斷；改回來要動閘道、帳本格式與 ef-tools。

## 2. 考量的選項

| 選項 | 結果 |
| :--- | :--- |
| 對話借用一張假工單的鑰匙（例：`job:c-xxx:chat:1`，對話資料夾放在 `jobs/` 底下） | 不採用：對話不是工單（`CONTEXT.md`），放在 `jobs/` 會被執行器、看板、帳單當成工單；`job.md` 的狀態機也套不上 |
| 對話不經閘道，主機直接替它打 Anthropic | 不採用：違反「閘道是唯一會花錢、會對外連線的地方」（ADR-0011 §3.4），對話的花費也不會進帳本 |
| **新的一種鑰匙 `conv:<對話 id>:<第幾次開>`，跟工單鑰匙用同一張登記表** | **採用** |

## 3. 決策

1. **鑰匙格式：`conv:<對話 id>:<第幾次開>`。**
   - 主機每替這個對話開一次 Pi，次數加一，記在 `conversation.json` 的 `launches`。
   - Pi 活著時登記在閘道（跟工單鑰匙同一張登記表），Pi 結束就撤銷。
   - 接回之後只認最新那一把：前一個還沒死透的 Pi 拿舊鑰匙來，一律拒絕（跟工單鑰匙「重跑同一段同一次」的道理一樣）。
   - 登記表記著每個對話登記過最大的第幾次開，撤銷之後也記著。第幾次開小於或等於它的一律不准登記：第 2 次開先登記好、延遲的第 1 次開才來登記，舊鑰匙也不會復活。對話主機接回時要先收掉舊的 Pi，再登記新鑰匙（#85）。
   - 對話 id 的字元規則跟工單 id 一樣（英數字開頭，只准英數字、點、底線、連字號），因為它會拿來拼路徑；`DataDir.conversation_dir` 拼路徑前就檢查（擋空字串、`/`、`..`、冒號）。
2. **對話資料夾放在 `$EF_DATA/conversations/<對話 id>/`：**
   - `conversation.json`：標題、建立時間、預算、開過幾次。只有主機寫。
   - `jobs.jsonl`：這個對話開過的工單，一行一張：`job_id`、`ts`、`version`、`parent`。只有閘道寫，只增不改。
     **每一版都是一張新工單**：補查、再改、換角色都開新單，不在同一張單上再跑一次；`parent` 指上一版的工單、`version` 是第幾版。分析開的單是第 1 版、沒有 `parent`。
   - `ledger.jsonl`：對話本身的模型呼叫。只有閘道寫，只增不改。
   - `pi-session/`：Pi 的對話紀錄（`--session-dir`，session id 就是對話 id）。只有 Pi 寫。
   - 工單仍在 `jobs/<工單 id>/`，不搬進對話資料夾：執行器、帳單、既有工具都不用改。`job.md` 多一欄 `conversation`，記是哪個對話開的（命令列開的是空的），只給投入去重用。
   - **「這個對話讀得到哪張工單」只看 `jobs.jsonl`。** 開單成功但還沒記進 `jobs.jsonl` 就當掉的話，下一次同樣的 `analyze` 會因為去重拿回那一張、補記進去。
   - `jobs.jsonl` 跟帳本用同一套追加寫入：一行一次寫完，上一筆寫到一半留下的殘行先補換行封起來，讀的時候跳過。
   - 閘道記進 `jobs.jsonl` 之前，先讀那張單的 `job.md`：`conversation` 不是這個對話就不記、回 500。範圍由閘道自己把關，不相信開單那一層回的工單 id。
3. **帳記在對話自己的帳本，算進每月總額。**
   - 帳本那一行寫 `conversation_id`、`job_id` 留空，段是 `chat`、次是第幾次開。一行只屬於一張工單或一個對話，兩欄剛好一個有值。帳單要分「對話」與「工單」，看這一欄就好，不用解析字串。
   - 閘道內部（登記表、預留、告示板）用 `conv:<對話 id>` 當擁有者 id：帶冒號，不可能跟工單 id 撞。**它不拼進任何路徑**：冒號在 Windows 的磁碟上不能當檔名，所以帳本、預算一律經 `DataDir.owner_dir` 導到 `conversations/<對話 id>/`，`DataDir.job_dir` 看到冒號直接報錯。
   - 每月上限的加總包含所有對話的帳本（`conversations/*/ledger.jsonl`）。
   - 對話另有自己的美元上限（`conversation.json` 的 `budget_usd`，預設 US$1），只管對話本身的呼叫；讀不到 `conversation.json` 就當成 0，雲端呼叫一律不放行。
4. **能碰的範圍：**
   - 對話鑰匙只能用對話的工具：`analyze`、`read_report`、`job_status`（之後加 `rewrite`、`read_article`、`list_personas`）。讀寫檔、抓網頁、搜尋、跑腳本這些段的工具一律拒絕。ef-tools 也只對對話註冊對話的工具，模型根本看不到段的工具。
   - 段的鑰匙不能用對話的工具（段不能自己開新工單、不能讀別張單的結果）。
   - 讀報告、問狀態只准讀列在這個對話 `jobs.jsonl` 裡的工單；別的對話開的一律拒絕，而且不說那張單存不存在。
   - 對話沒有任何寫檔工具：報告與文章只能由它開出去的工單產生（chat.feature「對話的 agent 不自己寫內容」）。
   - **每個對話同一時間最多 1 張工單在跑**（排隊中也算）。要開第二張新單時回 409，訊息帶著在跑的那張單，讓對話的 agent 跟創作者說「等它跑完」；同一篇文章再丟一次（連按兩下）不算新單，照樣拿回在跑的那一張。數字可以改（`EF_CHAT_MAX_RUNNING_JOBS`）。理由：對話的 agent 可以連續開單，每張單各有自己的預算，不擋的話總花費只剩月上限管得到。
     - 「在跑幾張」看每張單 `job.md` 的 `conversation`，不看 `jobs.jsonl`：開了單、還沒記進 `jobs.jsonl` 就當掉的那張也算在跑。
     - 已經滿了，而這次不會是拿回在跑的那一張（換了素材，或要重做），就在抓網頁之前擋下，不對外抓、不寫投入帳。同一份素材（貼的文字比內容 hash，網址比素材項目記的網址）才放過去讓去重處理；放過去之後要開的若是新單（例如換了目標），開單前照樣擋。
5. **對話不走模型快取。** 閘道的快取鍵是（工單, 段, 次, 請求 hash），同一個鍵第 n 次送出就回放帳本裡第 n 份成功的回應。對話一律不查這份快取，每次都轉送：
   - 對話的 Pi 每一輪都帶著整段紀錄，一模一樣的請求只會是同一輪重送，省不到什麼。
   - 會重送一模一樣請求的情況，例如創作者按「重新回答」，要的正是不一樣的答案。
   - 查快取要整份讀這個帳本；對話的帳本跨月一直長，每一輪都讀一次划不來。
   - 當機重跑也不需要它：主機重開後對話的 Pi 是新的一次開，次數不同，本來就對不上舊的鍵。
   - 重播模式（只看錄音，給測試與評估用）照舊適用。
6. **去重：同一份素材、同一份配方、同樣的目標，只在同一個對話裡才拿回舊工單。**
   - 創作者 2026-10-13 決定：**兩個對話丟同一篇文章，不共用分析**，各開各的單、各自只讀得到自己的。對話之間完全隔開。
   - 去重的鍵是「對話 + 素材 + 配方 + 目標」。素材項目（`inbox/manual/<內容 hash>/`）照舊只存一份；不共用的是工單。
   - 命令列的 `ef new` 沒有對話，只跟同樣沒有對話的工單去重；它不會拿到對話開的單，對話也不會拿到它開的單。改變有兩個：配方也算進鍵（以前同素材、同目標、不同配方會拿回舊單，現在開新單；只有一份配方時碰不到，有了重構配方就會碰到）；失敗與未完成的單不再拿回。
   - **只拿回排隊中、執行中，或跑完而且完成的單。** 失敗與未完成的單不拿回，再丟一次就開新單；不然一篇失敗過的文章在這個對話裡就再也分析不了。丟棄的單也不拿回，但不能只靠排除「丟棄」：工單狀態收成三種之後（#89），丟棄的單讀起來就是跑完了，所以條件寫成「完成才拿回」。
   - `analyze` 帶 `again: true` 就是重做（US-21 第 3 點「除非我要它重做」）：不走去重，一定開新單。同時在跑的上限照樣適用。
   - 補查、再改、換角色一律不走去重：每一版都是新工單（第 2 點）。
7. **工單跑完怎麼回到對話（對話主機那一張實作）：** 主機看到這個對話的工單結束，就對它的 Pi 送 `/ef-job-done <工單 id>`（ef-tools 的指令，不是模型能叫的工具）。ef-tools 用對話鑰匙問閘道那張單的狀態，在對話紀錄裡放一則 `ef-job` 通知，叫模型接著讀報告。同一張單已經通知過就不再通知，所以主機在每次接回時可以把跑完的單全部再送一次。

## 4. 後果

- **正面：**
  - 閘道的模型轉送、預留與結算、帳本都不用分兩套，對話跟工單走同一條路。
  - 對話的花費進帳本，每月總表算得到（chat.feature「對話本身的花費也入帳」）。
  - 範圍規則全部在閘道一個地方判斷，ef-tools 只轉送。
  - 對話之間完全隔開：讀不到別的對話開的單，同一篇文章也不會拿到別的對話的分析。
- **負面：**
  - 帳本格式多一欄 `conversation_id`、`job_id` 變成可以留空（NFR-OBS-01）。舊的帳本每一行都有 `job_id`，照樣讀得懂。
  - 同一篇文章丟進兩個對話會分析兩次、花兩次錢。等知識庫（P4）出來，新的分析先查它，可以把舊報告當參考，但仍是各自一張單。
  - 環境變數仍叫 `EF_JOB_KEY`，裝的卻可能是對話鑰匙；名字不準，但改名要同時改 ef-tools 與執行器。
  - 每個打開的對話都是一個常駐的 Node 程序（spike 量到常駐記憶體約 115 MB），要有閒置多久就關掉的規則（對話主機那一張定）。
- **還沒決定、要創作者選的：**
  - **對話開單的花費怎麼管。** 現在照第 4 點的預設：同一時間最多 1 張在跑，數字可以改。另外兩個做法：
    - 工單的預算也從對話的預算預留：對話的上限變成「這個對話連同它開的單一共能花多少」，最直接，但一個對話的預算要開到好幾美元，而且算預算要跨好幾份帳本。
    - 一個對話開超過 N 張單要創作者確認：不擋第一張，但多開時一定有人看過；要在畫面上做一個確認的動作。
  - 對話預算用完時，對話裡要怎麼說、要不要讓創作者在畫面上加額度。
- **影響範圍：** `src/evidence_forge/gateway/`（鑰匙、範圍、預算、帳本路徑、快取）、`convkey.py`、`conversations.py`、`paths.py`、`ledger_models.py`（帳本多一欄）、`runner/intake.py`（去重的鍵）、`models.py`（`job.md` 多一欄）、`harness/pi/extensions/ef-tools/`、帳單頁、`CONTEXT.md`（「對話鑰匙」「對話資料夾」）。
- **重新評估觸發：** 一個對話要同時開很多個 Pi（例如分頁各一個）；對話要能直接用某個段的工具（例如自己抓網頁）；知識庫出來之後，重複分析同一篇文章的花費變成問題。
