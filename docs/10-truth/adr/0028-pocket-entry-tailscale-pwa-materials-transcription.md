# ADR-0028：隨身入口：Tailscale、PWA、多模態素材、轉文字

> **狀態：** 已接受（創作者 2026-10-16 拍板；PR 合併即生效） | **日期：** 2026-10-16 | **決策者：** 專案擁有者
> 依 `docs/templates/vibecoding/04_architecture_decision_record_template.md` 撰寫。
> **修正：** ADR-0019 §1、§3.2——對話的起點不再只有「丟一篇別人的文章，它就開始分析」：丟進對話的東西先收進素材清單，創作者說要分析才開 `analyze`（§3.4）。ADR-0021 §3.4——對話多兩個只讀的工具 `list_materials`、`read_material`，`analyze` 可以拿素材清單上的一項當輸入；畫面多一個對話的 Pi 叫不到的入口 `save_material`，由閘道寫（§3.5）。**補充 ADR-0011 §3.4：** 閘道多一個會花錢的供應商（OpenAI 轉文字），跟 ADR-0027 的生圖同一套預估、預留、結算與記帳（§3.6）。
> 規劃原文：`30-snapshot/plans/2026-10-16-voice-first-replan.md`。票：#129。

## 1. 背景與問題

- **上下文：** 創作者最常有想法的時候不在電腦前。現在的 EF 只能在家裡那台電腦的瀏覽器開（`ef serve` 的聊天室 8790 與閘道 8787 都只綁 `127.0.0.1`），也只能從「別人的一篇文章」開始。想法要等回家才丟得進來，多半就忘了。
- **創作者 2026-10-16 拍板：**
  1. 使用者只有創作者自己：單人、純檔案、本機；不做多人，也不做登入系統。
  2. 手機要能直接用，未來看起來像一個 App：截圖、照片、檔案、連結、錄音、打字，在外面就能直接丟進來，不要回家再丟。
  3. 轉文字先用 OpenAI 的 `whisper-1`。
  4. 每種東西的大小上限參考 ChatGPT 與 Claude 的 App（§3.7）。
- **要回答的事：** 手機怎麼安全地連到家裡那台電腦；「像 App」做到什麼程度；丟進來的東西存在哪、誰寫、會不會自動花錢；錄音怎麼變成文字、錢記在哪；家裡電腦連不到時手機上看到什麼。
- **為什麼要寫成 ADR：** 這是 EF 第一次讓 `127.0.0.1` 以外的裝置連進來（T3）；閘道多一個付費供應商；對話多工具、起點也改了。改回來要動網路設定、身分檢查、閘道、帳本與畫面。

## 2. 考量的選項

| 選項 | 結果 |
| :--- | :--- |
| 開一個公開網址（雲端主機或反向代理），自己做帳號登入 | 不採用：一個人用的工具要先扛多人產品的成本（帳號、密碼、被掃描、憑證），而且資料要離開家裡那台電腦 |
| 寫原生 App（Android、iOS 各一支） | 不採用：兩套程式、上架、更新；目前要驗證的是「在外面丟得進來」，不是 App 本身 |
| 先存在手機上，回家再同步 | 不採用：創作者明說「不要回家再丟」；同步還要處理重複與衝突 |
| 本機跑 whisper 轉文字 | 不採用：WSL 的記憶體本來就緊，本機模型會跟 Qwen 搶；雲端一分鐘約 US$0.006，一小時不到半美元 |
| **Tailscale 私人網路＋`tailscale serve` 只開聊天室的 HTTPS；畫面做成 PWA；丟進來的先收進素材清單；轉文字經閘道用 `whisper-1`** | **採用** |

## 3. 決策

### 3.1 只有創作者一人

- EF 是一個人的工具。沒有帳號系統、沒有登入頁、沒有「使用者」這個資料。
- 「是不是創作者」只用 Tailscale 帶來的身分判斷（§3.2）。之後要給第二個人用，是另一份 ADR 的事（§4 重新評估觸發）。

### 3.2 手機怎麼連進來：Tailscale

- 家裡那台電腦與創作者的手機加進同一個 Tailscale 私人網路（tailnet）。**不開公開網址**，tailnet 以外的人連不到。
- **`tailscale serve` 只把聊天室（8790）用 HTTPS 開給 tailnet。** HTTPS 憑證由 Tailscale 發；瀏覽器要在 HTTPS 底下才准用麥克風（`MediaRecorder`），也才裝得了 PWA。
- **閘道 8787 照舊只綁 `127.0.0.1`，不經 serve 開出去。** 手機只碰得到聊天室與它給畫面的 API；模型、搜尋、金鑰仍然只在閘道（ADR-0011 §3.4、NFR-SEC-04）。
- `ef serve` 的兩個埠照舊只綁 `127.0.0.1`；連進來的路只有 `tailscale serve` 這一條。
- **身分檢查：** `tailscale serve` 轉進來的請求帶著 `Tailscale-User-Login` 標頭（請求者的登入帳號）；外面送來的同名標頭會被 serve 拿掉，所以偽造不了。
  - 帶著這個標頭的請求，帳號一定要等於創作者的帳號，對不上就回 403，畫面只說「這個帳號不能用」，不說創作者的帳號是誰。
  - 創作者的帳號寫在 `$EF_DATA/settings/` 底下的設定檔（實作票定檔名），不進 repo；沒設定時，帶標頭的請求一律拒絕。
  - 沒帶標頭的請求只當成本機桌面直接連 `127.0.0.1:8790`。Tailscale 的文件寫明，從帶 tag 的裝置來的請求不會有身分標頭，所以本機直連與 tag 裝置經 serve 進來，單看標頭分不出來。**實作票要先確認分得出這兩種；分不出來，就一律要求標頭**，桌面也改開 serve 的網址。
- 憑證、tailnet 的設定、手機加入 tailnet，都是創作者在 Tailscale 後台自己做的事，EF 不碰也不存 Tailscale 的金鑰。

### 3.3 像 App：PWA

- 聊天室做成 PWA：有 manifest 與圖示，可以加到手機主畫面、全螢幕開。不寫原生 App。
- **Service worker 只快取靜態檔**（HTML 外殼、CSS、JS、圖示），不快取 API 的回應、對話內容或素材。手機上不留對話與素材的副本，手機掉了也不會多洩一份。
- **Android：** manifest 宣告分享目標（Web Share Target），其他 App 的「分享」選單裡就有 EF，截圖、連結、檔案可以直接分享進來。分享進來先停在一頁：列出要收的東西、選要放進哪個對話（預設開一個新對話），按一下才送出。
- **iOS：** Safari 不支援分享目標，改用聊天室輸入框的上傳按鈕（相簿、相機、檔案）。這是平台限制，不是遺漏。

### 3.4 丟進來的先收進素材清單，不自動分析

- **聊天輸入框可以收：** 圖片與截圖、檔案（Markdown、純文字、PDF）、連結、口述（在輸入框按住錄音，或上傳音檔）、打字。一則訊息最多 20 個附件（§3.7）。
- **每一樣都先收進這個對話的素材清單**（`CONTEXT.md`「素材清單」）：原始檔存成 `$EF_DATA/conversations/<對話 id>/materials/<sha256>`，以內容雜湊為名，寫一次不再改；清單本身是同一個資料夾裡只增不改的一份紀錄，每一項記種類、時間、檔名、大小與 sha256。只有閘道寫（ADR-0021 的一個檔一個寫入者）。
  - 圖片：原檔照存。要讀懂內容時由雲端模型看圖（本機 9b 不保證看得懂圖）；送模型前先縮到長邊 2576 px 以內，原檔不動。
  - 檔案：沿用現有的文字抽取（`/api/extract`），抽出來的文字跟原檔一起存。
  - 連結：沿用閘道的 `Fetcher` 抓；抓不到照舊標「讀不到」並寫原因（FR-IN-01、NFR-RUN-08）。
  - 口述：音檔存起來，接著轉文字（§3.6），逐字稿連同時間戳一起存，之後可以點一句回聽。
- **不自動開分析工單。** 收進清單不花模型的錢（轉文字除外，見 §3.6）；創作者說「分析這篇」「看一下這張截圖」，對話的 agent 才開 `analyze` 或讀那一項。理由：不強迫互動（在外面丟了就走），錢只花在創作者選的事上。
  - 這一條改了 ADR-0019 §3.2「丟了就開始分析」：以前在對話裡貼一個網址就開分析；之後網址也只是收進清單，對話的 agent 回一句收到了什麼、問要不要分析，創作者說要才開。創作者一句話裡就說「分析這篇」，照舊直接開。
  - 訂閱源這類沒人看著的自動投入不受影響，照 ADR-0019、ADR-0025 §3.5 只跑到分析報告。
- **跟作者素材的關係：** 素材清單屬於一個對話；作者素材屬於一張編輯卡（ADR-0025 §3.3）。清單上創作者自己的東西（口述、筆記、數據、截圖）帶進訪談時，經 `add_material` 變成那張編輯卡的作者素材；別人的文章經 `analyze` 變成種子，照舊分析。兩邊的檔都用內容的 sha256 命名，同一份內容對得起來。

### 3.5 對話與畫面多的工具（修正 ADR-0021 §3.4）

| 工具 | 誰能叫 | 做什麼 |
| :--- | :--- | :--- |
| `list_materials` | 對話的 agent | 列出這個對話素材清單上的每一項（種類、時間、檔名、有沒有逐字稿） |
| `read_material` | 對話的 agent | 讀一項的內容：文字、抽出來的文字、逐字稿；圖片照 §3.4 縮過再給模型看 |
| `analyze` 多一種輸入 | 對話的 agent | 拿清單上的一項（連結或檔案）開分析，不用再丟一次 |
| `save_material` | 只有畫面，經閘道 | 把輸入框收到的東西寫進素材清單；口述就接著轉文字。對話的 Pi 叫不到 |

- 範圍照 ADR-0021：只碰得到這個對話自己的清單；別的對話的一律拒絕，而且不說它存不存在。
- 對話的 agent 仍然沒有通用的讀寫檔工具，也寫不進素材清單：清單只由創作者在畫面上丟東西產生。

### 3.6 轉文字：OpenAI `whisper-1`，經閘道、記帳

- **為什麼是 `whisper-1`：** OpenAI 的轉文字模型裡只有它給得出時間戳（`verbose_json` 加 `timestamp_granularities`），正好接「點一句回聽」；價錢約 US$0.006／分鐘；單檔上限 25 MB；收 mp3、mp4、mpeg、mpga、m4a、wav、webm。
- **轉文字是閘道的一個供應商，照 ADR-0027 §3.4 生圖的模式：**
  - 金鑰用同一把 `$EF_SECRETS/openai`，只有閘道讀，不進日誌、帳本、錯誤訊息（NFR-SEC-04）。
  - 價目表加轉文字的價錢（依分鐘）；用真的金鑰前對一次 OpenAI 的現行定價。
  - 送出前照音檔長度估價、先預留；讀不出長度就照 25 MB 能錄的最長時間預留，拿到結果照實際結算。
  - 帳本一個音檔一筆，記模型、秒數、金額、延遲、狀態；帳單把轉文字單獨列一項。
  - 自動化測試一律用假的轉文字後端，不花錢（NFR-COST-06）。
  - OpenAI 沒回應、網路斷是基礎設施故障：那一項標「轉文字失敗」並寫原因，音檔照樣留著，創作者可以按重試；不換別的供應商。
- **錢記在哪：** 收進清單時還沒有工單，所以轉文字記在這個對話自己的帳本，從對話的預算預留（ADR-0021 §3.3）；每月上限有設的話照樣算進去（ADR-0027 §3.6）。
- **口述收進來就轉，不另外問。** 創作者錄音就是要 EF 聽懂他說了什麼，逐字稿是讀它的前提；一小時不到半美元。分析、整理成想法卡這些要花模型錢的事，照 §3.4 等創作者說。

### 3.7 大小上限

參考 ChatGPT 與 Claude 的 App（2026-10-16 查，原文在規劃第七節）：

| 類型 | ChatGPT app | Claude app | EF 採用 | 理由 |
| :--- | :--- | :--- | :--- | :--- |
| 圖片 | 20 MB／張 | 10 MB／張、8000×8000 px | **20 MB／張**，原檔照存；送模型前縮到長邊 2576 px 以內 | 手機原圖常超過 10 MB；Claude API 單張上限 10 MB，新模型長邊超過 2576 px 會自己縮，先縮省錢 |
| 音檔 | （無單獨規定） | （無單獨規定） | **25 MB／檔** | Whisper API 硬上限；瀏覽器錄的 webm／opus 約一小時十幾 MB，夠用；超過先拒絕並說明，切段之後再做 |
| 文件（pdf、md、txt） | 512 MB／檔 | 對話 500 MB／檔、專案 30 MB／檔、PDF 1000 頁 | **30 MB／檔**（現在是 5 MB），PDF 1000 頁 | 一個人在家用的機器，抓 Claude 專案檔的上限；真正卡的是能不能塞進模型，不是檔案大小 |
| 一則訊息幾個附件 | 3 小時 80 個 | 20 個 | **20 個** | 照 Claude app |

來源：[ChatGPT File Uploads FAQ](https://help.openai.com/en/articles/8555545-file-uploads-faq)、[Upload files to Claude](https://support.claude.com/en/articles/8241126-upload-files-to-claude)、[Claude Vision 文件](https://platform.claude.com/docs/en/build-with-claude/vision)、[OpenAI Speech to text](https://developers.openai.com/api/docs/guides/speech-to-text)。

- 超過上限的那一項在送出前就擋下，畫面說是哪一個、上限多少；同一則訊息的其他項照收。
- 數字放在設定裡，不寫死在畫面上；改上限不必改程式。

### 3.8 家裡電腦連不到時，手機上看到什麼

EF 跑在家裡那台電腦的 WSL 裡。電腦關機、WSL 睡著、或 Windows 記憶體不足把 WSL 收掉時，手機那頭就連不到。這是用私人網路換來的代價，畫面要講清楚，不能讓創作者以為東西送出去了。

| 情況 | 手機上看到 |
| :--- | :--- |
| 連不到聊天室（電腦關機、WSL 沒開、手機沒連上 Tailscale） | PWA 的外殼從快取打開，頂端一行：「連不到家裡的 EF。電腦可能關機或睡著了，也可能手機沒連上 Tailscale。」輸入框照樣能打字、能選附件，但送出按鈕換成「重試」 |
| 聊天室連得到，閘道沒回應 | 「EF 開著，但後面的閘道沒回應；東西還沒收進來。」照舊不偷偷換路（NFR-RUN-05） |
| 附件傳到一半斷掉 | 那一項標「沒傳上去」與「重試」；已經收進清單的不會重複收（同一個 sha256 只存一份） |
| 身分對不上 | 「這個帳號不能用 EF。」不說誰才可以 |

- **送出前的東西只活在打開的頁面裡。** 頁面還開著就不會丟，重試就好；手機不另外排隊暫存，因為排隊就要處理重送與重複，第一版不做（§4 負面）。
- 畫面只說看得出來的事；分不出是哪一種原因時，照第一列講，不猜。

## 4. 後果

- **正面：**
  - 創作者在外面就能把想法與看到的東西丟進來，入口不再只有「別人的一篇文章」。
  - 沒有公開網址、沒有帳號系統；對外的面只有 tailnet 裡的一個 HTTPS 埠，閘道與金鑰照舊只在本機。
  - 丟東西不花模型的錢（轉文字很便宜），要分析、要整理由創作者決定；花費照舊每一筆進帳本。
  - 逐字稿帶時間戳，P5b 的想法卡可以指回錄音的那一段。
- **負面：**
  - 家裡那台電腦要開著、WSL 要醒著；記憶體不足時手機那頭連不到。§3.8 只能把話講清楚，不能讓它連得到。
  - 多一個外部依賴（Tailscale）與一個付費供應商（OpenAI 轉文字）；閘道要多維護一種價目與轉送格式。
  - 手機不排隊暫存：頁面關了，沒送出的就沒了。
  - 在對話裡貼網址不再直接開分析，習慣以前那樣的會多說一句「分析這篇」。BDD `chat.feature` 的「從丟網址到拿到報告」要跟著改（P5a 的票）。
  - 音檔超過 25 MB 先拒絕，長的口述要等切段做出來。
- **影響範圍：** `ui/pages.py`（上傳上限、`/api/extract`、身分檢查、PWA 外殼與 manifest、分享目標的頁）、`chat/api.py`（素材清單、斷線狀態）、`src/evidence_forge/gateway/`（轉文字供應商、`save_material`、`list_materials`、`read_material`、`analyze` 的輸入、價目表、帳本的種類）、`ui/bills.py`（轉文字一項）、ef-tools 的對話工具；PRD FR-MO、FR-MT、FR-TR、FR-IN-01、FR-IN-04、US-21、§9；`CONTEXT.md` 的素材清單、口述、隨身入口；BDD `chat.feature`、`intake.feature`。
- **重新評估觸發：** 要給第二個人用；常常因為家裡電腦連不到而放棄丟東西（P5a 的 Exit Gate 量得到）；轉文字的花費在帳單上變成大項；或常常有超過 25 MB 的口述。
