# ADR-0027：配圖用程式畫，只有封面用生圖；生圖經閘道預留、記帳，每月上限可以不設

> **狀態：** 已接受（創作者 2026-10-15 拍板；PR 合併即生效） | **日期：** 2026-10-15 | **決策者：** 專案擁有者
> 依 `docs/templates/vibecoding/04_architecture_decision_record_template.md` 撰寫。
> **補充 ADR-0011 §3.4：** 閘道多一個會花錢的供應商（OpenAI 生圖），跟 Anthropic 用同一套預估、預留、結算與記帳。**修正：** PRD NFR-COST-01 的「每月上限預設 US$10」改成可以不設（§3.6）。
> 規劃原文：`30-snapshot/plans/2026-10-15-content-workflow-integration.md`。票：#105。

## 1. 背景與問題

- **上下文：** EF 到現在只產文字。創作者自己的寫作流程每篇都有配圖：一張封面、幾張概念圖或流程圖、有數據時畫數據圖，圖的位置照大綱的圖文分鏡；另有五支已經實戰過的腳本（畫封面、畫概念圖、數據圖的版型、驗證數據圖的依據、檢查圖文節奏）。那些腳本散在一個 skill 資料夾裡，色票寫死，生圖呼叫的是 repo 外的一支腳本，自己讀 OpenAI 金鑰，花的錢沒有記在任何帳上。
- **創作者 2026-10-15 拍板：** 第一個里程碑含配圖（封面、概念圖、數據圖），不含發布到網站。每月上限先不設，雲端平台自己的後台已經有硬上限；EF 另做一頁費用設定（#115）。
- **要回答的事：** 哪一種圖用什麼方式產生；數據圖的數字從哪裡來才算有依據；生圖怎麼經閘道計費；沒有每月上限時，花費靠什麼擋。
- **為什麼要寫成 ADR：** 這是閘道第一個不是 Anthropic、也不是搜尋的付費供應商（T3），而且改了每月上限的預設；換回來要動閘道、價目表、帳本、帳單與設定。

## 2. 考量的選項

| 選項 | 結果 |
| :--- | :--- |
| 每一張圖都用生圖模型 | 不採用：概念圖的箭頭、節點、文字要跟文章一字不差，生圖做不到；數據圖的數字不能讓模型畫 |
| 腳本照舊自己讀 OpenAI 金鑰、自己呼叫 | 不採用：違反「閘道是唯一會花錢、會對外連線的地方」（ADR-0011 §3.4），花費也進不了帳本 |
| 先不做配圖，等發布那一階段 | 不採用：創作者要在第一個里程碑就看到完整的一篇，預覽也要有圖 |
| **概念圖與數據圖用程式畫；只有封面用生圖，生圖經閘道預留與記帳** | **採用** |

## 3. 決策

### 3.1 四種圖

| 種類 | 怎麼產生 | 說明 |
| :--- | :--- | :--- |
| 封面 | 生圖模型 | 每篇一張，是插畫，不是圖解 |
| 概念圖 | 程式畫 | 流程、架構、對照；箭頭、節點順序、圖中文字跟文章一致 |
| 數據圖 | 程式畫 | 數字只從證據帳本來（§3.3） |
| 截圖 | 這份不定 | 預覽認得它、會照截圖的版型排；怎麼取得與授權照 ADR-0016，等素材下載回來時再定 |

- 圖的位置照編輯卡的圖文分鏡（ADR-0025 第 6 關）：圖跟在它要證明的那一段後面。
- 每張圖有替代文字與圖說。

### 3.2 畫圖的程式收進 repo

- 五支腳本收成 `src/evidence_forge/figures/` 套件，用 uv 管依賴。配圖段經閘道的 `run_script` 執行（ADR-0009、`gateway/scripts.py` 的規則照舊：只跑登記的腳本、不經 shell、拿不到金鑰、有逾時）。
- 色票、字型、封面預設從角色的 `brand.yaml` 讀（ADR-0026 §3.3），找不到就用中性的預設值。品牌的色票與字型不進 repo。
- 字型缺了就給清楚的錯誤，不默默換字型（中文字會變成方塊）。
- **圖文節奏檢查**是配圖段的程式檢查：第一張圖之前、沒有圖的連續段落、兩張圖之間的字數照規則量；例外要寫理由。沒過就算這一次不合格，走重試與升級（ADR-0022）。

### 3.3 數據圖的證據帳本

- 有數據圖的文章有一份證據帳本 `charts/evidence.json`：每一筆有編號、一句陳述、種類（實測、推算、預測、假設）、出處位置、單位、期間、母體與數值。
- 每張數據圖有一份圖表說明 `charts/fig-<N>.brief.json`：讀者要回答的問題、這張圖的結論、引用了帳本哪幾筆、至少兩個候選圖型與選這一種的理由。
- 程式檢查兩份的格式與交叉引用（說明引用的每一筆都在帳本裡）。畫圖的程式只能從帳本拿數字。
- **在 EF 裡多一條：** 帳本每一筆的出處要對得到這張工單讀得到的東西：分析報告的來源（`sources.json` 裡真的抓過的網頁，ADR-0020 §3.5），或創作者在訪談裡給的資料（編輯卡快照）。模型不能自己寫一個數字當出處。
- 證據帳本跟閘道的帳本（花費）是兩回事，名字只是像。

### 3.4 生圖經閘道

- 生圖是閘道的一個工具，配圖段經閘道叫它；畫圖的程式只負責組提示、裁切、轉檔，拿不到金鑰，也不直接連 OpenAI。
- **供應商：** OpenAI 的生圖模型。金鑰放 `$EF_SECRETS/openai`（沒設就是 `~/.config/evidence-forge/secrets/openai`），跟 Anthropic、Tavily 的金鑰一樣只有閘道讀，不進日誌、帳本、錯誤訊息（NFR-SEC-04）。
- **跟模型呼叫同一套錢的規則：**
  - 價目表加生圖的價錢，依模型、尺寸、品質查；價錢以 OpenAI 現行定價頁為準，用真的金鑰前核對一次。
  - 送出之前照價目表估這一張要多少，先從這張工單的預算預留；不夠就拒絕。拿到結果再照實際結算。
  - 帳本一張圖一筆，種類是 `image`（帳本已有這一種），記模型、尺寸、品質、金額、延遲、狀態。帳單把生圖單獨列一項，看得出生圖花了多少。
  - 同一段同一次嘗試裡送出一模一樣的生圖請求，回放存好的那一張，不重付（NFR-COST-02）。
  - 重播模式只回放存好的圖；自動化測試一律用假的生圖後端，不花錢（NFR-COST-06）。
  - OpenAI 沒回應、網路斷是基礎設施故障：停下、標失敗，不換別的供應商。
- 封面再生一次就是再花一次，每一次都記帳；創作者要換封面時，對話裡說得出這次大約多少錢。

### 3.5 配圖是寫稿之後的一段

- 配圖是配方裡的一段（`figures`），讀文章的圖位與編輯卡快照的分鏡，產出封面、概念圖、數據圖。它接在寫稿配方的最後，還是單獨開一張配圖工單，由 #112 依實作定；兩種都照段產出的規矩放（ADR-0010）。每篇的資料夾整理成 `article.md`、`images/`、`charts/` 的樣子給預覽用（#113）。
- 改圖跟改稿一樣是新工單、新版本，舊的圖不覆寫。

### 3.6 預算：單張工單的預算照舊，每月上限可以不設

- **單張工單的美元與 Tavily credits 預算照舊**（ADR-0011 §3.4），生圖的花費也從這裡預留。
- **每月上限預設不設**（創作者 2026-10-15）：雲端平台自己的後台已經有硬上限。有設的時候照舊擋，模型、搜尋、生圖、對話的花費全部算進去；沒設的時候只靠單張工單與單個對話的預算擋。
- 設定放 `$EF_DATA/settings/costs.json`：每月上限（可以是「不設」）、各種工作的預設預算。費用設定頁（#115）寫這個檔；`EF_MONTHLY_BUDGET_USD` 這類環境變數照樣能蓋過設定檔，給測試用。
- 生圖的計費不依賴每月上限：有沒有設，預留與記帳都一樣。

## 4. 後果

- **正面：**
  - 每一張圖的花費進帳本，帳單看得出生圖花了多少；金鑰只在閘道。
  - 概念圖與數據圖不花錢、可以重畫，文字與數字跟文章一致；數據圖的每個數字都回得到出處。
  - 色票字型在角色資料裡，換一個角色就換一套樣子。
- **負面：**
  - 閘道多一個供應商：要維護生圖的價目表、預估與錯誤處理，而且它不是 Anthropic Messages 格式，要另外寫轉送。
  - 新的 Python 依賴（畫圖、表格、影像處理）讓安裝變大；字型是前置條件。
  - 每月上限不設之後，沒人看著時花太多錢只剩單張預算與雲端後台的硬上限擋得住（PRD §10 的風險表跟著改）。
  - 截圖這一種先不做，需要截圖的文章這個里程碑只能放替代的概念圖。
- **影響範圍：** `src/evidence_forge/gateway/`（生圖工具、`credentials.py`、`prices.yaml` 與 `prices.py`、`budget.py`、`config.py`）、`src/evidence_forge/figures/`（新）、`harness/recipes/rewrite.md` 或新的配方（`figures` 段）、`harness/skills/`（配圖 skill）、`ui/bills.py`（生圖一項）、`ui/`（費用設定頁）、`pyproject.toml`；PRD NFR-COST-01、§9 外部依賴、§10；`CONTEXT.md` 的封面、概念圖、數據圖、證據帳本。
- **重新評估觸發：** 生圖的花費在帳單上變成大項；創作者要正文裡也用生圖；或每月實際花費常常超過他心裡的數，要把每月上限的預設改回來。
