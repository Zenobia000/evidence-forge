# ADR-0005：跨 Run 快取，檔案儲存區只增不改

> **狀態：** 已接受 | **日期：** 2026-10-10 | **決策者：** 專案擁有者
> **後續修正：** 由 ADR-0010、ADR-0011 修正實作——快取與只增不改改由閘道與工單資料夾實作。原則不變。
> 依 `docs/templates/vibecoding/04_architecture_decision_record_template.md` 撰寫。延伸 ADR-0003（State 與內容分開）與 ADR-0004（同一 Run 內的冪等），不覆蓋它們。

## 1. 背景與問題

- **上下文：** ADR-0004 保證**同一次 Run** 恢復時不重做。但實際上更常見的重跑是**換一次 Run**：修了 bug 重跑同一篇、改了 prompt 要比較、R5 的三組實驗跑同一批 20 篇。
- **問題：**
  - 每次新 Run 都從頭擷取、搜尋、呼叫 LLM，修一個寫作節點的 bug 也要重付整條流程的錢。三組實驗各自搜尋，約 1,080 credits，超過 Tavily 每月 1,000 的免費額度。
  - 網頁會改版或消失。只存「最後一次抓到的版本」，舊 Run 的證據就對不回去了。
- **驅動因素：** 成本（PRD NFR-02、NFR-06）；證據可回溯（PRD §6、NFR-14）。

## 2. 考量的選項

### 選項一：只靠 ADR-0004 的 Run 內冪等

- **優點：** 不用多做。
- **缺點：** 跨 Run 全部重付；實驗成本翻三倍。
- **成本／複雜度：** 低

### 選項二：跨 Run 快取＋只增不改的內容儲存

- **描述：**
  - 內容一律依 hash 存檔，同樣內容只存一份，**永不覆寫**；網頁改版就是另一個 hash，新舊都留著。
  - 快取鍵：擷取用 canonical URL；Tavily 用「正規化後的查詢＋參數」；LLM 用「模型 ID＋prompt 版本＋輸入 hash」。
  - 擷取與搜尋快取有有效期限（網頁會變）；LLM 快取不過期（同樣的輸入、模型與 prompt 版本，重用結果是安全的）。
  - 每個 Run 可以選「沿用快取」或「強制重新擷取」。
- **優點：** 改哪個節點就只有它之後花錢；實驗共用快照；舊證據永遠找得回來。
- **缺點：** 儲存只增不減；快取命中要能在執行紀錄裡看出來，否則會誤以為「這次真的查過」。
- **成本／複雜度：** 中

### 選項三：用外部快取服務（例如 Redis）

- **缺點：** 多一個服務要維運，而且 Redis 預設不保證持久，正好跟「留得住」相反。
- **成本／複雜度：** 高

## 3. 決策

**選擇：** 選項二。

1. 檔案儲存區只增不改，依內容 hash 定址。原始擷取（`raw/`）與 AI 產出（`derived/`）分開放。
2. 快取索引放在 Metadata DB（ADR-0003），與 ADR-0004 的操作紀錄分開：操作紀錄回答「這個 Run 做過沒」，快取回答「別的 Run 做過沒」。
3. 每次命中快取都記進執行紀錄（FR-10），標明「取自快取，原始 Run 是哪一個」。
4. 擷取與搜尋快取的有效期限是設定值，預設值在 R0 基線之後定。
5. 證據快照（`CONTEXT.md`）是快取的一份凍結複本，建立後不受有效期限影響。

**理由：** 成本和證據保存其實是同一個機制：只要內容依 hash 存、永不覆寫，「不重付」與「找得回當時的原文」就一起解決了。

## 4. 後果

- **正面：** 修 bug、改 prompt、做實驗時，只有改到的節點之後才花錢；證據不會因為來源網站改版而消失。
- **負面：** 儲存空間只增不減，要靠備份與（人工觸發的）清理控制；快取鍵的組法一旦改了，舊快取就全部失效。
- **影響範圍：** `clients`（查快取再呼叫）、`artifacts`（只增不改）、執行紀錄、測試（重播錄好的回應，本質上就是一份固定的快取）。
- **重新評估觸發：** 儲存量大到單機磁碟吃緊；或要多使用者共用快取時（隱私與權限）。
