# ADR-0013：給目標就自動做完，人只審結果

> **狀態：** 已接受 | **日期：** 2026-10-10 | **決策者：** 專案擁有者
> 依 `docs/templates/vibecoding/04_architecture_decision_record_template.md` 撰寫。
> 原本的人工停點（選研究問題、定題 Gate）是 PRD v1.5 的需求（FR-02、FR-03、FR-06），原文見 `30-snapshot/2026-10-10-prd-v1.5.md`。

## 1. 背景與問題

- **上下文：** 舊設計的定位是「人決定立場」：產完研究問題要停下選題，研究完要在定題 Gate 接受或改寫論點，論點還必須跟原作者不同。
- **創作者的修正：**
  - 不需要替原作者寫得不好的地方提出自己的主張。
  - 他給目標，AI 照目標把內容產出來，他審文章。
  - 不滿意就再下一句 prompt，同一條流程重跑。
  - 中間每一步都要人介入，等於沒辦法全自動，這個設計是錯的。
- **為什麼要寫成 ADR：** 這推翻了產品的核心定位與好幾條 P0 需求；之後要把停點加回來，流程、狀態、UI 都要改。

## 2. 考量的選項

| 選項 | 結果 |
| :--- | :--- |
| 維持選題停點與定題 Gate | 不採用：沒辦法全自動 |
| 停點變成可選的設定 | 不採用：現在沒有人要用，先做會變成沒人維護的分支（需要時用配方加一段「停下等決定」） |
| **全自動到待審；退件時附一句意見重跑** | **採用** |

## 3. 決策

1. **工單從開始到進待審，中間不停下等人。**
2. **原本人在中間把關的事，改成自動處理：**
   - 自動檢查：引句真實、引用完整、不照抄、圖片授權、格式（架構草案 v0.3 §6）。沒過就自動回寫作段修，修到上限還不過，就帶著沒過的清單進待審。
   - 預算上限：用完就停，帶著目前的結果進待審。
3. **人只在待審出手**：
   - 通過。
   - 退件：寫一句意見，選從哪段重跑，預設依配方。上游的產出照樣沿用，不重付。
   - 丟棄。
   - 通過之後還能再改，舊版保留。
4. **拿掉的需求**：選研究問題的停點、定題 Gate、「論點不得與原作者立場實質相同」。整理段仍然列出作者的主張與觀點，因為那是二創的材料，不是要反駁的對象。
5. **不變的底線**：
   - 不自動公開發布。公開永遠要人按。
   - 授權不明的圖不進成品。
   - 不繞過付費牆。
   - 不無上限地迴圈：每段有最多嘗試次數，每張單有預算。

## 4. 後果

- **正面：** 可以排程自動跑；人的時間只花在看結果；退件意見累積起來，就是評估資料（PRD 的評估需求）。
- **負面：**
  - AI 自己挑切角，可能不合創作者的意思；只能靠目標寫清楚、`my-style` skill 和退件迴圈修正。
  - 自動檢查只擋得住程式判斷得了的錯；觀點好不好，仍然要人審。
- **影響範圍：** PRD 的流程、使用者故事與功能需求；BDD 的定題與研究提案情境（拿掉）；UI 從「多個停點畫面」改成「看板＋待審」。
- **重新評估觸發：** 退件率長期偏高，而且退件意見集中在「切角不對」。那時可以在配方加一段「產出三個切角讓人選」，但要做成可選的一段，不改回全面停點。
