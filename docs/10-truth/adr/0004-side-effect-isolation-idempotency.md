# ADR-0004：外部副作用獨立成節點，用冪等鍵去重

> **狀態：** 已接受 | **日期：** 2026-10-10 | **決策者：** 專案擁有者
> **後續修正：** 由 ADR-0010、ADR-0011 修正實作——不再有節點與 `operation_key`；所有外部呼叫經過閘道，靠請求 hash 快取與重播保證不重付。原則不變。
> 依 `docs/templates/vibecoding/04_architecture_decision_record_template.md` 撰寫。

## 1. 背景與問題

- **上下文：** LangGraph 從 interrupt 恢復時，**整個節點從頭重跑**，`interrupt()` 之前的程式會再執行一次（ADR-0001）。程式崩潰後從 checkpoint 恢復，也會重跑那個還沒完成的節點。
- **問題：** 重跑的節點如果裡面有 Tavily 搜尋、LLM 呼叫、寫檔或送到網站，就會重複扣錢、重複寫入，甚至重複發布。PRD §8 要求「中斷恢復重跑節點時不重複收費、不重複發布」。
- **驅動因素：** 成本可控；發布不可重複；故障注入測試要 100% 可恢復（`brief.md` §4）。

## 2. 考量的選項

### 選項一：副作用寫在業務節點裡，靠小心

- **優點：** 節點少。
- **缺點：** 只要有人在 `interrupt()` 前面加一個呼叫，就會重複扣錢，而且平常測不出來。
- **成本／複雜度：** 低（起步），出事時高

### 選項二：外部呼叫獨立成節點＋冪等鍵

- **描述：** 每一種外部副作用（搜尋、LLM 呼叫、寫檔、送出到網站）各自是一個節點，不和 `interrupt()` 放在同一個節點。每次呼叫前用 `run_id + operation_key` 查紀錄，已經做過就直接回傳上次的結果。
- **優點：** 重跑變成安全的；可以用故障注入測試證明。
- **缺點：** 節點變多；要維護一張操作紀錄表；`operation_key` 的組法要穩定。
- **成本／複雜度：** 中

## 3. 決策

**選擇：** 選項二。

規則：

1. 有外部副作用的程式碼，只能出現在專門的副作用節點裡。
2. `interrupt()` 所在的節點不准有外部副作用。
3. 每個副作用以 `run_id + operation_key` 為鍵，做之前先查，做完把結果記下來。
4. `operation_key` 由「節點名稱＋輸入內容的 hash」組成，同樣的輸入一定得到同樣的鍵。

**理由：** 恢復時重跑是 LangGraph 的設計，不是 bug，只能讓副作用承受得了重跑。

## 4. 後果

- **正面：** 定題 Gate 等再久、程式重啟幾次，搜尋與 LLM 都只付一次錢；發布只會發生一次。
- **負面：** 節點數增加，圖比較長；操作紀錄表要跟著 Run 一起保存。
- **影響範圍：** 所有呼叫 Tavily、Anthropic、Ollama、檔案系統與網站的程式；測試要包含「同一節點跑兩次」的情境。
- **重新評估觸發：** LangGraph 提供節點內部的部分恢復，或內建的冪等任務機制時，再評估能否簡化。
