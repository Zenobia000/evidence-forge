## 怎麼讀

- **區域**照領域語言分（`CONTEXT.md`）：`INTAKE` 投入、`DIGEST` 整理、`COMPOSE` 二創、`CHECK` 自動檢查、`REVIEW` 待審與審稿、`GATEWAY` 閘道、`LEDGER` 帳本與預算、`BILL` 帳單；另外兩個是元件名：`RUNNER` 執行器、`UI` 簡易 UI。帳本與帳單分兩區，因為 `CONTEXT.md` 明講它們是兩個東西：帳本是機器寫的流水帳，帳單是給人看的報表。
- **路徑**：`$EF_DATA` 預設是專案的 `data/`（NFR-KEEP-04）。`<id>` 是工單 ID，在工單詳情頁的網址 `/jobs/<id>` 看得到。
- **算帳本的小指令**（好幾條會用到，先放這裡）：
  - 依段數筆數：`uv run python -c "import json,sys,collections as c;print(c.Counter(json.loads(l)['stage'] for l in open(sys.argv[1])))" $EF_DATA/jobs/<id>/ledger.jsonl`
  - 加總金額：`uv run python -c "import json,sys;print(sum(json.loads(l)['cost_usd'] for l in open(sys.argv[1])))" $EF_DATA/jobs/<id>/ledger.jsonl`
- **工單對到的 issue**：S0.14（Exit Gate 實跑）是 #31；各案例要的功能由 #19～#30 做出來，對照見 `test-blueprint.md`〈追溯表〉。
- **故障注入**：TC-GATEWAY-02、TC-RUNNER-09 需要一個能故意製造 429 與「產出不合格」的開關（`test-blueprint.md` 缺口 G-06）。開關不存在時，這兩條判「未判」並註明原因。

## TC-INTAKE-01 — 在新增工單頁貼一段文字，開出一張排隊中的工單
- **狀態**：active
- **負責人**：創作者
- **來源**：FR-IN-01／US-01／`intake.feature`〈手動投入就開一張工單〉
- **角色**：創作者
- **前置條件**：`uv run ef serve` 已啟動，開跑前檢查全過；手邊有一篇文章的全文
- **步驟**：
  1. 開啟 `/`，點頂部的「＋新增」，進到 `/jobs/new`
  2. 選「貼文字」分頁，把全文貼進去
  3. 目標填「給台灣 PM 看的 1,500 字觀點文」，配方選 `restructure`，預算用預設
  4. 按送出
  5. 在終端機執行 `ls -t $EF_DATA/inbox/manual/ | head -1`，打開那個資料夾的 `item.json`
  6. 從看板點新卡片進 `/jobs/<id>`，再打開 `$EF_DATA/jobs/<id>/job.md`
- **期望結果**：送出後回到看板，「排隊」欄出現新卡片（可能先顯示「準備中」，幾秒內換成真的卡片）；`item.json` 有出處（manual）、時間、內容 hash；`job.md` 的目標是剛剛填的那句，配方是 `restructure`
- **最近判定**：未判

## TC-INTAKE-02 — 貼一個公開網址，抓回正文並開單
- **狀態**：active
- **負責人**：創作者
- **來源**：FR-IN-01、NFR-RUN-08、NFR-COST-03／US-01
- **角色**：創作者

  1. 在 `/jobs/new` 選「貼網址」，貼上網址，填目標，送出
  2. 打開新的 `$EF_DATA/inbox/manual/<項目>/item.json`、`content.md`，列出 `raw/`
  3. 列出 `$EF_DATA/cache/fetch/`

- **期望結果**：`item.json` 有原網址與抓取時間；`content.md` 是正文、不是整頁 HTML；`raw/` 留著原始 HTML；`cache/fetch/` 多了這個網址的一筆，看得到有效期限；帳本有一筆 `fetch`，狀態 `ok`
- **最近判定**：未判

## TC-INTAKE-06 — 網址回 403 或是付費牆，不繞過，工單以失敗進待審
