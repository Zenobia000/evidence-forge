## 2. 為什麼做

**痛點。** 讀到一篇好文章，最花時間的是：弄懂作者到底在主張什麼、立場在哪；查他說的對不對；找其他相關的文章；最後用自己的角度和聲音寫出來。直接叫 AI 改寫，會照搬原文的結構和句子、編出不存在的來源，寫出來也不像自己。

**定位。** 不是「文章改寫器」，是一個**研究與寫作的工作台**：AI 先把一篇文章讀懂、查證、延伸成一份分析報告；人讀報告、追問、決定要不要寫、用哪個角色寫。報告一份份累積，長成一套技術基本功的知識體系。

**為什麼這次這樣設計。**
- 第一版在中間放了固定的表單關卡（選研究問題、定題），流程被綁死（ADR-0013）。
- 第二版改成全自動產線加待審。2026-10-12 用六篇文章實跑，流程跑得通，但方向錯了：
  - 逐句拆主張、逐字引句，是在錯的地方下功夫，本機模型也做不動。
  - 稿子每句掛引用，讀起來像報告。
  - 看板與審稿解的是創作者沒有的問題。
- 這一版：分析與重構分開，人在對話裡決定下一步（ADR-0019）；查證放在寫稿之前，寫成報告給人看（ADR-0020）。

## 3. 核心工作（JTBD）

> 我讀到一篇值得想的文章，就丟進聊天室。它告訴我作者在說什麼、站在哪裡、哪些說法查得到佐證、哪些有疑慮、還有哪些題材可以延伸。我看完追問兩句，覺得值得寫，就叫它用某個角色、某種文體寫一篇；不滿意就說一句叫它改。這些報告留下來，慢慢變成我自己的知識體系。

## 4. 什麼算成功

以下都是**要驗證的門檻**，還沒有實測結果。驗證方式與時間點見 `roadmap.md`。

| 指標 | 門檻 |
| :--- | :--- |
| 分析報告有用 | 創作者讀完覺得「讀懂了作者、查證有用、題材值得寫」的比例 ≥ 80%（P1 用 6 篇評，之後持續記） |
| 文章像自己、不是改寫 | 創作者覺得可以直接拿去改來發的比例 ≥ 50%（P1b 起追蹤） |
| 從丟素材到拿到報告 | ≤ 10 分鐘 |
| 每篇的花費 | 分析＋重構一次可計量，且落在每次工作的預算內；US$0.6 是試算基準（見 §5） |
| 換模型或改 skill 後 | 同一批素材重跑，創作者判斷沒有變差才上線 |

任何一項沒過，都不能自動公開發布；公開永遠要人按。

## 5. 要驗證的假設

### 5.1 成本假設

單價以 2026-10-10 官方頁面為準：Sonnet 5.5 每百萬 tokens 輸入 US$2／輸出 US$10；Opus 5.5 輸入 US$4／輸出 US$20；Tavily 每 credit US$0.008，免費方案每月 1,000 credits。

2026-10-12 的實測（舊流程：整理＋補料＋二創，六篇）：每篇 US$0.43～0.90，Tavily 3～5 credits。依此粗估新流程：

| 工作 | 段 | 每篇估計 |
| :--- | :--- | :--- |
| 分析 | brief（本機；失敗升級 strong） | US$0～0.15 |
| 分析 | 查證與找題材（strong＋Tavily 4～8 credits） | US$0.25～0.45 |
| 重構 | 重構（strong） | US$0.15～0.3，每再改一次約同價 |
| 對話 | 每輪（strong） | US$0.01～0.05 |
| **合計** | 分析一次＋重構一次 | **約 US$0.4～0.9／篇** |

- 這份假設**不是上限**，上限由每次工作的預算擋（PRD NFR-COST-01）。P1、P1b 實測後更新。

### 5.2 本機模型夠不夠做 brief

舊流程裡，本機 Qwen3.5 9B 做逐句拆解六篇全敗。假設：讀懂整篇並寫成文字，比逐字抽引句容易，9B 做得動。P1 用 ihower 六篇驗證；本機的 brief 常常誤解作者，就把 brief 段改成 `strong`（只改配方，ADR-0011）。
