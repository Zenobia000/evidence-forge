# 路線圖

> 階段的唯一的家。票與 PR 引用階段編號（`S2`），不另寫一版。需求編號的內容在 `10-truth/requirements/prd.md`。
> 舊版（R0～R5）：`30-snapshot/2026-10-10-roadmap-r0-r5.md`。階段改用 `S` 開頭，避免跟舊的 `R` 編號混用。

**為什麼重排（2026-10-11）：** 架構改成「agent 核心＋資料夾狀態」（ADR-0009～0013）。最大的未知是「Pi＋本機 Qwen＋skill 能不能把一篇別人的文章變成能用的二創稿」，所以第一階段就是一個能端到端跑的實驗，含一個陽春但功能齊全的 UI。Celery、Redis、PostgreSQL 都不需要了（ADR-0010）。

週次是建議，不是承諾；過不了 Exit Gate 就不進下一階段。

| 階段 | 建議週次 | 交付 | Exit Gate |
| :--- | :--- | :--- | :--- |
| **S0** 實驗：核心迴路 | 第 1–2 週 | 執行器、閘道（模型代理、預算、快取與重播、帳本）、Pi 擴充 `ef-tools`、配方 `restructure`（整理→二創→檢查）、skill `digest`、`compose`、`verify`、12 份文類定義、作家設定（聲音＋解說文與筆記摘要兩類的文類風格）、手動投入、簡易 UI（看板、工作單詳情、審稿、新增、帳單）、開跑前檢查、CI 重播 | 5 篇真實電子報都跑出稿子；退件→重跑→v2 可用；每篇的花費與時間有帳單；中途殺掉程序後重跑不重付；C1 捏造引句為 0；實測成本更新 `brief.md` §5.1 |
| **S1** 評估 | 第 3 週 | 評估架子：10 篇凍結案例與人工標註、硬指標、評審兩兩比較與人工校準、只重跑某一段、真實回饋記錄、UI 評估頁、從範本學作家風格（FR-CP-05） | 基準 v0 報告完成；`local` 與 `strong` 做整理的比較完成並決定配方分級（`brief.md` §5.2） |
| **S2** 膠水層 | 第 4–5 週 | connector 介面、兩個真實訂閱源（創作者指定，可能是部落格）、`drive` connector、排程、自動開單、UI 訂閱源頁 | 兩個訂閱源無人看管連跑一週：沒有重複開單、沒有超出預算、抓取失敗都看得到 |
| **S3** 補料與素材 | 第 6–7 週 | `research` 段（Tavily、額度上限）、圖片與上游素材下載、授權與「引用」使用狀態、C4 檢查、UI 的來源與圖分頁 | 補充來源都可回溯；授權不明的圖 0 件進成品；Tavily 每篇實測用量更新成本假設 |
| **S4** 品質與擴充 | 第 8 週起 | 依評估與退件資料調整 skill 與分級；第二份配方；UI 套用設計系統（ADR-0007、ADR-0008） | 一次通過率與審稿時間達 `brief.md` §4 的門檻 |
| **Later** | — | 網站草稿預覽（FR-EX-01）、錄音感想等其他投入方式、學習型派發器的 A/B 實驗（接在閘道後面）、跨工作單查詢的 SQLite 索引、多台機器 | 依實際需求再決定 |

MVP = S0～S3。
