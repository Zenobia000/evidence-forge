# 路線圖

> 階段的唯一的家。票與 PR 引用階段編號（`P1`），不另寫一版。需求編號的內容在 `10-truth/requirements/prd.md`。
> 舊版：`30-snapshot/2026-10-16-roadmap-p0-p4.md`（P0～P4，加 P5a～P8 之前）、`30-snapshot/2026-10-13-roadmap-s0-s4.md`（S0～S4，自動產線）、`30-snapshot/2026-10-10-roadmap-r0-r5.md`（R0～R5）。階段改用 `P` 開頭，避免跟舊的 `S`、`R` 編號混用。

**為什麼重排（2026-10-13）：** 產品改成「聊天室：先分析、再重構」（ADR-0019、ADR-0020）。S0 已經做好的執行器、閘道、帳本、Tavily 搜尋與來源放置全部沿用。2026-10-12 的實跑證明，最大的未知是**內容品質**：報告和文章寫不好，介面改得再好也沒用。所以先用命令列證明新流程寫得出好東西，再換介面。

**為什麼再加 P5a～P8（2026-10-16）：** 創作者最常有想法的時候不在電腦前，而 EF 只能在家裡那台電腦上、從「別人的一篇文章」開始；記憶也只有角色資料夾與單張編輯卡，沒有跨文章的「我以前怎麼看這件事」。所以接著做：先讓手機丟得進來（P5a），再把一段口述整理成想法（P5b），再把想法問成論點（P6）、查得更深（P7），最後才記住立場（P8）——要先有前面累積的資料，記憶才有東西可記。P8 取代原本的 P4 知識庫。規劃原文見 `30-snapshot/plans/2026-10-16-voice-first-replan.md`，P5a 的決策見 ADR-0028。

週次是建議，不是承諾；過不了 Exit Gate 就不進下一階段。

| 階段 | 建議週次 | 交付 | Exit Gate |
| :--- | :--- | :--- | :--- |
| **P0** 決策與文件 | 第 1 天 | ADR-0019、ADR-0020、PRD v3.0、`brief.md` v3.0、`CONTEXT.md`、BDD、路線圖、票的整理 | 創作者確認 |

| **P1b** 重構配方 | 第 1–2 週 | `rewrite` skill、`rewrite` 配方、標題與金句規則、角色選擇、帶意見再改 | 用 P1 的報告寫出六篇，創作者覺得像自己寫、不是原文改寫的 ≥ 3 篇 |
| **P2** 對話 spike | 第 1–2 週（可跟 P1 並行） | Pi RPC 開著一個對話，用 `analyze` 工具開工、等它跑完、把結果帶回；事件串流到一個最小網頁；對話的工作鑰匙與範圍 | 從丟網址到拿到報告走通一次；關掉瀏覽器再開，對話還在 |

| ~~**P4** 知識庫~~ | — | **由 P8 取代（2026-10-16）。** 原本是跨對話索引、主題頁、分析前先查舊知識；改成先記創作者自己的立場，報告的索引併進 P8 再定 | — |
| **創作流程**（GitHub 里程碑，收尾） | — | #114 lessons 的提議與核准（程序記憶的寫入路徑，也是 P8「記憶升格」的範本）；#112 封面生圖、#113 預覽移到 Later（創作者 2026-10-16） | 依原票 |
| **P5a** 隨身入口 | 接在創作流程收尾之後 | 手機與桌機都能用、像 App 的入口（ADR-0028）：Tailscale＋`tailscale serve` 只開聊天室的 HTTPS、身分檢查；PWA 外殼與 Android 分享目標；輸入框收截圖與照片、檔案、連結、口述、打字；每樣先收進對話的素材清單（原始檔只寫一次），不自動分析；口述經閘道轉文字、記帳；家裡電腦連不到時講清楚 | 創作者在外面用手機丟東西進來，一週內至少 10 次，沒有一次因為「連不上／傳不上」放棄 |
| **P5b** 想法卡 | P5a 之後 | 一段口述＋一堆素材 → AI 整理成想法卡（立場、理由、親身經驗、待查問題、可能題目），每項標 `speaker: creator`、`status: tentative`；不強迫互動；想法卡可以一鍵帶進編輯卡（`origin: idea`）；逐字稿保留時間戳可以回聽 | 至少 5 段口述整理後，創作者覺得「是我的意思」 |
| **P6** 追問式訪談 | P5b 之後 | 編輯卡前加「深度訪談」模式：讀素材與想法卡，一次一題追問缺口（反對的是數據還是結論？這個經驗撐得起這個結論嗎？），可略過、可「稍後研究」；答案進第 2、4 關與主張清單 | 創作者覺得問題「有打到點」的比例過半 |
| **P7** 多來源研究 | P6 之後 | 一次分析多篇來源（比較不同作者）；配方平行展開查證（開工前寫 ADR-0030）；獨立性升級到網域與原始出處；查證結果可以指回來源段落（存在來源檔，不進報告） | 三篇比較的報告，創作者讀完覺得有用 |
| **P8** 思想記憶（取代 P4） | P7 之後 | 只增不改的立場事件（提議、確認、修改、撤回），連到想法卡、來源、編輯卡、文章；可以刪掉重建的索引（SQLite FTS）；訪談開始前先查「你過去對這題的立場」；記憶頁：查看、修正、撤銷、匯出（開工前寫 ADR-0029） | 新文章中，有引用到已確認舊立場的比例量得出來（知識再利用率） |
| **Later** | — | YouTube 字幕、原生 App、多人與登入、#112 封面生圖、#113 預覽、發布、跨作品回顧（「哪些觀點成熟了？」）、訂閱源自動投入、評估、素材下載與授權 | 依實際需求再決定 |

MVP = P0～P3。P5a～P8 的順序：P5a 是入口，沒有入口其他都用不到；P6 讓入口的想法變成論點；P7 是研究深度；P8 要等前面累積出資料才有東西記。
