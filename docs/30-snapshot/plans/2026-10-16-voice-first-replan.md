## Context

創作者貼了一份產品構想（Voice-first Thought-to-Publish＋思想記憶），想知道：
1. 現在的 EF 能不能解決「有想法、沒時間寫」這個痛點；
2. 現有方向跟構想的異同，哪些概念已經做了；
3. 深度研究要不要讓 Pi 叫子代理，代理怎麼管；
4. 依 MVP 分階段的路線圖，以及怎麼開發。

這份規劃只做「方向調整與路線圖」，每一階段開工前各自開 ADR 與票，照既有 T3 流程走。

## 一、結論先講

**差距大約一半，但方向是同一條。** 構想說的三道護城河——作者主權、觀點驗證、思想記憶——EF 已經做了前兩道的骨架，第三道（思想記憶）完全沒做。真正缺的是「入口」和「記憶」：

- **入口**：EF 從「別人的一篇文章」開始；構想從「我今天有什麼想法」開始。
- **記憶**：EF 的記憶只有角色資料夾（文風）和單篇編輯卡；構想要跨文章的「立場」與「思想演變」。

產線後半段（訪談→編輯卡→寫稿）反而是構想裡最該守的地方，EF 已經做得比構想寫的還嚴。

## 三、我不同意構想的地方（先講清楚，免得走歪）

1. **它在寫一個多人 SaaS，EF 是一個人的工具。** PostgreSQL、pgvector、物件儲存、手機 App、10 位 PoC 使用者，全都是「多人產品」的成本。創作者自己就是第 0 號使用者，先用自己驗證「說話→作品」走得通。純檔案＋可重建的索引（SQLite FTS）撐得住一個人幾千篇。
2. **轉文字本身不難，難的是整理。** 構想自己引的 Reddit 訊號就這樣說。所以錄音、轉文字用現成服務接上就好，力氣花在「接住一大段亂講的話和一堆截圖連結，整理成想法卡」。
3. **思想記憶不能變成「從記憶補事實」。** PRD 的反模式（`prd.md:110`、ADR-0020 §3.5）：查證不准憑記憶填。思想記憶只存「創作者的立場與理由」，事實每次照樣重查。
4. **AI 萃取的立場不能自動升格。** 跟 lessons 同一條規矩（決定 G）：AI 提議、創作者在畫面上核准、閘道寫入。

## 四、深度研究與子代理：不要讓 Pi 自己生子代理

**工單執行器已經就是子代理機制。** 每個階段是一個獨立的 Pi 執行，自己的工作鑰匙、預算、帳本、輸出檢查（`runner/pi_launch.py`、`jobkey.py`）。缺的只是：階段只能一個接一個跑，而且配方是固定的。

Pi 1.1.0 沒有內建子代理，只附了一個範例 extension（`examples/extensions/subagent/`）。直接載入會出問題：子行程沿用對話的 `conv:` 鑰匙，閘道分不出是誰在花錢、碰哪些工單，ADR-0021 的範圍與帳本就破了。

**建議做法：在配方層做「平行展開」，由閘道管。**
- 配方的一個階段可以宣告 `fan_out: key_claims`：brief 產出 K1…Kn，執行器為每個主張開一個子階段（各自的鑰匙 `job:<id>:<stage>.<k>:<attempt>`、分到一份搜尋額度與預算），全部完成後跑 `merge` 階段寫報告。
- 「代理管理」直接沿用已有的東西：鑰匙＝身分、帳本＝花費、`events.jsonl`＝進度、檢查＝品質。不另造一套代理管理系統。
- 要改的硬規則：`runner/sources.py` 要求網址必須由「這個階段這次嘗試」抓過——改成「由這張工單的某個子階段抓過」。
- 注意：本機 qwen 一次只能跑一個（`concurrency: 1`），平行只在雲端等級有用，等於要花錢。所以深度研究是**創作者點了才跑**的選項，不是預設。

## 五、路線圖（接在 P0–P4 之後，重排 P4）

| 階段 | 交付 | Exit Gate |
|---|---|---|
| **M3 收尾** | #114 lessons 提議與核准（程序記憶的寫入路徑，也是之後「記憶升格」的範本）；#112 封面、#113 預覽視創作者決定 | 依原票 |
| **P5a 隨身入口** | 手機與桌機都能用、像 ChatGPT app 的入口（見下方「P5a 細節」）：截圖／照片、檔案、連結、錄音、打字都能直接從手機丟進對話；每樣東西先存成**素材**（原始檔只寫一次），不急著分析 | 創作者在外面用手機丟東西進來，一週內至少 10 次，沒有一次因為「連不上／傳不上」放棄 |
| **P5b 想法卡** | 一段口述＋一堆素材 → AI 整理成**想法卡**（立場、理由、親身經驗、待查問題、可能題目），每項標 `speaker: creator`、`status: tentative`；不強迫互動；想法卡可一鍵帶進編輯卡（`origin: idea`）；錄音保留時間戳可回聽 | 至少 5 段口述整理後，創作者覺得「是我的意思」 |
| **P6 追問式訪談** | 編輯卡前加「深度訪談」模式：讀素材＋想法卡，一次一題追問缺口（反對的是數據還是結論？這個經驗撐得起這個結論嗎？），可略過、可「稍後研究」；答案進第 2、4 關與 claims 清單 | 創作者覺得問題「有打到點」的比例過半 |
| **P7 多來源研究** | 一次分析多篇來源（比較不同作者）；`fan_out` 平行查證（第四節）；獨立性升級到網域／原始出處；查證結果可指回來源段落（存在來源檔，不進報告） | 三篇比較的報告，創作者讀完覺得有用 |
| **P8 思想記憶**（取代原 P4） | `data/memory/` 只增不改的事件（`stance_proposed / confirmed / revised / retracted`），連到想法卡、來源、編輯卡、文章；可重建的索引（SQLite FTS，衍生物、可刪可重建）；訪談開始前先查「你過去對這題的立場」；記憶頁：查看、修正、撤銷、匯出 | 新文章中，有引用到已確認舊立場的比例可以量出來（知識再利用率） |
| **Later** | YouTube 字幕、原生 App、多人與登入、#112 封面、#113 預覽、發布、跨作品回顧（「哪些觀點成熟了？」） | 依實際需求 |

順序的理由：P5 是入口，沒有入口其他都用不到；P6 讓入口的想法變成論點；P7 是研究深度；P8 要等前面累積出資料才有東西記。

### P5a 細節（創作者 2026-10-16 說明：多模態、手機直接傳、不要回家再丟）

- **手機怎麼連到家裡的 EF**：Tailscale 私人網路＋`tailscale serve` 只把聊天室（8790）以 HTTPS 開給自己的裝置；閘道 8787 繼續只綁 `127.0.0.1`。不開公開網址。登入用 Tailscale 帶的身分標頭比對創作者自己的帳號，對不上就拒絕。
- **像 App**：先做 PWA（加到手機主畫面、全螢幕、有圖示），不寫原生 App。Android 可以用「分享到 EF」直接把截圖、連結、檔案丟進來（Web Share Target）；iOS 不支援分享目標，改用 App 內的上傳按鈕。
- **聊天輸入框多模態**：
  - 圖片／截圖：存成素材；需要讀懂內容時由雲端模型看圖（本機 9b 不保證看得懂圖）。
  - 檔案：沿用 `/api/extract`（md、txt、pdf），上限照舊 5 MB，圖片另訂上限。
  - 連結：沿用閘道 `Fetcher`，抓不到照舊標「無法取得」。
  - 錄音：瀏覽器 `MediaRecorder` 錄（必須 HTTPS，Tailscale 提供）；音檔存成素材，轉文字走閘道新供應商、記帳，跟 #112 生圖同一套模式。雲端還是本機轉寫在 ADR-0028 定（建議雲端：本機 whisper 會吃掉 WSL 本來就緊的記憶體）。
- **素材先收、分析後做**：丟進來的東西進對話的素材清單（像 NotebookLM 的來源欄），不自動開分析工單——符合「不強迫互動」與「錢只花在創作者選的事」。
- **風險**：家裡電腦要開著、WSL 要醒著；記憶體不足時（見 env-layout）手機那頭會連不上。ADR 要寫清楚斷線時手機畫面怎麼說。

## 七、待創作者決定

創作者 2026-10-16 已拍板：
- **使用者只有創作者自己**：單人、純檔案、本機；不做多人與登入系統。
- **手機要能直接用**：多模態（截圖、檔案、連結、錄音、打字），手機與桌機都能用，未來是 App 的樣子 → P5a 用 Tailscale＋PWA。
- **M3 收尾**：做完 #114；#112 封面、#113 預覽暫停，移到 Later（票加註原因，不關票）。

- **轉文字先用 OpenAI Whisper API**（`whisper-1`，創作者 2026-10-16 拍板）：它是 OpenAI 轉文字模型裡唯一能給時間戳的（`verbose_json`＋`timestamp_granularities`），正好接「可回聽」；約 US$0.006／分鐘，單檔上限 25 MB，格式 mp3、mp4、mpeg、mpga、m4a、wav、webm。
- **大小上限（參考 ChatGPT 與 Claude app，2026-10-16 查）**，寫進 ADR-0028：

| 類型 | ChatGPT app | Claude app | EF 採用 | 理由 |
|---|---|---|---|---|
| 圖片 | 20 MB／張 | 10 MB／張、8000×8000 px | **20 MB／張**，原檔照存；送模型前縮到長邊 2576 px 以內 | 手機原圖常超過 10 MB；Claude API 單張上限 10 MB，新模型長邊超過 2576 px 會自己縮，先縮省錢 |
| 音檔 | （無單獨規定） | （無單獨規定） | **25 MB／檔** | Whisper API 硬上限；瀏覽器錄的 webm／opus 約一小時十幾 MB，夠用；超過先拒絕並說明，切段之後再做 |
| 文件（pdf、md、txt） | 512 MB／檔 | 對話 500 MB／檔、專案 30 MB／檔、PDF 1000 頁 | **30 MB／檔**（現在是 5 MB），PDF 1000 頁 | 一個人在家用的機器，抓 Claude 專案檔的上限；真正卡的是能不能塞進模型，不是檔案大小 |
| 一則訊息幾個附件 | 3 小時 80 個 | 20 個 | **20 個** | 照 Claude app |

來源：[ChatGPT File Uploads FAQ](https://help.openai.com/en/articles/8555545-file-uploads-faq)、[Upload files to Claude](https://support.claude.com/en/articles/8241126-upload-files-to-claude)、[Claude Vision 文件](https://platform.claude.com/docs/en/build-with-claude/vision)、[OpenAI Speech to text](https://developers.openai.com/api/docs/guides/speech-to-text)。
