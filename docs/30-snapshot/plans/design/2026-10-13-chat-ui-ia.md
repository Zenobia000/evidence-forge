## 1. 這個畫面要讓你做的事

你只做三件事：**丟素材進去**、**讀報告、追問**、**叫它寫、叫它改**。所以畫面的工作是：

1. 對話就是工作的地方。不用去別的頁面開單、看狀態、審稿。
2. 報告和文章很長，不塞進對話泡泡裡。對話裡放一張「結果卡」，右邊面板放全文。
3. 工作在跑的時候，看得到跑到哪、在等什麼、花了多少，不放假動畫。

舊設計的四條原則沿用：**出處一鍵可達**、**狀態不只用顏色**、**錢先講清楚**、**等我的事放最前面**（對話清單裡，報告剛出來、你還沒看過的對話排前面）。拿掉的一條是「通過與退件一樣好按」，因為審稿動作已經拿掉（ADR-0019）。

## 2. 頁面與路由

| 頁 | 路由 | 做什麼 |
| :--- | :--- | :--- |
| 聊天室 | `/`、`/c/<對話 id>` | 三欄：對話清單、對話、右側面板 |
| 帳單 | `/bills?month=` | 本月總表與分項（沿用 S0 的設計稿，改分項） |

導覽只有兩個入口：**聊天室**、**帳單**。分頁標題顯示「有新結果」的對話數，例如 `(1) Evidence Forge`。

```
聊天室 /c/<id>
 ├─ 左：對話清單（＋新對話）
 ├─ 中：對話串流
 │    ├─ 你的訊息（文字、網址、附檔）
 │    ├─ agent 的回答
 │    ├─ 工作進度列（跑的時候）
 │    └─ 結果卡（報告 v1、文章 v1…）──點一下──► 右側面板打開那一份
 ├─ 右：面板（報告／文章／花費 三個分頁，可以收起）
 └─ 下：輸入框（打字、貼網址、拖檔案）
帳單 /bills
```

## 3. 左：對話清單

| 項目 | 內容 |
| :--- | :--- |
| 排序 | 有新結果、你還沒看過的在最上面；其餘依最後活動時間，新的在上 |
| 每一列 | 標題（第一份素材的標題；還沒丟素材就是「新對話」）、最後活動時間、狀態小標：`分析中`／`寫作中`／`有新結果`／`失敗`；這個對話花了多少（`US$0.42`） |
| 頂部 | 「＋新對話」按鈕；搜尋框（依標題，先不做全文搜尋） |

## 4. 中：對話串流

### 4.1 訊息的種類

| 種類 | 長相 | 來源 |
| :--- | :--- | :--- |
| 你的訊息 | 靠右；網址顯示成連結卡（網域＋標題，抓到前只顯示網域）；附檔顯示檔名與大小 | 你 |
| agent 的回答 | 靠左，Markdown 渲染；串流逐字出現 | 對話的 Pi |
| 工具呼叫 | 一行灰字：「開始分析」「讀報告 v1」；可展開看參數 | Pi 的工具事件 |
| 工作進度列 | 見 4.2 | 主機推的 `ef_job` 事件 |
| 結果卡 | 見 4.3 | 工作結束時 |
| 錯誤 | 一行紅字＋原因＋能做什麼，例：「讀不到網址（付費牆）。可以改貼文字或上傳檔案」 | 主機或 Pi |

### 4.2 工作進度列

工作跑的時候，在對話裡固定一列，跑完換成結果卡。

```
分析中 · 2／2 查證與找題材 · 3 分 12 秒 · 搜尋中 · US$0.18／1.00 · 4／12 credits
```

- **在等什麼**：`等 GPU`、`等限流`、`等模型回應`、`搜尋中`、`抓取網頁中`、`跑腳本中`。資料來自閘道，不放假動畫、不放百分比進度條（NFR-OBS-02）。
- **花費**：目前花費／預算；有搜尋額度的段加上 credits。
- 本機段在 GPU 排隊時，列出前面還有幾個請求。

### 4.3 結果卡

| 結果 | 卡片內容 | 按鈕 |
| :--- | :--- | :--- |
| 分析完成 | 「分析報告 v1」、作者在說什麼的第一句、查證摘要（例：`2 有疑慮 · 3 有佐證 · 1 查不到`）、研究題材數、花費 | 打開報告（右側面板） |
| 重構完成 | 「文章 v1」、標題、角色＋文類、字數、跟原文的重疊率、未校準時標「未校準」、花費 | 打開文章、複製 Markdown |
| 未完成 | 「未完成：預算用完」，以及已經做到哪 | 打開目前的產出 |
| 失敗 | 「失敗：Ollama 沒回應」＋原因 | 「重試」（送一句「重試」給 agent） |

結果卡不帶「通過／退件」。要改就直接打字。

### 4.4 輸入框

- 一個框：打字、貼網址、拖檔案（Markdown、純文字、PDF）或按迴紋針選檔。
- 框上方三個**建議**按鈕，只是幫你填字，不是表單：
  - 剛分析完：`用 me 寫一篇觀點文`、`再查一下有疑慮的那條`、`這篇的立場是什麼？`
  - 剛寫完：`開頭直接講結論`、`換一個標題`、`換成 B2B 角色寫`
- 角色與文類不放下拉選單，直接講。agent 用 `list_personas` 聽懂你說的是哪個；聽不懂就列出現有的讓你選。
- agent 正在回答時仍然可以打字送出，訊息排在它後面（spike 的 `followUp`）。

## 5. 右：面板

三個分頁，可以收起；在窄螢幕上變成覆蓋整個畫面的抽屜。

| 分頁 | 內容 |
| :--- | :--- |
| 報告 | 版本切換（v1、v2…，補查會產生新版）；五節照固定順序；「查證」一節有疑慮的排最前面，每條標 `有爭議`／`查不到`／`過時`／`有佐證`（文字＋圖示，不只顏色）；來源清單每條可點開原網址、看抓取時間 |
| 文章 | 版本切換，可以跟上一版對照（刪除線＋底色）；渲染後的文章；旁邊一欄小資訊：角色、文類、未校準、重疊率（只顯示）；「複製 Markdown」 |
| 花費 | 這個對話的總花費；每次工作一列：分析 v1、文章 v1、文章 v2…，各自的花費、模型、升級、時間；對話本身的花費另列一行 |

## 6. 帳單

沿用 S0 的設計稿（`GqAyiKFvYZNd948RTmsAyT` 的 Bills），改三處：

| 區塊 | 改成 |
| :--- | :--- |
| 頂部三個數字 | 本月總花費、報告幾份、文章幾篇（平均每份報告、每篇文章的成本放在數字下方） |
| 分項表 | 依角色、模型、skill、本機／雲端；對話本身的花費是一項 |
| 列表 | 從工單改成對話：每個對話一列，點進去是那個對話的花費分頁 |

## 7. 每個區塊的四種狀態

| 區塊 | 載入中 | 空 | 錯誤 | 正常 |
| :--- | :--- | :--- | :--- | :--- |
| 對話清單 | 骨架列 | 「還沒有對話」＋一句說明：丟一篇文章進來試試 | 讀不到資料目錄：顯示 `EF_DATA` 路徑與原因 | 列表 |
| 對話 | 骨架 | 新對話：中間放三個例子（貼網址、貼文字、丟 PDF） | Pi 接不回來：「這個對話暫時打不開」＋重試；紀錄還在 | 串流 |
| 右側面板 | 骨架 | 「這個對話還沒有報告」 | 檔案讀不到 | 分頁 |
| 帳單 | 骨架 | 「這個月還沒有花費」 | 帳本壞掉的那一行標行號，其餘照算 | 數字＋表 |

## 8. 畫面之間的接縫

| 接縫 | 怎麼交代 |
| :--- | :--- |
| 丟網址 → agent 開工 | 你的訊息先出現；agent 回一句「開始分析」，接著出現進度列。開工前抓網頁失敗時，直接出錯誤列，不開單 |
| 工作結束 → agent 整理 | 進度列換成結果卡；agent 接著用一兩句說重點（讀報告後），不重貼全文 |
| 關掉分頁再開 | 對話清單與紀錄照舊；跑到一半的工作，進度列接著顯示 |
| 對話閒置被關掉 | 畫面上看不出來；你再打字時，主機在背景接回，第一句回覆可能慢幾秒，期間顯示「接回對話中」 |
| 兩個分頁開同一個對話 | 兩邊都收到同樣的串流；兩邊都可以送訊息，依送達順序排 |
