## 1. 這個 UI 要讓你做的事

新設計裡你只在兩個地方出手：**丟東西進去**、**審結果**。中間全自動，所以 UI 的工作是：

1. 一眼看出**哪幾張在等你審**，以及其他的跑到哪、在等什麼、花了多少。
2. 審稿時，稿子、原文主張、檢查結果、花費都在同一頁，不用切來切去。
3. 退件只要寫一句話、選從哪段重跑。

舊設計的五條原則沿用四條：**等我的事放最前面**、**出處一鍵可達**、**狀態不只用顏色**、**錢先講清楚**。「決定不催促」也保留，通過與退件一樣好按。

## 2. 頁面與路由

| 頁 | 路由 | 做什麼 | 從哪進 |
| :--- | :--- | :--- | :--- |
| 看板 | `/` | 所有工作單依狀態分欄；頂部顯示「待審 n 張」 | 首頁 |
| 工作單詳情 | `/jobs/<id>`，分頁用 `?tab=` | 一張單的稿子、整理結果、來源與圖、檢查、帳單、事件；待審時右側有審稿區 | 看板的卡片 |
| 新增工作單 | `/jobs/new` | 貼網址、貼文字或上傳檔案；填目標；選配方與目標文類；調預算 | 看板頂部按鈕 |
| 帳單 | `/bills`，月份用 `?month=` | 本月總表與分項；每篇通過文章的平均成本 | 頂部導覽 |
| （審稿動作） | `POST /jobs/<id>/decision` | 不是獨立頁面，是詳情頁的審稿區 | 詳情頁 |

導覽只有三個入口：**看板**、**帳單**、**＋新增**。分頁標題顯示待審數，例如 `(2) Evidence Forge`（沿用舊設計 Q-10 的做法，沒有推送通知）。

```
看板 /
 ├─ 卡片 ──► 工作單詳情 /jobs/<id>
 │            ├─ 稿子（各版切換）   ← 待審時預設開這一頁
 │            ├─ 整理結果（主張＋原文引句、研究方向、文類與信心）
 │            ├─ 來源與圖（S0 只有原文；圖在 S3）
 │            ├─ 檢查結果（C1～C5 過或沒過；C6、C7 提醒）
 │            ├─ 帳單（這張單）
 │            ├─ 事件紀錄
 │            └─ 審稿區：通過／退件／丟棄；失敗的單多一個「重試」
 ├─ ＋新增 ──► /jobs/new ──送出──► 回看板，新卡片出現在「排隊」
 └─ 帳單 ──► /bills
```

## 3. 看板

五欄，順序照狀態流：**排隊 → 執行中 → 待審 → 通過 → 丟棄**。待審欄底色加強、欄頭顯示張數；通過與丟棄預設只顯示最近 20 張。

卡片內容（依狀態不同）：

| 欄 | 卡片顯示 |
| :--- | :--- |
| 排隊 | 標題、訂閱源（S0 都是「手動」）、排隊多久 |
| 執行中 | 標題、`3／4 二創`、這段跑了多久、**在等什麼**、目前花費／預算 |
| 待審 | 標題、結果標籤、原因一句、總花費、稿子第幾版 |
| 通過、丟棄 | 標題、日期、總花費 |

**在等什麼**（`features/review.feature`〈看板說明正在等什麼〉）：`等 GPU`、`等限流`、`等模型回應`；正在跑工具時顯示工具名稱，例如 `抓取網頁中`。資料來自 Pi 的事件與帳本，不放假動畫（NFR-OBS-02）。

**結果標籤**：文字＋圖示＋顏色三者一起，不只靠顏色。

| 結果 | 標籤文字 | 例 |
| :--- | :--- | :--- |
| `complete` | 完成 | — |
| `incomplete` | 未完成：＜原因＞ | 未完成：預算用完；未完成：C3 照抄修了 1 次仍沒過 |
| `failed` | 失敗：＜原因＞ | 失敗：Ollama 沒回應 |

另外兩個要標的提醒：文類判斷信心低、目標文類「未校準」（ADR-0015）。

看板每 5 秒用 HTMX 輪詢更新（架構草案 v0.3 §8）。

## 4. 工作單詳情

**版面**：左邊是分頁內容，右邊是固定的資訊欄：狀態、結果、目標、配方、目標文類、花費／預算、版本。待審時，資訊欄下方就是審稿區。

| 分頁 | 內容 | 預設開啟 |
| :--- | :--- | :--- |
| 稿子 | Markdown 渲染；版本切換（v1、v2…），可以和上一版對照；引用編號點一下跳到來源 | 待審、通過時 |
| 整理結果 | 文類（主／次、信心）；主張列表，每條附逐字原文引句與段落位置，點一下展開原文那一段；觀點與事實分開標；研究方向 | — |
| 來源與圖 | 原文出處、抓取時間、讀不到的原因。S0 只有原文，圖與補料來源在 S3 加進來 | — |
| 檢查結果 | C1～C5 逐條過或沒過，沒過的列出位置；C6、C7 的提醒與理由；自動修了幾次 | 待審且結果不是「完成」時 |
| 帳單 | 這張單每段的花費、模型、升級、時間；退件重跑多花的（FR-LG-02） | — |
| 事件紀錄 | `events.jsonl` 依時間列出 | 執行中、失敗時 |

### 4.1 審稿區

| 動作 | 要填的 | 送出後 |
| :--- | :--- | :--- |
| 通過 | 無 | 卡片移到「通過」 |
| 退件 | 一句意見（必填）；從哪段重跑（下拉，預設照配方的 `on_feedback`，通常是二創） | 卡片回到「排隊」，下一版是 v(n+1) |
| 丟棄 | 無（二次確認） | 卡片移到「丟棄」 |
| 重試 | 只在 `failed` 出現；不用填 | 卡片回到「排隊」，從失敗那段重跑 |

通過與退件一樣大、並排；丟棄放在下方，比較小。

## 5. 新增工作單

| 欄位 | 必填 | 說明 |
| :--- | :---: | :--- |
| 素材 | 是 | 三選一分頁：貼網址／貼文字／上傳檔案（Markdown、純文字、PDF） |
| 目標 | 否 | 一句話；沒填就用配方的預設目標，欄位裡先顯示預設目標當提示 |
| 配方 | 是 | 下拉，S0 只有 `restructure` |
| 目標文類 | 否 | 下拉 12 種；沒選用作家設定的預設文類；未校準的文類在選項旁標示 |
| 預算 | 是 | 預設照配方；顯示「這個配方過去平均花 US$x」（S0 初期沒有資料就不顯示） |

網址讀不到（403、付費牆）時，**不在送出前擋**：送出後，那張單會以「失敗：讀不到網址（原因）」進待審，並提示改用貼文字或上傳檔案（`features/intake.feature`〈讀不到的網址不繞過〉）。

## 6. 帳單

| 區塊 | 內容 |
| :--- | :--- |
| 頂部三個數字 | 本月總花費、通過幾篇、**每篇通過文章的平均成本** |
| 分項表 | 依 skill、模型、訂閱源、本機／雲端；本機顯示 GPU 秒數，金額 0 |
| 工作單列表 | 本月每張單的花費，點進去是該單詳情的帳單分頁 |

月份用上一月／下一月切換。

## 7. 每頁的四種狀態

| 頁 | 載入中 | 空 | 錯誤 | 正常 |
| :--- | :--- | :--- | :--- | :--- |
| 看板 | 骨架卡片 | 「還沒有工作單」＋新增按鈕 | 讀不到資料目錄：顯示 `EF_DATA` 路徑與原因 | 五欄 |
| 詳情 | 骨架 | 某分頁沒有內容時寫明為什麼（例：「還沒跑到整理段」） | 找不到這張單 | 分頁＋資訊欄 |
| 新增 | — | — | 欄位錯誤顯示在欄位旁；檔案格式不支援 | 送出後回看板 |
| 帳單 | 骨架 | 「這個月還沒有花費」 | 帳本有壞掉的一行：顯示行號，其餘照算 | 三個數字＋表 |

## 8. 畫面之間的接縫（給接縫站先列）

UI 只寫兩種檔（`review/decision.vN.json`、`inbox/manual/…`），狀態由執行器每幾秒套用一次（架構草案 v0.3 §5）。所以**送出到生效之間有空檔**，畫面要交代：

| 接縫 | 現在的設計沒寫的 | 建議 |
| :--- | :--- | :--- |
| 審稿送出 → 執行器套用 | 送出後、執行器還沒套用前，卡片顯示什麼 | 卡片標「已送出：退件，等待套用」，審稿區鎖住；套用後才移欄 |
| 新增送出 → 開單 | `inbox/manual/` 寫好了，但工作單還沒開 | 回看板時在「排隊」欄頂部放一張暫時卡片「準備中」，開單後換成真的卡片 |
| 看板 → 詳情 → 退件 → 回看板 | 退件後停在詳情頁還是回看板 | 回看板，並讓那張卡片短暫標示 |
| 同一張單在兩個分頁同時審 | 兩份決定都寫進去 | 執行器只套用第一份，第二份標「已失效」；畫面提示這張單已經被決定 |

## 9. 不在 S0 的頁面

訂閱源頁（S2）、評估頁（S1）、素材逐件核准（S3，見 `open-questions.md` Q-24）、外觀三選一的設定頁（ADR-0008，S4 套用設計系統時一起做）。
