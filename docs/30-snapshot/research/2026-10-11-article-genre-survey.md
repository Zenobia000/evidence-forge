# 研究：文章類型與寫作結構盤點（轉換基底）

> 快照，只增不改。日期：2026-10-11。目的：二創要把一篇文章「轉成」另一種文章，先要有一張共用的類型表當轉換基底，再決定每種類型要不要有自己的模板。
> 來源多半是二手整理（行銷公司部落格、課程講義），**沒有一套業界公認的標準分類**；下面是把幾個圈子的分法對齊後的整理，不是權威定義。

## 1. 先講結論：三層分開，不要相乘

寫作圈談「一篇文章怎麼寫」，其實混著三件不同的事：

| 層 | 回答什麼 | 例子 | 誰的 |
| :--- | :--- | :--- | :--- |
| **文類**（genre） | 這篇是什麼、讀者讀完得到什麼 | 教學文、觀點文、評測、彙整 | 依讀者需求決定 |
| **結構公式**（framework） | 內容按什麼順序排、怎麼說服 | 倒金字塔、SCQA、PAS、AIDA、步驟式 | 每種文類有預設，可換 |
| **風格**（voice） | 用什麼語氣、句子長短、舉例習慣 | 先講結論、用自己踩過的坑當例子 | 作者本人，跨文類一致 |

**每種文類要有自己的「骨架模板」，但風格只要一份。** 如果每種文類各做一份風格模板（12 類 × 1 位作者 = 12 份），很快就會各自走樣，讀者也認不出是同一個人寫的。正確做法是：一份個人風格，加上各文類的骨架，必要時再加幾行「這一類的風格微調」（例：教學文的指令要精確、少修辭）。

## 2. 各圈子怎麼分

### 2.1 內容行銷／部落格圈（英文）

靠部落格流量賺錢的寫手與行銷團隊，常用的類型：how-to／教學、清單文（listicle）、彙整（roundup，彙整專家意見或好文連結）、支柱文（pillar post，2,500～4,000 字以上的長文，連到各子題文章）、案例（case study）、比較文（X vs Y）、新聞與趨勢、思想領導／觀點文。這套分法以「搜尋意圖」與「流量」為出發點。

### 2.2 技術文件圈：Diátaxis

教學（tutorial）、操作指南（how-to guide）、參考（reference）、解說（explanation）。分法依據兩個問題：讀者當下是在學習還是在工作？要的是動手做還是理解？

### 2.3 新聞圈

新聞（hard news，倒金字塔）、特稿（feature）、分析、評論／社論、評測、專訪。

### 2.4 中文自媒體圈

圈內常用的說法有：乾貨文、觀點文、故事文、熱點文、清單文、測評、案例拆解、讀書筆記。這些是習慣用語，沒有查到統一的定義。熱點文靠事件自帶的話題吃流量；觀點文講究「一個鮮明論點，加 2～3 個支撐論點」。

### 2.5 文案圈的結構公式（不是文類）

寫銷售文案賺錢的寫手，談的多半是「公式」，而不是類型：

| 公式 | 順序 | 適合 |
| :--- | :--- | :--- |
| AIDA | 注意 → 興趣 → 慾望 → 行動 | 最老牌的通用說服順序 |
| PAS | 問題 → 放大痛點 → 解法 | 有明確痛點的主題 |
| BAB | 現在 → 理想狀態 → 橋（怎麼過去） | 轉變型的主題 |
| FAB | 功能 → 優勢 → 好處 | 介紹產品或工具 |
| 4P | 承諾 → 畫面 → 證據 → 推一把（各家說法不一） | 廣告文案 |
| SCQA＋金字塔原理 | 情境 → 衝突 → 問題 → 答案；結論先講，論點由上往下 | 分析、觀點、給決策者看的文章（Barbara Minto，麥肯錫） |
| 倒金字塔 | 最重要的先講，細節往後 | 新聞 |

多數文案公式是 AIDA 或 PAS 的變形。

## 3. 對齊後的類型表：12 種，依讀者需求分 6 組

| 讀者想要 | 文類 | 一句話 | 預設結構公式 | 其他圈子的叫法 |
| :--- | :--- | :--- | :--- | :--- |
| 知道發生什麼 | **新聞快訊** | 某某發布了什麼、有什麼數字 | 倒金字塔 | news、熱點文（純報導） |
| | **熱點評論** | 一件新事＋我的看法 | SCQA | newsjacking、熱點文（帶觀點） |
| 學會做事 | **教學文** | 從零做出一件事 | 步驟式（目標 → 前置 → 步驟 → 驗證 → 踩坑） | tutorial、how-to、乾貨文 |
| | **清單／技巧** | N 個技巧、檢查表 | 清單式（每項：做什麼＋為什麼） | listicle、checklist、清單文 |
| 理解一件事 | **解說文** | 一個概念為什麼這樣、怎麼運作 | 問題 → 直覺 → 原理 → 例子 → 誤解 | explainer、what-is、explanation |
| | **深度長文** | 一個主題的完整地圖 | 金字塔（總覽 → 各子題） | pillar post、deep dive |
| | **筆記摘要** | 整理一場演講、一本書、一篇論文 | 出處 → 重點條列 → 我的補充 | 讀書筆記、talk notes、paper summary |
| 做決定 | **評測比較** | A 跟 B 哪個好、適合誰 | 評比標準 → 逐項比較 → 適用情境 → 結論 | review、X vs Y、測評 |
| | **案例拆解** | 某團隊怎麼做、結果如何 | 背景 → 做法 → 結果 → 教訓 | case study、postmortem、案例拆解 |
| 被說服、想一想 | **觀點文** | 一個主張和論證 | SCQA／金字塔（論點 → 2～3 個論據 → 反方 → 結論） | opinion、thought leadership、觀點文 |
| | **故事心得** | 我經歷了什麼、學到什麼 | 情境 → 轉折 → 收穫（BAB） | 故事文、心得、經驗談 |
| 一次掃很多 | **精選彙整** | 多則連結各配一段短評 | 主題分組 → 每則：一句重點＋評語＋上游連結 | roundup、curation、電子報、合集 |

訪談（interview）先併入「筆記摘要」；參考文件（reference）不是部落格文類，所以不列。

## 4. 轉換基底怎麼用

```
來源文章 ──判斷文類──▶ 依「來源文類」的抽取欄位整理
                             │
目標（或預設） ──選目標文類──▶ 依「目標文類」的骨架＋預設公式
                             │
                     個人風格（一份）＋該文類的風格微調 ──▶ 二創稿
```

每一種文類的定義檔需要寫四件事：

1. **辨識訊號**：整理段用來判斷文類。
2. **抽取欄位**：來源是這一類時，要多抽哪些東西。例如教學文抽步驟與環境，彙整抽每一則的上游連結。
3. **寫作骨架＋預設公式**：目標是這一類時，稿子長什麼樣。
4. **適合轉成**：常見的轉換方向。

| 來源 → 目標 | 常見轉換 |
| :--- | :--- |
| 精選彙整 → 解說文／觀點文／深度長文 | 挑一則深挖；或把幾則串成趨勢判斷；或整理成主題地圖 |
| 新聞快訊 → 解說文／熱點評論 | 這件事為什麼重要、原理是什麼；或加上自己的判斷 |
| 筆記摘要 → 解說文 | 把重點重新組成一條理解路徑 |
| 教學文 → 教學文／解說文 | 換成自己的環境重做；或講背後原理 |
| 觀點文 → 觀點文／評測比較 | 寫自己的立場；或把爭點變成比較 |
| 案例拆解 → 清單／技巧 | 從案例萃取可重複的做法 |

## 5. 對照這次的評估案例

| 案例 | 判斷 |
| :--- | :--- |
| ihower 電子報 #34、#35、#37 | 精選彙整 |
| ihower 電子報 #40 | 新聞快訊為主、彙整為輔 |
| ihower 電子報 #36、#38 | 觀點文為主、彙整為輔 |
| ihower 電子報 #39 | 演講公告加系列文清單，最接近精選彙整 |
| Agentic Search、AI Agent 產品開發仍然不簡單 | 觀點文（大量轉述別人，帶有彙整性質） |
| Framework 外接 GPU | 教學文 |
| ycc 擴散模型、廣義線性模型 | 解說文 |
| ycc Tesla AI Day | 筆記摘要 |

舊的標註範本只有 6 種類型，沒有「彙整」，所以 GPT 把好幾期電子報標成 `other`。這正好說明類型表不夠用。
