## 1. 專案總覽

| 項目 | 內容 |
| :--- | :--- |
| 專案名稱 | Evidence Forge（repo：`evidence-forge`） |
| 一句話 | 把別人的文章與電子報接進來，自動整理、補資料，再照你的目標、用你的風格二創成新文章；你只審結果。 |
| 使用者 | 一個人的內容工作室：技術作者、產品經理、AI 工程工作者。訂了很多電子報與 app 文章，想把讀到的東西轉成自己的內容。 |
| 部署形態 | 本機優先：3090 跑 Qwen 做大部分工作；雲端 Claude 只用在二創與必要的升級。 |

## 2. 為什麼做

**痛點。** 每天讀到很多好文章（電子報、app 裡的文章），想轉成自己的內容，最花時間的是：整理作者到底主張什麼、找補充資料、再用自己的風格重寫。直接叫 AI 改寫有四個問題：照搬原文的結構和句子、編出不存在的來源、用了沒授權的圖、寫出來不像自己。

**定位。** 不是「文章改寫器」，是一條自動化的內容產線：素材自動接進來，AI 照目標做完，人當專案管理者，只審結果、退件、決定要不要用。

**為什麼這次這樣設計。** 第一版設計在中間放了很多人工停點（選研究問題、定題），用起來被流程綁死，也沒辦法排程自動跑（ADR-0013）。這一版把流程寫成可以改的配方與 skill（ADR-0009），人只在最後出手。

## 3. 核心工作（JTBD）

> 我訂閱的地方有新文章時，系統自己把它整理成主張、觀點和研究方向，補上資料，照我給的目標寫成一篇像我寫的新文章；我打開待審清單，看稿、看花了多少錢，通過或寫一句意見打回去。

## 4. 什麼算成功

以下都是**要驗證的門檻**，還沒有實測結果。驗證方式與時間點見 `roadmap.md`。

| 指標 | 門檻 |
| :--- | :--- |
| 一次通過率（不退件就通過的稿子比例） | ≥ 50%（S1 起追蹤，S4 檢視） |
| 每篇稿子創作者花的審稿時間 | ≤ 10 分鐘 |
| 整理段的捏造引句（C1） | 0 |
| 授權不明的圖進成品（C4） | 0 件 |
| 無人看管連跑一週 | 沒有超出任何一張單的預算；沒有重複開單 |
| 每篇通過文章的平均成本 | 可計量，且落在每張單的預算內；US$0.15 是試算基準（見 §5） |
| 換模型或改 skill 後 | 評估的硬指標沒有退步才上線 |

任何一項沒過，都不能自動公開發布；公開永遠要人按。

## 5. 要驗證的假設

### 5.1 成本假設

單價以 2026-10-10 官方頁面為準：Sonnet 5.5 每百萬 tokens 輸入 US$2／輸出 US$10；Opus 5.5 輸入 US$4／輸出 US$20；Tavily 每 credit US$0.008，免費方案每月 1,000 credits。

| 段 | 每篇假設用量 | 成本 |
| :--- | :--- | :--- |
| 整理（本機 Qwen） | — | US$0（電費另計） |
| 補料：Tavily | 10 credits | US$0.08（未扣免費額度） |
| 二創：Sonnet | 輸入 15,000＋輸出 4,000 tokens | US$0.07 |
| 檢查（本機 Qwen，偶爾升級） | — | 約 US$0 |
| **合計** | 假設沒有退件、沒有升級 | **約 US$0.15／篇** |

- 每月 100 篇：Tavily 1,000 credits，剛好是免費額度上限；雲端 LLM 約 US$7。
- 沒算進去的：退件重跑、升級到 Opus、評估。退件重跑通常只重跑二創段（約 US$0.07／次）。
- 這份假設**不是上限**，上限由每張單的預算擋（PRD NFR-COST-01）。S0 用 5 篇真實電子報實測後更新。

### 5.2 本機模型夠不夠用

假設本機 Qwen3.5 9B 做「整理」（抽出主張、引句、研究方向）的品質夠用，只有二創需要雲端。S1 用 10 篇人工標註的案例驗證：比較 `local` 與 `strong` 做整理的主張召回率與捏造率。**本機版的捏造率不是 0，或召回率明顯較低，就把整理段改成 `strong`**（只改配方，ADR-0011）。
