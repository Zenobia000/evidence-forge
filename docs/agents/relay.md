# 多台電腦／多 session 接力（選用）

**只有一台電腦、一個 session 在推這個 repo 的話，這份可以整份不用**（`/init-from-template` 問過要不要；不要的話刪掉這個檔與 `CLAUDE.md` 裡指到它的那一行）。

為什麼有這份：同一個人在兩台電腦（或同一台的幾個 session）輪流推同一個 repo 時，兩邊會各自派票。前一個專案有一天兩邊撞了四張票，一邊停掉才沒浪費。**誰在做什麼要能從 GitHub 上看出來，不能只活在某一台電腦或某一個 session 的記憶裡。**

## 單一真相在 GitHub，不在任何一台電腦上

- **誰在做什麼**：看 GitHub，不看記憶。一張票開工，就在票上留一句 `開工：<哪台／哪個 session> <日期時間>` 並加標籤 `in-progress`；
  分支名帶票號（`feat/<票號>-<短描述>`）。PR 開了就把 `in-progress` 拿掉（PR 本身就是狀態）。
- **接力日誌**：開一張 pinned issue，標題「接力日誌」，標籤 `relay`。號碼：`#2`。
  每次下班（換手）前留一則，三段：
  1. 合進去的（PR 號）。
  2. 開著的（PR 號、等誰：審查幾輪、使用者按、還是對方接）。
  3. 留給對方的（哪幾張票可以開、哪幾張不要碰、有沒有本機還沒推的東西——**不該有**，見下）。
- **本機不留東西**：下班前所有改動都推上遠端分支。做到一半的推 `wip/<票號>-<短描述>`，PR 不開，換班留言寫明。
  沒推的東西對另一台等於不存在。

## 開工前五件事（每一次）

```bash
git fetch --prune origin
gh issue view 2 --comments | tail -40   # 讀最新的換班留言
gh pr list --state open                              # 誰開著、疊在誰上面
gh issue list --label in-progress                    # 誰在做
git branch -r                                        # 遠端有哪些分支、名字裡的票號
```

一張票只要符合任一條就**不要碰**：遠端有帶它票號的分支、有開著的 PR 引用它、票上有 `in-progress`、換班留言說「不要碰」。

## 兩班的分工（預設；換班留言可以改）

| 班 | 主要做什麼 | 不做什麼 |
| --- | --- | --- |
| 開發班（當下在電腦前的人） | 派票、寫程式、開 PR | 不合 T3／T4（那是使用者的按鈕，兩班都一樣） |
| 審查班（另一台、或沒人在時） | 審查（Claude 一輪、T3 加換家模型兩輪）、本機驗證、合 T1／T2、刪已合併的分支、帳本與教訓 | **不派開發票**，除非換班留言明說「這幾張交給你做」 |

同一時刻只有一個開發班。切換的訊號就是換班留言。

## 兩班都要守的

- 派新票前先看 `.claude/skills/PIPELINE.md`〈鞏固站〉的觸發條件；任一成立就停派。
- 合一條底下疊著別的 PR 的分支：先把上面的 PR 改 base，再合、再刪分支（L-018）。給使用者的合併指令預設不帶 `--delete-branch`。
- 不在共用的主目錄動 git 狀態；每個 session 用自己的 worktree（L-006）。審查班的 worktree 固定一個名字（例：`.claude/worktrees/merge`）。
- repo 在慢的掛載上時，兩班加起來同一時刻跑測試的線也只有 1～2 條（`PIPELINE.md`〈慢檔案系統的 I/O 上限〉）。

## 撞到了怎麼辦

發現兩邊做同一張：**晚開工的那邊停**，分支刪掉、票上留一句。已經開了 PR 的那邊繼續。
兩邊都開了 PR：留內容多的那個，另一個關掉並在 PR 留言指過去；不要試著合併兩份。
