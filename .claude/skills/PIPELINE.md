# 技能流水線：開發怎麼跑

技能目錄是平鋪的，名字看不出順序。這張表是開發時的順序，後面幾節是每一站之間的停點與規矩。

這幾支技能都設定成**只能由使用者打指令啟動**。排程與切片（哪幾張票一波、誰阻塞誰）寫在你的排程計畫裡（例：`docs/30-snapshot/plans/<日期>-<名稱>.md`），這份只講順序與規矩。

| 順序 | 指令 | 做什麼 | 產出放哪 |
| --: | --- | --- | --- |
| 首次 | `/init-from-template` | 新專案第一次打開：填佔位、設守衛、建標籤 | `pyproject.toml`、`CLAUDE.md`、`README.md`、`.claude/hooks/human-only-paths.conf` |
| 0 | `/setup-skills` | 設定議題追蹤器、領域文件的位置，核對守衛 | `docs/agents/` |

| 可選 | `/to-architecture` | 架構，跟程式一起進 | `docs/10-truth/architecture.md` |

## 審查與合併

等級照改到的路徑決定，不照 AI 的判斷（家規第 39 條；通用清單在 `.claude/hooks/guard-git.sh` 的 `human_only_path`，專案自己的清單在 `.claude/hooks/human-only-paths.conf`）。

0. **CI 綠就照常。** CI 沒啟動（帳務、額度——job 零步驟就紅）時，`guard-git` 會退回在本機量 `human-only-paths.conf` 的 `check:` 那一組檢查（本專案是 `uv run pytest && uv run mypy && uv run ruff check .`）；那時**實際輸出貼進 PR 的 Testing** 並註明「CI 未跑，本機驗證」（`LESSONS.md` L-015）。若 repo 掛了密鑰掃描（例：GitGuardian），測試用的假金鑰不要長得像真的（例：前綴用 `sk-fake-`）。
1. **確定性檢查先跑**：型別、lint、格式、測試。紅的直接退回，AI 不花 token。排版與命名風格交給 ESLint／Prettier，**審查者一律不准提**。
2. **Claude 審查**：只報三級——**必修**（會壞使用者的資料、安全、違反 ADR 或票的規格、核心不變量沒測試）在同一個 PR 修；
   **該修**開後續票；**建議**只記下。每次最多 5 條。
3. **動到 T3 路徑才加換家模型的交叉審查**（例：`codex exec --sandbox read-only` 讀 diff 與票），同樣三級、最多 5 條、**最多 2 輪**。
   Claude 對每一條決定修、拒絕（附理由）或開票延後；第 2 輪只驗必修有沒有修好，不重審整份；還有爭議就交給使用者。
   唯讀沙盒通常不能寫暫存檔，審查模型自己跑測試會失敗：**送審前 Claude 先在 worktree 跑一次測試，把完整輸出跟票、diff 一起交給它**；「沙盒裡測試跑不起來」不算審查發現。
4. **合併**：只動 T1／T2 → 檢查全綠後 Claude 用 `--squash` 合併（`guard-git` 會再驗一次）；動到 T3／T4 → 使用者合併，附兩輪審查摘要。

各片的等級與建議模型寫在排程計畫的票上（起始格見 `Ai-coding-principle/MODEL-ROUTING.md`）。

**合併 T3／T4、開不開 PR 到 main、刪分支是使用者的按鈕。** 用 main＋dev 兩條線時，發 `main` 的 release PR **一律用 merge commit**，不能 squash：squash 會把 `dev` 的歷史壓成新 commit，下一次發 `main` 每個檔都衝突（前一個專案踩過，最後要用 `merge -s ours` 補血緣才解開）。合一條底下疊著別的 PR 的分支時，**先把上面的 PR 改成 base `dev` 再刪分支**（L-018）。「可以按」一律帶 head sha（L-022）。UAT 由使用者本人做，每個里程碑一次，沒過不進下一個。

## 設計站

**要改畫面的一波，開工前先畫設計稿給使用者確認；沒確認就不派票。**

為什麼：前一個專案有一波做完之後，使用者發現當初規劃的畫面配置沒出現，分不清是「做完了」還是「排在後面」。設計稿是讓人在寫程式之前就看得到「這一波做完長什麼樣」的唯一辦法，比做完再改便宜一個數量級。

1. 這一波動到哪些畫面，每個畫面一張設計稿（用設計工具或程式產生都行）。
2. 給使用者看，等他明說「確認」。意見寫回票。
3. **意見改回設計稿的原始檔重畫，不在網頁或畫布上手改**——repo 裡的原始檔是正本，手改的那份下次重畫就不見了。
4. 確認過的設計稿連結寫進這一波每張票的描述。

只畫設計稿的子代理不吃機器資源（它在等模型），可以並行多開。

## 接縫站

**設計站之後、派工之前，用跑起來的 app 把使用者流程走一遍，把畫面之間的接縫補齊、寫回票，再派。**

為什麼：設計稿是靜態的，畫得出每一個畫面，講不了畫面之間怎麼接。前一個專案有一波照設計稿做完，使用者驗收時說很多畫面「沒照設計」——查下來不是畫面錯，是畫面之間的互動細節（貼進來要不要直接渲染、預設收合能不能攤開、某個入口在哪、切分的單位是什麼）規格沒寫、實作者各自猜。**表象與底層串接要一起想**，這就是垂直切片。

1. 從使用者流程出發，用跑起來的 app（或現有畫面）走一遍，每一步留截圖＋一行文字。
2. 每兩個相鄰畫面之間列一列：**現在怎麼接**／**該怎麼接**／**要不要改伺服器或資料**。
3. 規格沒寫的細節列成「沒定的細節」，**每一條附建議答案**，請使用者拍板（一次問完，不要一條一條問）。
4. 拍板的結果寫回該波的票（更新驗收條件）再派。
5. **驗收用同一份流程表**對——驗的是流程走得通，不是每張圖像不像。

## 派工前的資源盤點

一次要開幾個子代理（或 worktree、session），先量、再派；每台機器不一樣，不抄上一次的數。對應 `PLAYBOOK.md` P-010。

**量什麼**（派工前跑一次、加人前再跑一次；每一段都包 `timeout`，機器忙的時候 `ps`、`pgrep` 自己會掛住一分鐘以上）：

```bash
timeout 5 nproc; timeout 5 free -m | awk 'NR<=2'; timeout 10 df -h . / | awk 'NR==1||/\//'
grep -H . /proc/pressure/cpu /proc/pressure/io /proc/pressure/memory | grep some; grep procs_blocked /proc/stat
for p in claude codex vitest playwright chrom; do printf '%s: %s  ' "$p" "$(timeout 20 pgrep -c -f -i "$p")"; done; echo
```

**看哪個數字**：`uptime` 的 load 不能直接信——在 WSL2 這類虛擬環境上，它會把 Docker 等其他容器的執行佇列一起算進去，load 40 也可能是閒的。看 `/proc/pressure/*` 的 `some avg10`（百分比，CPU 超過 50 才算擠）和 `/proc/stat` 的 `procs_blocked`（卡在磁碟等待的程序數，常態是 0～2）。這兩個都低就照常派；高了才是真的塞。

**怎麼算**：

1. 子代理本身：一個代理程序幾百 MB、幾乎不吃 CPU（在等模型）。只畫設計稿、只改文件的子代理，瓶頸不在這台機器。
2. 會跑測試的子代理才算力貴：單元測試會把所有核心用滿；e2e 要開瀏覽器、各自一組埠。**同時跑幾套測試，先量一套的峰值再算上限**；不知道的時候，單元與 e2e 各最多兩套。
3. 記憶體：可用量減掉已經在跑的，除以「一個子代理＋它的一套測試」的峰值，再**乘 0.75（留四分之一餘裕）**當上限。峰值怎麼量：跑一次測試，旁邊每 2 秒 `free -m` 取樣，看最高點減基線。
4. 硬碟：uv 在每個 worktree 建自己的 `.venv`，套件檔從共用快取（`~/.cache/uv`）硬連結過去，一個幾十 MB。快取和 worktree 不在同一個檔案系統時會退回複製，空間與 I/O 都會變大。repo 在慢的掛載上時問題不是空間是 I/O，見〈慢檔案系統的 I/O 上限〉。
5. 算完之後再問一次：**瓶頸是算力嗎？** 一波能開幾張票，先看檔案重疊（兩兩不動同一批檔）、再看規劃者審得動幾顆 PR、再看 API 配額，最後才是這台機器。加人不會讓合併變快。

**做了幾個就記幾個**：派工時在接力日誌或票上寫「這次量到 X 核、Y GB 可用、PSI some N、procs_blocked M、已有 K 個子代理與 J 套測試，開 L 個」，下次對照。

## 慢檔案系統的 I/O 上限

**repo 放在慢的或跨系統的檔案系統上（例：WSL 讀 Windows 磁碟）時，同一時刻跑測試／安裝／重 git 的線壓到 1～2 條。**

為什麼：前一個專案在這種掛載上三次整個卡死（EIO），所有 session 的 shell 都起不來，只有使用者手動重啟子系統能救——每掛一次整條產線停擺到使用者醒來（`LESSONS.md` L-019）。卡死之前的小症狀是索引沒跟上、鎖檔殘影。

1. 「一條線」＝一個正在跑測試、安裝或重 git（fetch、checkout、rebase、worktree add）的 session 或子代理。**主 session 自己跑也算一條。**
2. e2e 的 worker 設低（例：`--workers=2`）。
3. 能離線安裝就離線（`uv sync --offline`，快取裡已有的就不必再碰網路）。
4. 只讀的子代理（讀檔、grep、`gh` 查詢）不算線，但同一回合不要對同一個 worktree 並行下兩個會寫索引的 git 指令。
5. 出過一次事，就跟使用者提**把 repo 搬到原生檔案系統**（例：WSL 自己的 `~/`）——那是唯一根治的做法，搬不搬是他的決定。

## 並行 T3 的收尾

幾張都要加遷移（或其他「照順序編號」的東西）的 T3 票同時開工時，每張都把遷移寫成「現在的下一個號」（L-023：不佔位、不跳號），合併順序決定誰改號。固定撞點通常是那幾個檔，兩邊各加相鄰的東西，取聯集就好：`pyproject.toml`、`uv.lock`、型別宣告與進入點的 import 清單、資料層的 import、遷移陣列（聯集後**檢查前一項的收尾符號**，例如反引號、逗號）、遷移的退版測試鏈、架構文件裡的對照表、測試藍圖的 ID。

收尾順序：第一張照常；第二張起，**建置者閒置就由協調者接手**，不等它醒——先把審查輪的 commit 壓成一顆（衝突只解一次），`rebase` 到「前一張的 head」上改號、跑型別、lint、整套單元、動到的 e2e；等前一張進 dev 再 `rebase --onto origin/dev <前一張 head>`，那一步零衝突；推之前對一次「跟驗過的那份內容零差異」（`git diff <驗過的 sha> HEAD --stat` 為空）才推，CI 只是再確認。一次只給使用者一個「可以按」，訊息帶 head sha（L-022、L-023）。

## 鞏固站

**不要一直往前衝。** 下面任一條成立就**停派新票**，開一張「鞏固站 N」票先做完：

- 一波收完；
- 從上一次鞏固起連續合了 10 顆 PR；
- e2e 本機一次超過 4 分鐘、CI 任一 shard 超過 4 分鐘，或單元超過 90 秒（**預設值，依專案調**；調過的上限與量測環境寫進測試藍圖）；
- 同一條測試不穩兩次。

為什麼：前一個專案一天合了二十幾顆 PR 之後，單元近兩千題、e2e 兩百多條，不穩測試一天擋四次合併；只往前推會讓每張票的驗證成本一直漲。

鞏固站**先盤點、不改**，盤點完一到兩顆 PR 收掉：

1. **整段 code review**，不是逐 PR：較強的模型（格 2）讀從上次鞏固到現在的整段 diff，找同一件事兩套寫法、順手長出來沒人用的介面、邊界漏、死 export。
2. **測試取捨**：對照測試藍圖，每條 e2e 要答得出**守哪一條承諾**；答不出的刪或降成單元；同一條使用者路徑只留一條 e2e。**量各層跑時間**、寫進藍圖、超過上限就拆或刪。測試數可以變少，承諾覆蓋不能少。
3. **文件對齊**：文件講的跟程式做的對得上；過期的數字刪掉。

做完**回報給使用者**（粗體結論、刪了什麼、時間從多少到多少、留了什麼），**使用者點頭才開下一波**——不是鞏固完就自動開。協調者派票前先看這四條；觸發了就先鞏固，不因為「這張很小」繼續推。

## 夜間自主

**使用者授權整段推進（例：「我去睡了，把後面的做完」）時的做法。** 目標是他醒來看到結論與可按的 PR，不是半成品或一堆等他回答的問題；他付錢給每一輪審查與測試，所以每一輪要有新資訊才值得跑。

1. **先量資源**（〈派工前的資源盤點〉；慢掛載照〈慢檔案系統的 I/O 上限〉）。
2. **多角度唯讀審查**，依 CP 值配模型：強模型（格 2）看架構與資安；便宜模型（格 1）看測試與文件；外加換家模型一輪。全部唯讀、不跑測試、不 commit（L-016）。
3. **拍板寫進票**。能自己拍板的自己拍，理由寫在票上；把工作拆成「**自己能合**」（T1／T2）與「**留給人按**」（T3／T4）兩堆，不混在同一顆 PR。
4. **驗證夠就好**：每顆只做型別、lint、整套單元一次、動到的 e2e 一次；全套交給 CI。不為了安心多跑。
5. **人的按鈕留著，但不卡住其他工作**：T3 的 PR 開好、審好、帶 sha 擺著，繼續做不依賴它的票；依賴它的，疊在它上面做或排到早上。
6. **早上第一則訊息**，照這個順序：
   1. **粗體結論**（一行）；
   2. **要按的**：每顆帶 PR 號、head sha、**按的順序**（有依賴時一次只給一顆，L-023）；
   3. 做了什麼（一顆一行）；
   4. 留了什麼、為什麼留（等他決定的事，每題附建議答案）。
