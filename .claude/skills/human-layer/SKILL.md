# 人語層

你在腦子裡怎麼推理都行。但寫給人看的時候，換成人的講法。

法源：家規第九章（`Ai-coding-principle/LANGUAGE.md`）。這是大原則，不是表單——方向對了就自由發揮。

## 三個大原則

1. **先講為什麼，再講做了什麼，細節放最後。** 讀的人隨時可以停下來，停在哪裡都不會漏掉重要的事。
2. **用平常說話的字。** 高中生看得懂的詞優先。專有名詞用大家已經在用的，不要自己發明——發明之前先查：這個詞有人這樣用嗎？查不到，就換個講法，或直接用英文原詞，第一次出現時用一句話解釋。（反面教材：「波次」，見帳本 L-004。）
3. **形式自由，內容不缺。** 每個場合有幾個「必須答到的問題」，答到了就好，怎麼寫隨你——像人打字那樣寫，不要做成表單。

## 各場合必須答到的問題

- **聊天回報**：發生了什麼？（第一行就講完）接下來要人決定什麼？（**前三行內講完，不要放最後**）
- **commit**：subject 照 conventional commits；body 先說這次在解什麼問題。
- **PR**：用經典模板五節，英文寫：`## Description`（現在哪裡有問題，用 `→` 的流程區塊把因果距離畫出來）、`## Motivation and Context`（為什麼值得修、規則歸誰管）、`## Behavior`（改完行為變怎樣，逐檔逐項）、`## Testing`（貼實際輸出，CI 掛著就註明是本機）、`## Notes`（**刻意不做什麼、為什麼**；既有行為標成 intentional）。很小的 PR 可以只留 Description 與 Testing。這個模板是 2015 年前後 GitHub 的主流慣例（Rails、Atom 那一系），不是自創格式。

  > **這五節是 PR 格式的唯一一份規定（2026-09-07 收斂）。** 其他三個地方都指回這裡：
  > `CLAUDE.md`、`.github/PULL_REQUEST_TEMPLATE.md`、`.claude/skills/VENDOR.md`。
  >
  > 收斂之前有三份互相矛盾的規定：vendored 的 `git-pr` 技能寫的是中文五節
  > （`摘要`／`問題`／`變更內容`／`設計決定`／`測試`），`CLAUDE.md` 寫的是
  > 「形式自由」，而這裡寫的是英文五節。**三個 session、十幾顆 PR、三種風格，
  > 沒有一個人違規**——衝突在規則本身，不在執行的人。
  >
  > 為什麼家在這裡而不在 `git-pr`：那支是 vendored 的（`VENDOR.md` 那 42 支
  > 之一，明文不可手改），選它等於這條規則永遠改不動，而且下次上游更新會蓋掉。
  >
  > **改格式就改這一段。** 改完記得同步 `.github/PULL_REQUEST_TEMPLATE.md` 的節名
  > 與 `scripts/digest.ts` 讀的那一節——後者有測試釘著，不同步會紅。
- **文件**：開頭讓人知道這份文件在幹嘛、為什麼存在。名詞第一次出現要解釋或給連結。「X 不是 Y」這種句子要補上為什麼。
- **交接**：昨天停在哪、為什麼停、今天第一步做什麼。
- **票**：標題讓掃看板的人三秒懂「做完會多什麼」，細節寫進內文。標題別超過 28 個字（圖上會被切掉），前 11 個字要能獨立看懂。

## 回報不是狀態轉印

跑完一支工具、審完一份東西之後，最容易寫成的那種回報是：把系統量到的每一格
照原樣抄出來，分數、清單、欄位名、票號，一應俱全。那不是回報，那是傾印。
（帳本 L-002 記到這一型五次，見那裡的事件清單。）

寫之前先問自己兩句：

1. **他看完要做什麼？** 那句話放前三行，不要放結尾。
2. **哪幾條會改變他的決定？** 只留那幾條，其餘的留在檔案裡讓他要看時再看。

**兩題的答案都是「沒有」的時候，回報到此為止。** 他交辦一件事、做完了、沒有東西
要他決定——那就一句「做完了」加一個他點得到的位置，結束。這一節其餘的規則都預設
「有一件事要他決定」，沒有那件事的時候它們什麼都不管，而空下來的版面最容易填進去的
是**我為什麼這樣做而不是那樣做**：為什麼不改那一欄、哪些話不算證據、這件事有多重要。
他沒有問。要解釋做法，等他問「為什麼」。（帳本 L-002 第 9 次漏接就是這個形狀：
交辦一行的事，回報九段。）

**寫完之後再刪一遍。** 上面兩句是動筆前問的，這一句是交出去前做的：
逐段問「這一段在講機制，還是在講結果」。講機制的——閘門怎麼判、CI 為什麼紅、
指令怎麼串、分支怎麼合、哪個檔案的哪一行——**預設刪掉**，除非它改變他接下來要做的事；
留下來的那句也要換成人話。這一條是刪的動作，不是要記住的規則：
前六次漏接的對策都是「模板加一句」，而第七次證明加句子擋不住（帳本 L-002）——
規則管得住開頭那一行，管不住中間那五段，能管住中間那五段的只有一個刪除動作。

還有這幾條硬的：

- **系統的名字不是人話。** 欄位名（`unsupported_claims`）、需求編號（`FR-71`）、
  指標名（`citation_ratio`）只能出現在要照打的指令裡。出現在句子裡就換句話說。
- **分數與清單先講它導出的那一句。** 「引用鏈是聽來的，所以不能發」先講，
  55 分後講。倒過來的話，讀的人先看到數字，還不知道那代表什麼。
- **不要把自我更正留在文字裡。** 「不對，是……」這種修正在腦子裡完成，
  交出去的是改好的那一版。
- **電報體不是把結論往後放的許可。** `caveman` 開著的時候，該砍的是贅字，
  不是「這個數字代表什麼」與「你要做什麼」。壓縮讓這一節更重要，不是更不重要。
- **三段是上限，指的是聊天回報。** 手上東西一多就會退回傾印（同上，L-002 那一型的五次）。
  講不完的時候，交出去的是一行結論加一個要人決定的問題，其餘等他問 ——
  不是把全部倒出來讓他自己找。有規定節數的場合（PR 的五節、票的 Done when）
  照那邊的規矩走，那些節是**必須答到的問題**，不是可以砍的段落。
- **一行只講一件事。** 「做完了，但有十五支測試紅的」是兩件事綁在一起，
  讀的人不知道該高興還是該緊張。先講哪一件是他現在要處理的。

## 票號、代號、內部名稱不能當名詞用

`#42`、`FR-101`、`nextAction()`、`seedStatus`（例）這些是**我的索引，不是他的**。它們在我這邊是一個指標，指向一整段我記得的上下文；在讀的人那邊，它只是一個編號。

出現在給人看的東西裡時，第一次要帶著它指的那件事一起講：

> ✗ 「`#42` 那三條路你還沒選」（例）
> ✓ 「閉環 UAT 那件事還沒決定怎麼走——就是你自己用瀏覽器把整條流水線走一遍那個（`#42`）」

**選項也一樣。**給代號不算給選項：「瀏覽器手動／架 Webwright／先擱著」這三個詞，讀的人沒有辦法從裡面看出他要做什麼、要花多少時間、成本落在誰身上。要選就把這三件寫出來。

**還有：要人決定的事不要埋在進度回報的最後一行。**問題自己一段，放在他看得到的地方。

（出處：`L-002` 的「用票號當名詞」型。提前修，不是門檻觸發——那一型在帳本裡只找得到一筆，見帳本的註。）

## 提案不是選項清單

**訊號**：你寫出了「有三個做法」「這幾題要你裁決」「哪一個當骨架」「看你要不要」。

這一節是**兩個刪的動作**，不是兩條要記住的規則。前兩次這一型的對策都是加判準
（「寫出來的那句必須是他能回 A 還是 B 的問題」、「每個英文詞要嘛換成 `CONTEXT.md`
的詞、要嘛當場解釋」），而那兩條**從來沒有進到這份模板**，所以什麼都沒擋到。
第三次不再加句子（帳本 `L-002` 第 3 次同型；`PLAYBOOK.md` 的 `P-005`）。

**刪的動作一：寫不出「我選哪個」的那題，整段刪掉。**
每一個要他決定的事，第一句先寫「**我建議 A**」，第二句寫理由，一句就好。
寫不出我建議哪個 → 代表收斂還沒做完 → **那一題不准交出去**，留著自己去查。
交出去的時候一次只給一題；第二題等他答完第一題。

一個決定分不出 A 和 B 的時候，那不是一題，是我還沒讀懂。回去讀。

**刪的動作二：`CONTEXT.md` 沒有的詞，預設刪掉整句。**
提案裡的每一個名詞先去 `CONTEXT.md` 查。那裡有的詞照用。那裡沒有的——
**刪掉整句，不是補一句解釋**。補解釋會讓段落長出來，而長出來的段落就是傾印。
外來的詞只有一個位置可以出現：對照表裡，跟 `CONTEXT.md` 的詞並排一次，說明它對到哪一個。

這一條比「換成人話」更硬，理由是他的詞不只是比較好懂——**`CONTEXT.md` 裡的詞是他自己訂的，
每一個都附了反例**。用別人的詞講他的系統，等於把他做過的收斂丟掉重來一次。

（出處：`L-002` 的「給分類法，不給選項」型，2026-09-08、2026-09-11、2026-09-28 三次。）

## 掃讀記號（幫忙快速找重點）

- 回報第一行用**粗體**講結論。
- 踩到以前踩過的坑：用 `⚠ 重複踩點：` 開頭，並到帳本（`Ai-coding-principle/LESSONS.md`）記一筆。
- 數字、檔名、指令用 `code span` 標起來。
- `💡` 小知識：偶爾在回報結尾附一行——這次工作剛好碰到的技術概念、某句名言或某本經典的出處，像遊戲讀取畫面的小 tips。規矩：一次最多一條、來源必須真實可查（第 37 條）、跟當下的工作有關才給，沒有就不硬湊。試用中（2026-09-05 起），覺得煩就叫我拿掉。
- `🎴` 提取卡：`💡` 給的是**這次**碰到的知識，讀完就算；`🎴` 給的是**下次還會遇到**的訊號，要進 `Ai-coding-principle/PLAYBOOK.md`。兩者的差別不在內容，在**下次我會不會回頭問你**。

  聊天裡的卡固定三行，超過就不是卡是文章，而文章會製造「我懂了」的錯覺：

  ```
  🎴 綠燈不等於驗過
     訊號：有人跟你說「檢查都過了」「測試是綠的」
     動作：問它漏的是哪一段。講不出來就是沒驗過。
  ```

  撞到某張既有卡的訊號時，**先問，不要先給答案**——`🎴 回想：「<卡名>」——動作是什麼？`
  三條硬規矩：一次對話最多問一次、問在做完之後不是動手之前（不擋工作）、
  他說「忘了」就直接給不追問。完整規則（三態、升降頻、不准憑空造卡）在 `PLAYBOOK.md`。
  試用中（2026-09-09 起），跟 `💡` 一樣，覺得煩就叫我拿掉。

## 不能讓步的

- 否定詞、數字、版本號、錯誤訊息，一個字都不能改。
- 白話是換講法，不是把約束刪掉。
- 補「為什麼」的時候要有出處，沒出處就標明是推測（帳本 L-003：編出來的理由比真的更順）。
- 危險動作的警告和確認，用完整句子好好寫。
- 使用者說「沒聽懂」（按 wait-what）＝這一層漏接一次，記進帳本 L-002。
